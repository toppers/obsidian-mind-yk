# 5B. 色に依存しない状態表示

[[TECSCDE-DT外部仕様 - 04 コンポーネント図の表現]]が継承する[[TECSCDE外部仕様 - 04 コンポーネント図の表現]]4.1.2と、[[TECSCDE-DT外部仕様 - 10 制約・制限]]10.2の、色以外でも状態を識別できる要件を具体化します。以下は2026-11-07の内部設計案であり、実装済みを意味しません。

## 5B.1 状態の導出

状態は一つの排他的な種別にせず、独立して導出します。判定と描画を分離し、同じ状態スナップショットをセル描画・凡例の説明・プロパティの文言に使います。

```ts
interface CellVisualState {
  readonly readOnly: boolean;
  readonly incompleteReasons: readonly string[];
  readonly unconnectedCallPortIds: readonly PortId[] | null;
  // nullは型未解決等で未結合の判定ができない場合。空配列とは区別する。
}
// deriveCellVisualState(doc, cell, structuralIssues): CellVisualState
// structuralIssuesは現在のモデルに対応する既存の構造判定結果。
```

| 状態 | 判定と境界 |
|---|---|
| 編集不可 | `!cell.editable`。`systemDefined`だけで決めない。設定で編集可能になったシステム定義セルは編集不可扱いにしない |
| 不完全 | `cell.celltypeUnresolved`、および既存ローダー・整合性処理が対象セルに関連付けた構造未解決（結合先・ポートシグニチャの未解決等）の理由がある場合 |
| 未結合 | モデルに存在する通常の呼び口要素で`joinId`が無いもの。配列は各要素のIDで判定。型未解決で要素を列挙できなければ判定不能とする |

`.unresolved`の既存クラスはセルタイプ未解決の表現であり、不完全全般と同義にはしません。任意の診断があるだけで不完全にしたり、新たな意味解析をこの表示処理へ追加したりしません。操作拒否・用紙overflow・環境警告等も、不完全の理由へ一律に含めません。

`optional`の未結合も、存在する呼び口が接続されていない状態としてUの対象にしますが、それだけをエラーや不完全とは判定しません。結合の無い受け口は通常利用可能な状態なので、呼び口の未結合判定へ混ぜません。図に存在しない名前なし`require`はUの件数へ含めず、既存の`W-REQUIRE-PORT-HIDDEN`の通知と区別します。

表示のためのフラグを`Cell`の編集可否や診断へ書き戻しません。`CellVisualState`自体はCDL・セッション・Undo/Redo履歴へ保存せず、現在のモデルと有効な構造判定結果から作ります。古いセルIDや解消済みの理由を、過去のログやメッセージ文字列から復活させません。

## 5B.2 記号と併記

| 状態 | 常時表示する記号 | 文字による意味 |
|---|---|---|
| 編集不可 | **四角い囲みの`RO`** | 編集不可 |
| 不完全 | **三角形の囲みの`!`** | 不完全 |
| 未結合 | **丸い囲みの`U`** | 未結合の呼び口あり |

記号の形とASCII文字を組み合わせ、色相だけに意味を持たせません。絵文字やOS固有のアイコンフォントへ依存せず、SVGの線・図形・テキストで描きます。記号は不透明な明るい背景と暗い輪郭・文字を持ち、セルの塗りやactiveの青背景が透けて識別を妨げないようにします。

順序は**RO → ! → U**とします。該当しない記号は出さず、同時に該当する記号はすべて併記します。例えば編集不可かつ不完全で未結合なら3つを表示し、色の優先順位によって一つへ潰しません。Uは未結合が1件以上の場合だけ表示し、詳細文言で件数とポート名・添字を確認できます。未結合判定不能は「未結合なし」と表示せず、プロパティ等で判定不能と伝えます。

編集可能で不完全理由も未結合もないセルは、この3つの状態記号を持ちません。active、選択中、検索一致はそれぞれ別の表示機構を使い、RO・!・Uの意味へ流用しません。

## 5B.3 セル内の配置と描画

`CellRenderer`は既存の`<g data-cell-id>`内に`cell-status-badges`グループを追加します。セル内のラベル領域の下部へ状態行を確保し、セル名・セルタイプ名、左側のリージョン色の帯、辺上のポート記号と重ねません。モデルのセル寸法やポート位置は表示記号のために変えず、状態行を含めてラベル配置を調整します。最小のセル寸法でも3記号と2つのラベルが欠けないことを検証します。

状態行はセル本体とともに移動・拡大縮小・フィルタ非表示に追従します。セルが非表示なら、記号だけを残して見せません。`pointer-events: none`としてセル選択・ポートドラッグ・結合操作の入力を遮らず、記号そのものを新たな編集対象にしません。

描画順は、リージョン矩形等の背景、セルの塗り・色の帯、セルのラベルと状態記号、既存の前面の選択枠・ハンドルを基本とします。検索の外側の破線枠と状態記号は別の位置・形にし、選択枠や検索強調をRO・!・Uの代用にしません。状態記号はセルの内側へ収め、枠・ハンドル・ポートを覆いません。

active背景と既存状態色の塗り・枠の優先順位は、[[TECSCDE-DT-EL内部仕様 - 06C V0.2.0表示と配置]]6C.2で決定済みです（2026-11-08。塗りと枠を別の軸とする）。この状態行は色の合成から独立して描画します。記号の有無を色分け・セル名強調のオン／オフに連動させません。

## 5B.4 凡例と文字情報

`AppShell`はキャンバスに隣接する固定の凡例領域に、**四角RO＝編集不可、三角!＝不完全、丸U＝未結合**を、実際と同じ図形と日本語で表示します。セル選択やホバーがない状態でも意味を確認できるようにします。領域の表示／非表示を切り替える旧表示制御バーを復活させません。

既存のリージョン凡例とは別の見出し「セルの状態」を付け、リージョン名の一覧・色見本を置き換えません。同じ固定領域に配置する場合もレイアウトで分離し、スクロールやウィンドウサイズ変更で重ならないようにします。

単一セル選択時のプロパティには、同じ状態スナップショットから「編集可否」「不完全の理由」「未結合の呼び口名と添字・件数」を日本語で示します。`optional`の未結合はエラーとは限らないことを区別します。判定不能の場合はその旨を出し、誤って正常・完全と断定しません。低倍率でセル内の文字や記号を読み取りにくい場合も、この固定UIの文字で状態を確認できます。

セルのSVGグループの`aria-label`または説明要素にも、セル名と該当状態・理由を文字で含めます。図形だけの記号はその説明と重複して読み上げない構成とします。色やホバー時のツールチップだけに意味を閉じ込めません。

## 5B.5 更新・履歴・保存との境界

セルの追加・削除、結合の追加・解除、配列要素の挿入・削除、型解決結果の変更、文書の差し替え、Undo/Redoで状態を再導出します。型・参照等の判定がdoc外にある場合、ストアは確定docに対応する判定結果と同期してから描画へ渡します。`Command.apply()`からDOMや凡例を副作用更新しません。

差分描画の更新条件に、状態記号の有無と理由・件数の変更を含めます。docの参照が同じでも、型解決結果等が変わったときは更新します。状態解消時は記号と説明を除去し、削除済みセルの理由を別の同名セルへ引き継ぎません。選択解除・検索解除では状態記号を消しません。

凡例・記号・説明を描くだけではdirtyや編集履歴を変更しません。保存では既存のモデル・診断の契約を使い、状態記号のための属性をCDLへ追加しません。通常のセル描画を使う画像出力でも、状態記号を一時的な選択オーバーレイとして除外しない契約とします。

画像出力の状態スナップショットと、HTMLの状態凡例をSVGへ描き直す契約は[[TECSCDE-DT-EL内部仕様 - 07F エクスポート設計（たたき台）|第7F章7.10.4]]へ接続します（2026-11-07、監査#15）。出力時に状態判定や文言を別々に作り直しません。

## 5B.6 実装時の検証条件

- 編集不可・不完全・未結合の各状態と、2状態・3状態の組み合わせで、色を除去した表示でも記号・凡例・プロパティ文言を区別できること。
- `systemDefined=true`でも編集許可の設定により`editable=true`ならROが出ず、Plugin生成等で`editable=false`ならROが出ること。
- セル型未解決と既存の構造未解決理由だけを不完全へ反映し、任意の警告やoptionalの未結合だけで!を出さないこと。
- 配列要素ごとの未結合、結合追加・削除、型未解決による判定不能、名前なしrequireの別通知を確認すること。
- 選択・検索・リージョン色・セル名強調・active背景の併存時にも記号を失わず、ポート操作を妨げないこと。非表示セルの記号は描かないこと。
- 最小セル寸法、長い名前、通常倍率と低倍率、凡例領域の狭いウィンドウを確認し、低倍率でも固定UIの文字で状態を確認できること。
- 状態解消、Undo/Redo、文書切替、同名セルの再生成で古い記号が残らず、選択・検索解除では通常の状態記号が消えないこと。
- SVG説明とプロパティの文言が描画状態と一致し、画像出力で通常の状態記号が保持されること。
- DOM・状態導出のテストは`tests/renderer/`、白黒・組み合わせ・凡例の実機確認記録は`tests/verification/`へ置くこと。これは将来の受入条件であり、今回実装テストを行ったという記録ではありません。
