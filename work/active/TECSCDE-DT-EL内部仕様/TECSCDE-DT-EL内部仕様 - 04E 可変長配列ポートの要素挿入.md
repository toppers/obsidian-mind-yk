# 4E. 可変長配列ポートの要素挿入

[[TECSCDE-DT外部仕様 - 06A 編集操作（前半）]]が継承する[[TECSCDE外部仕様 - 06A 編集操作（前半）]]6.1.2のInsert操作と固定長配列の挿入拒否を、[[TECSCDE-DT-EL内部仕様 - 03 モデル設計]]・[[TECSCDE-DT-EL内部仕様 - 04 編集コマンドとUndo-Redo設計]]・[[TECSCDE-DT-EL内部仕様 - 05 描画・インタラクション設計]]へ追加する設計です。2026-11-07の契約具体化であり、実装済みを意味しません。新しい型・関数・コード名は内部契約案です。要素削除（監査#13）は扱いません。

## 4E.1 配列の種別と要素の同一性

ポート宣言から、非配列・固定長・可変長・未解決を区別する`arrayKind`を保持します。`subscript`の有無や現在の要素数だけで、固定長か可変長かを推測しません。`[]`は可変長、`[N]`は固定長として宣言情報を保持し、サイズ式を解決できない宣言は未解決とします。

各配列グループは、**所有セルID・呼び口／受け口の種別・宣言ポートの識別子**で識別します。同じシグニチャでも別の宣言を一つの配列にまとめません。要素は`PortId`と現在の`subscript`を別々に持ちます。既存要素のIDは添字変更後も維持する設計とし、表示名や保存用添字からIDを作り直しません。

`CPort`要素は最大1本の`joinId`、`EPort`要素は複数の`joinIds`という既存の制約を維持します。受け口も宣言から可変長と確定できる場合は対象に含め、呼び口だけへ限定しません。未解決の配列種別は挿入可能とみなしません。セルタイプ宣言自体の固定長やシグニチャを書き換える操作ではありません。

## 4E.2 対象と入力

**内部設計案として、単一の配列要素を選択し、Insert単独でその直後へ1要素を挿入します。** 前後や複数選択の扱いは外部6.1.2に明記されていないため、この単一対象・後挿入を具体的な実装契約とします。Ruby版の操作記録にあるShift+Insertの前挿入は、今回のInsert単独の契約とは分けます。

`AppShell`のキーハンドラは`KeyboardEvent.key === 'Insert'`で判定し、文字キー`c`や数値のビットマスクを使いません。Ctrl・Alt・Meta・Shiftを伴う入力、IME変換中、テキスト入力欄・編集可能要素にフォーカスがある場合は、この操作として扱いません。ドラッグ・結合作成など別の入力操作中にも割り込みません。

| 条件 | 処理 |
|---|---|
| 編集可能セルの可変長配列要素を1つだけ選択 | 挿入計画を作り、成功時だけdispatch |
| 固定長配列要素を選択 | 挿入せず、固定長の拒否通知を出す |
| 非配列、配列種別未解決、読み取り専用セル | 挿入せず、対象外であることを既存のステータス通知で示す |
| ポート選択なし、または複数要素を選択 | 挿入せず、単一の可変長配列要素の選択を促す |

Insert操作を扱う対象があるときだけ`preventDefault()`します。他の編集機能のイベントまで一律に遮断しません。対象の選択は要素IDで解決し、同名ポートの先頭や配列の0番へ置き換えません。

## 4E.3 挿入計画とコマンド

UIから独立した`prepareArrayPortInsertion(doc, selectedPort)`（案）が対象を検証し、成功時に次の計画を返します。

```ts
interface ArrayPortInsertionPlan {
  readonly cellId: CellId;
  readonly direction: 'call' | 'entry';
  readonly declarationKey: string;
  readonly anchorPortId: PortId;
  readonly expectedElementIds: readonly PortId[];
  readonly insertIndex: number;
  readonly newPortId: PortId;
  // 新規要素の辺・オフセットを含む、確定した更新内容も保持する
}
// 成功: plan。拒否: fixed-array / not-array / unresolved / read-only / selection。
// InsertArrayPortElementCommand(plan).apply(doc) → TecscdeDocument
```

対象要素の現在添字が`i`なら`insertIndex = i + 1`とします。新規ID・挿入位置・配置結果はdispatch前に確定し、コマンドへ固定します。`apply()`は現在の選択やクリップボードを参照せず、同期・副作用なしで次の更新を一括適用します。

1. 所有セル・宣言・対象要素が存在し、編集可能な可変長配列で、要素ID列が計画の前提と一致することを確認します。対象がなくなった、固定長へ変わった、前提が変わった場合は元のdocを返します。
2. 新しい未結合要素を挿入します。CPortなら`joinId: null`、EPortなら`joinIds: []`です。既存の接続を新要素へコピーしません。
3. 挿入位置以降の既存要素の添字を1増やし、要素列の順序と添字の対応を更新します。既存PortId、結合ID、結合相手の要素IDは保持します。
4. 表示名・配列要素数・ポートの添字参照を同じ更新で一致させます。結合が添字を補助情報として持つ場合は、その情報も更新します。受け口要素に入る結合は一部だけでなく全件を保持します。
5. 配置変更で端点の位置が変わる結合は、第4章4.7の共通経路計算で再計算します。添字だけが変わり位置が同じなら、経路を不要に変更しません。

同じ計画を適用済みで`newPortId`が存在する場合もno-opにし、重複挿入しません。配列種別や宣言・結合の整合を更新の途中状態で通知しません。

## 4E.4 辺上の配置・選択・履歴

新規要素は選択した要素と同じ辺に配置する案とします。既存の辺上位置計算・ALIGN丸め・辺の長さによる制限を共用し、辺をまたいで自動配置しません。既存要素と同じ位置を無条件に採用せず、辺上の空き位置を求めます。必要な既存要素の位置調整は同じ配列グループ内に限定します。

辺上に配置できる位置がない場合は、セルや別の辺を勝手に変更せず、配置できないことを通知して挿入全体を拒否します。具体的な空き間隔と同じ配列内の再配置方法は既存のポート配置計算に合わせて実装時に確定する詳細事項とし、計画段階で成功／失敗を確定します。

成功した挿入全体を1コマンド・1Undo単位とします。Undoで要素数・ID・添字・結合・位置を元に戻し、Redoで同じ新規IDと対応関係を復元します。拒否やno-opではdirty・履歴を変更しません。拒否通知はコマンドの外で行い、履歴再生中に再表示しません。選択は既存の対象要素IDを維持し、添字変更によって別の要素を選んだことにしません。

## 4E.5 保存との接続

既存の結合先を保持したまま添字を更新した場合、保存では現在の要素添字から結合代入を組み立て直します。[[TECSCDE-DT外部仕様 - 04 コンポーネント図の表現]]4.6.xの原文維持は、**変更していない呼び口だけ**に適用します。挿入で呼び口添字が変わった配列は変更済みとして、添字付きの結合代入を書きます。受け口の添字が変わった場合も、その受け口を参照する全結合の出力を更新します。

定義元別の保存は[[TECSCDE-DT-EL内部仕様 - 04C ファイル別保存契約|4C]]に従います。別ソースの編集可能な呼び口が更新された受け口を参照している場合、その呼び口側ソースも保存変更対象とします。読み取り専用ソースの結合代入を書き換えなければ整合を維持できない計画は、事前に拒否して理由を知らせます。

**未結合要素の永続化は決定済み（2026-11-08）**: 外部5.1.xの`array_elements`へ個数を明示保存します。セルの定義元ソースと完全修飾セル名・方向・宣言ポート名で対応付け、挿入後の現在個数を`element_count`として出力します。実行中のPortIdは保存キーにせず、再読み込み時に必要な要素を生成してから結合と位置を適用します。PortIdの同一性は実行中のUndo/Redoで保証し、保存をまたぐ同一IDは要求しません。

ローダーは全ソースの宣言・結合から必要数を求め、検証済み個数情報がある可変長配列だけ`max(必要数, 保存個数, 1)`へ拡張します。受け口は入結合の参照添字を含めます。位置情報はその後に適用し、個数の根拠にしません。旧ファイルで個数情報がなければ従来規則を維持します。固定長・非配列・未解決には適用せず、不正値は警告します。負数・0・小数・安全な整数でない値・モデルの上限超過を拒否し、黙って切り詰めません。同じソース内の同一キー重複も警告して、そのキーの個数情報を適用しません。上限はモデルの配列生成で共用する制約とし、保存可能な状態が同じ版で再読込時に拒否されないようにします。

保存では既知の個数情報を現在モデルから再構成し、既存の未知キーを保持します。型未解決等で適用できない原情報は保持しますが、利用者が削除したセル・ポート・要素の既知情報は復活させません。`array_elements`だけを理由にCDLの結合原文を添字付きへ変更しません。外部編集で結合だけが減ったときは保存個数を尊重し、縮小には個数情報も変更・削除する規則です。これらは確定した仕様であり、実装適合は未確認です。

## 4E.6 拒否通知と検証条件

固定長配列の拒否には、`W-ARRAY-PORT-INSERT-REJECTED`（案、warning、sourceは`consistency`）を用い、「固定長配列には要素を挿入できません。」と対象セル・ポートを第9章形式で示します。ほかの拒否理由も同じ通知経路で対象と理由を示し、docを書き換えることでエラーを表現しません。

実装時は`tests/renderer/`で次を確認し、実機の選択・キー操作記録は`tests/verification/`へ置きます。

- 可変長呼び口の中間・末尾への挿入で、新規要素が未結合となり、後続添字・表示名・既存IDと結合先が一致すること。
- 可変長と確定した受け口配列でも挿入でき、後続要素への複数の入結合がすべて保持されること。
- 非配列・固定長・未解決・読み取り専用・複数選択・選択なしを拒否し、固定長には指定の通知を出すこと。いずれもdirty・履歴を変えないこと。
- `c`、修飾キー付きInsert、IME変換中、テキスト入力中、別の入力操作中に誤挿入しないこと。
- 1回のUndo/Redoと複数回の挿入、消えた対象への古い計画、同じ計画の二重適用でIDや結合が重複しないこと。
- 添字を省略した呼び口の結合が挿入によって変わる場合、現在の添字で保存され、変更されない別ポートの原文は保持されること。
- 受け口添字変更が別ソースの結合代入へ反映され、読み取り専用の参照元がある場合は原子性を保って拒否されること。
- 配置失敗を通知してモデルを保持し、成功時の位置・結合経路と選択IDがUndo/Redo後も整合すること。

配列要素の削除、Deleteの結合解除との優先関係、固定長・添字0の拒否は[[TECSCDE-DT-EL内部仕様 - 04F 配列ポートの要素削除|4F]]で定める。配列種別・安定PortId・未結合要素数の明示保存契約は共用する。

保存の往復検証には、末尾挿入後に結合を追加せず保存・再読み込みして個数と位置が戻ること、結合なし・受け口・複数ソース・同名別スコープ・名前変更・Save As、旧ファイル、固定長、不正値、重複キー、型未解決、外部で結合だけを削除した場合を含めます。比較対象は個数・添字・結合・位置とし、再読み込み後のPortIdの一致は要求しません。
