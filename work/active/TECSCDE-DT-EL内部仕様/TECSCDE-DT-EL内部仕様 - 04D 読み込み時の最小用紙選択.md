# 4D. 読み込み時の最小用紙選択

[[TECSCDE-DT-EL内部仕様 - 04B CDLパーサ設計]]4B.5の配置手順を具体化します。根拠は[[TECSCDE-DT外部仕様 - 05A 開く（読み込み）]]5.3.xの項目1〜7、特に用紙未指定時の最小用紙選択です。これは2026-11-07の内部設計の追加であり、実装済みを意味しません。関数名・補助型は契約案です。

## 4D.1 入力と責務

`ToolInfoValidator`は、レイアウトとともに**用紙の指定有無**をローダーへ渡します。未指定を早い段階で`PaperSpec.default()`へ置き換えると、明示的なA4指定と区別できなくなるため、最終選択までは区別を保持します。

```ts
type LoadPaperInput =
  | { readonly kind: 'specified'; readonly paper: PaperSpec }
  | { readonly kind: 'unspecified' };

// 純粋な計算。入力のセルやドキュメントを変更しない。
// chooseLoadPaperAndLayout(paperInput, fixedCells, unpositionedCells)
//   → { paper, placements, overflowCellIds }
```

- `fixedCells`は、全ソースから読み込んだセルのうち、有効な保存済みレイアウトを持つセルです。編集対象ファイルグループ内のファイル（主ファイル・追加ソースの区別はしない）・読み取り専用の別で除外しません。
- `unpositionedCells`は、位置を持たないセルだけです。既存ローダーで採用した定義の順序を固定して渡し、候補用紙によって並べ替えません。
- 可視フィルタや検索の状態によって、収容判定のセルを除外しません。
- 用紙寸法と内容領域は既存の`PaperSpec`から取得し、画面のpxやズーム率を使いません。

全ソースの解析・同名セルの採否・保存済み位置の検証を済ませてから、固定セル集合を確定します。ソースを読む途中で自動配置を確定し、後から読んだソースの固定セルと衝突する順序にはしません。

**検証との境界**: 不正な`paper`値は既存の`ToolInfoValidator`の検証・警告の対象です。既存の検証規則で棄却され、有効な指定が残らなければ`unspecified`として扱う内部設計とします。複数ソースの相反する有効な`paper`の採用優先順位は、外部仕様[[TECSCDE-DT外部仕様 - 05B CDLファイル一覧の作成と自動配置|5.3.x]]項目8で2026-11-08に決定されました。編集対象ファイルグループ内で、**開いた順に最初に有効な`paper`を宣言しているファイル（採用元）**の指定を採用し、採用元以外の相違は`W-PAPER-CONFLICT`で通知します。「開いた順」は、ソース配列の並びとは別に保持した順序を使います。本節の計算には、採用元を確定した`LoadPaperInput`を渡します。全ソースで指定なしなら`unspecified`です。アプリケーション既定は新規作成にだけ適用し、読み込みの`unspecified`には適用しません。

## 4D.2 用紙候補の試行

1. `specified`なら、その用紙と向きを採用します。A4横→A3横→A2横の試行はせず、その指定用紙内で配置します。収まらなくても自動拡大しません。
2. `unspecified`なら、**A4横 → A3横 → A2横**の順に候補を試します。自動選択に縦向きやA2より大きな用紙を加えません。
3. 各候補で固定セルを元の位置・大きさのまま置き、自動配置対象を同じ入力順で走査します。候補位置は(10, 10)mmを起点に横55mm刻み、用紙幅−30mmを超えたら次の段へ縦30mm進む、外部仕様5.3.xの格子順を使います。
4. 各自動配置セルについて、**用紙内に矩形全体が収まり、固定セルおよび同じ試行で先に置いたセルと重ならない最初の候補**へ置きます。保存済みセルの位置を移動・縮小して空きを作りません。
5. 固定セルも含む全セルが用紙内に収まり、重ならない配置が成立した最初の候補を採用します。既存の格子順による配置試行での最小用紙であり、任意の並べ替え・詰め直しによる最適化は行いません。
6. 小さい用紙で失敗しても、そこでの配置を大きい用紙へ引き継ぎません。元の固定セル集合と自動配置対象から、次の候補を最初から試します。

候補試行中は、重ね配置を許すずらし処理を行いません。A4に重ねて置けたことを、重なりなしで収容できた成功と判断しないためです。空の図、または全セルが固定済みでも、用紙未指定なら同じ収容条件で最小候補を選びます。空の図はA4横になります。

## 4D.3 最大候補でも収まらない場合

A2横まで重なりなしで収まらなければ、**A2横を採用**し、その用紙で最終配置を行います。指定済み用紙で収まらない場合も、用紙を変えず同じ最終配置処理へ進みます。

最終配置では、固定セルを保持し、自動配置対象を同じ格子順で置きます。重ならない候補がなくなったセルだけ、外部仕様の横8mm・縦6mmずつずらすフォールバックへ進みます。新たに自動配置するセルを用紙外へ置くことで収容扱いにはしません。

`overflowCellIds`は、重なりなしの候補がなくフォールバックした**自動配置セル**のID集合とし、同一セルは一度だけ数えます。固定セル同士の既存の重なりや固定セルの用紙外配置も、候補の成功条件を満たしたことにはしませんが、その位置を自動修正しません。外部仕様第9章の警告対象に合わせ、固定セルの既存の異常を自動配置のoverflow件数へ加算しません。固定済みレイアウト自体の異常の扱いは既存の検証規則と区別し、追加の通知方法が必要な場合は別途TBCとします。

最終的な同集合が空でなければ、そのセル数で`W-AUTO-LAYOUT-OVERFLOW`を出します。不採用のA4・A3の試行での件数や警告は残しません。

## 4D.4 モデルへの反映と保存

ローダーは用紙と自動配置結果を一組で確定し、`TecscdeDocument.build`へ渡します。セル位置を確定したあと、4B.5の結合組み立てへ進み、保存済みの有効経路がない結合を最終位置から計算します。試行中のセル位置で経路を確定しません。

用紙選択と配置試行はrenderer内の純粋な計算とし、ファイル書き込み・ストア通知・履歴追加・診断登録は試行中に行いません。採用結果と最終警告だけをロード結果へ反映します。

通常の保存では、選んだ用紙を`__tool_info__("tecscde")`の`paper`へ書きます。書き込み先は、**採用元の1ファイル**（どのファイルも宣言していなければ最初に開いたファイル）だけとし、他のファイルの`paper`は書き換えません。用紙だけを変更した場合も、その書き込み先を保存対象に含めます（外部仕様5.3.x項目8）。編集可能セルの位置は[[TECSCDE-DT-EL内部仕様 - 04C ファイル別保存契約|4C]]の定義元別保存契約に従って保存します。読み取り専用・Plugin生成セルをこの処理のために保存対象へ加えません。次回の読み込みでは、保存した用紙は指定済みとして尊重し、有効な保存済み位置を再配置しません。

読み込み時のこの用紙自動選択を、画面上の用紙変更、通常の「再配置」、[[TECSCDE-DT-EL内部仕様 - 06C V0.2.0表示と配置]]のactive最上段配置に自動適用しません。ファイルを読み込まない新規作成の既定用紙は、この自動選択の対象外です。外部仕様[[TECSCDE-DT外部仕様 - 03 画面構成|3.2.y]]（2026-11-08）に従い、アプリケーション既定が設定されていればその用紙、なければA4横とします。アプリケーション既定は新規作成にだけ適用し、読み込み時の`unspecified`（上記の最小用紙選択）には適用しません。したがって、アプリケーション既定がA3横でも、用紙指定のないファイルの読み込みは、A4横から順に最小用紙を試す動作のままです。なお、4D.2の空の図の結果（A4横）は、読み込んだ空のファイルについての規定で、新規作成の既定用紙とは別です。

## 4D.5 実装時の検証条件

- 用紙未指定でA4に収まる／A3で初めて収まる／A2で初めて収まるケースを用意し、最初に成功した用紙を選ぶことを確認します。
- 自動配置対象の後ろに読み込まれる別ソースの固定セルも、最初の候補から障害物として使われることを確認します。固定セルの座標・大きさは全試行後も不変とします。
- 固定セルがA4外・A3内ならA3以上を選び、固定セル同士の重なりやA2外の固定位置を、移動して成功扱いにしないことを確認します。
- A4で重ね配置可能でも、A3で重なりなしに収まるならA3を選ぶことを確認します。各試行の初期状態・セル順が同じで、不採用候補の配置・警告を持ち越さないことも確認します。
- A2でも失敗する場合はA2を採用し、ずらし配置と重複のない最終overflow件数を確認します。固定セルの既存の異常を自動配置セルの件数へ加算しないことも確認します。明示A4横・縦の指定は、収まらなくても変更しないことを確認します。
- 未指定と明示A4を区別し、不正な指定を棄却した場合、空図、配置対象なし、複数ソースで有効な指定が一意な場合を確認します。競合指定は、開いた順で最初に有効な宣言を持つファイルが採用元になること、採用元以外の相違で`W-PAPER-CONFLICT`が出て用紙は変わらないこと、`size`不正は宣言なし・`orientation`不正は横として扱い`W-PAPER-INVALID`が出ること、ソース配列の並びを変えても開いた順で結果が決まること、用紙だけの変更でも書き込み先が保存対象になり他ファイルの`paper`が保持されることを確認します（2026-11-08）。
- 保存した`paper`と編集可能セルの位置を再読み込みし、同じ用紙・配置が復元されることを確認します。
- 計算とローダーのテストは`tests/renderer/`、用紙・セル配置の実機記録は`tests/verification/`へ置きます。これは将来の受入条件であり、今回の文書更新で実装テストを実行したという意味ではありません。
