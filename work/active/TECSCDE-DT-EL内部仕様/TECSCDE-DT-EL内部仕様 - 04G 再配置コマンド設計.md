# 4G. 再配置コマンド設計

[[TECSCDE-DT外部仕様 - 07 表示機能]]7.3.xの「再配置」「全体再配置」を、[[TECSCDE-DT-EL内部仕様 - 04 編集コマンドとUndo-Redo設計]]へ追加します。配置規則は[[TECSCDE-DT外部仕様 - 05A 開く（読み込み）]]5.3.xを共用します。2026-11-08の内部設計案であり、実装済みを意味しません。

## 4G.1 操作と対応コマンド

| 操作 | 対象 | コマンド案 | 有効条件 |
|---|---|---|---|
| 再配置 | 選択セルのうち、存在し編集可能なセル | `RelayoutSelectedCellsCommand(plan)` | 対象が1個以上 |
| 全体再配置 | 選択にかかわらず、存在する全編集可能セル | `RelayoutAllCellsCommand(plan)` | 編集可能セルが1個以上 |

両コマンドは同じ`RelayoutCellsCommand`の適用処理と`prepareRelayout`の純粋な配置計算を共用します。対象集合が同じなら同じ配置結果を返します。ツールバーは整列の隣に2つのボタンを置きます。ポートや結合バーの選択だけでは「再配置」の対象セルを補いません。

「現在の並びの順」は、内部設計として**操作開始時の`doc.cellValues()`の列挙順**と定義します。選択IDを重複除去したあと、その文書順で対象を列挙します。セル名順やクリックした順に並べ替えず、計画へ確定した順序を保持します。

可視性では対象を絞りません。非表示でも選択集合にある編集可能セルは再配置対象とし、全体再配置も非表示セルを含む全編集可能セルを扱います。フィルタ・検索・activeOnlyは計算へ持ち込みません。

## 4G.2 固定セルと現在用紙

対象外の**全セル**を固定障害物とします。未選択の編集可能セル、読み取り専用・Plugin生成セル、別ソースのセル、非表示セルも除外しません。対象セルの古い矩形は障害物から外し、固定セルと、同じ計画で先に配置した対象セルに対して空きを探します。

現在の`doc.paper`のサイズと向きを使います。[[TECSCDE-DT-EL内部仕様 - 04D 読み込み時の最小用紙選択|4D]]の読み込み時のA4横→A3横→A2横の自動選択は呼びません。収まらないからといって用紙を変えず、固定セルを動かしたり縮小したりもしません。セルのサイズ・所属リージョン・定義元・ポートの所属辺とセル内オフセットも変更しません。

## 4G.3 純粋な配置計画

```ts
interface RelayoutPlan {
  readonly scope: 'selected' | 'all';
  readonly orderedCellIds: readonly CellId[];
  readonly precondition: LayoutPrecondition;
  readonly moves: readonly CellRectChange[];
  readonly joinRoutes: readonly JoinRouteChange[];
  readonly overflowCellIds: readonly CellId[];
}
// prepareRelayout(doc, scope, selectedCellIds)
//   → 計画と警告情報、変更なし、または配置不能の理由
// new RelayoutSelectedCellsCommand(plan)
// new RelayoutAllCellsCommand(plan)
```

型と関数名は契約案です。`LayoutPrecondition`には、対象と固定セルのID集合・位置・寸法・編集可否・定義元、現在用紙、ポート配置、関係結合の端点等、計算結果が依存する値を保持します。再生で変わるオブジェクト参照やストアの通知回数を前提検査に使いません。

配置計算は次の順で行います。

1. 固定障害物と対象の順序を確定します。候補の原点は(10, 10)mm、横55mm刻み、用紙幅−30mmを超えたら次の段へ縦30mm進む既存の格子順を使います。
2. 各対象セルを、矩形全体が現在用紙内に収まり、固定障害物と先に配置した対象セルに重ならない**最初の候補**へ置きます。寸法は各セルの現在値を使います。
3. 重ならない候補がなくなった対象だけ、格子の先頭から横8mm・縦6mmずつずらすフォールバックへ進めます。フォールバックしたセルIDを`overflowCellIds`へ一度だけ記録します。固定セル同士の既存の重なりや用紙外位置はこの件数に混ぜません。
4. フォールバックの走査状態は計画内で共有し、各対象を毎回同じ先頭位置へ戻しません。ずらした格子を順に使い、走査し直すたびにずれを1段階増やします。用紙内に矩形全体が収まる候補だけを採用し、重なりはこのフォールバックで許容します。
5. 全対象の最終位置を確定したあと、4G.4の関係結合の経路を求めます。位置と経路をまとめて計画へ固定します。計画中はストア通知・履歴・診断・ファイルI/Oを行いません。

**探索の終端（内部設計）**: 用紙の有限な内容領域から通常格子の範囲を求め、ずれ段階`k`も、最小の候補原点(10+8k, 10+6k)に対象矩形を置ける範囲までに制限します。用紙外の候補を探し続けません。セル自体が用紙より大きい場合や、有限なずらし候補でも配置できない場合は、**計画全体を配置不能として返す**設計とします。対象の一部だけを動かす・セルを縮める・用紙を変えることで成功扱いにしません。これは物理的に配置不能な場合の内部処理であり、通常のoverflow時は上記のずらし配置と警告を行います。

## 4G.4 結合経路の更新

実際に位置が変わるセルにつながる結合を、呼び口・受け口の両側から集め、結合IDで重複除去します。**全対象の新位置を置いた最終モデル**のポート座標と全セル矩形で、第4章4.7の共通経路計算を行います。1セル動かすたびに途中状態で経路を確定しません。

結合のID・接続先・配列添字・シグニチャは変更しません。読み取り専用セルが相手でもその位置は動かさず、編集可能なセルの再配置を相手の編集可否だけで拒否しません。必要な経路表示の再計算と、CDLの結合代入や読み取り専用セルの変更は区別します。

現在の経路を新経路で置き換え、元の経路はUndoで再現できる計画情報として保持します。関係しない結合の手動経路は変更しません。位置・端点が変わらないセルだけなら、結合経路を不要に作り直しません。

## 4G.5 `apply`・履歴・画面状態

`apply(doc)`は、全前提を検査してから位置と経路を一括更新する同期・純粋な処理とします。前提が変わった、対象が消えた、編集可否が変わった場合は、元のdocを返します。障害物の追加・移動や用紙変更も前提に含め、古い計画をそのまま適用しません。同じ計画の二重適用もno-opにします。

対象順・最終位置・経路はコマンド入力へ固定し、`apply()`から選択・フィルタ・UI・クリップボードを読み直しません。既存`History`の再生方式を使い、`invert()`を追加しません。各ボタンの1回の操作を**1コマンド・1Undo**にまとめ、Undo/Redoで位置と経路を一緒に復元します。

計画が配置不能、対象なし、または位置・経路がすべて変更なしなら、履歴・dirtyを変更しません。成功したモデル変更だけをdispatchします。overflow情報は変更なしでも現在の計算結果として通知できますが、モデル変更を作って警告を表現しません。

選択、検索語、可視フィルタ、ズーム・パン、用紙、主ファイル・参照集合を変更しません。確定後の通常描画によって、状態記号・リージョン外周・検索強調等が新しい座標へ追従します。選択対象や入力モードを、計画の途中状態で変更しません。

## 4G.6 保存・警告・他の配置操作との関係

位置は[[TECSCDE-DT-EL内部仕様 - 04C ファイル別保存契約|4C]]の定義元別契約で、編集可能な各元ソースへ保存します。変更した結合レイアウトも、その保存対象の規則に従います。相手が読み取り専用の経路を再計算しても、そのソースを新たに保存対象へ加えません。読み取り専用セルの位置や生成物は保存しません。

`overflowCellIds`が空でなければ、`W-AUTO-LAYOUT-OVERFLOW`で対象セル数を知らせます。配置不能で操作を拒否する場合は、`W-RELAYOUT-FAILED`（案、warning、`source: 'consistency'`）で「現在の用紙内に配置できないため、再配置を行いませんでした。」と理由を示します。確認ダイアログは追加しません。

診断の登録は呼び出し側で、計画の最終結果から一度だけ行います。現在の図・操作に関連付けた警告を差し替え、履歴再生中の`apply()`から通知を追加しません。Undoでその操作が外れたときは該当警告を解除し、Redo時は保存した計画情報から現在の警告表示を再構成します。文書の切り替えでも古い操作の警告を残しません。

4Dの読み込み時配置とは、用紙が確定したあとの格子・衝突・ずらし計算を共用できます。ただし4Dは「位置なしセルだけを配置」「必要なら最小用紙を選ぶ」、本節は「選んだ編集可能セルの既存位置を捨てて現在用紙で再配置」という入力条件を分けます。

[[TECSCDE-DT-EL内部仕様 - 06C V0.2.0表示と配置]]6C.4のactive最上段配置は、対象の選び方と最上段を優先する別の計画です。コマンドの純粋性・経路更新・1Undoの共通処理は利用できます。最上段不足時の扱いは2026-11-08に6C.4で決定済みで、本節のずらしフォールバック（重なりの許容）は流用しません。格子走査は`allowOverlap: false`を指定して共用します。操作入口は6C.4で決定済みです（2026-11-08。ツールバーのボタン）。

## 4G.7 実装時の検証条件

- 「再配置」の選択混在（編集可能・読み取り専用・存在しないID）、選択なし、ポートだけの選択で対象とボタン可否が一致すること。
- 「全体再配置」が選択に依存せず全編集可能セルを対象とし、同じ対象集合を全選択して「再配置」した結果と一致すること。
- 文書の列挙順を保持し、対象の旧位置を障害物へ残さず、未選択・読み取り専用・別ソース・非表示セルを固定障害物に含めること。
- (10,10)、横55mm・縦30mm、重なりなしの最初の候補、横8mm・縦6mmのずらしと重複のないoverflow件数を確認すること。
- 現在用紙の向きと大きさを尊重し、通常再配置でA4→A3→A2選択を行わないこと。用紙より大きなセル・探索不能時は全体を拒否し、無限探索しないこと。
- 関係結合を重複なく最終位置で再計算し、接続先・添字と対象外セルの位置を保持すること。読み取り専用の相手や自己結合、関係しない手動経路も確認すること。
- 複数セルと経路が1回のUndo/Redoで復元され、同じ計画・変更なし・古い計画で不要な変更や履歴を作らないこと。
- 障害物・対象の編集可否・用紙の変更による前提失敗を確認すること。選択・フィルタの変更では確定済み計画の対象や結果を変えず、再生中の通知重複やUndo後の古い警告を残さないこと。
- 定義元別保存に再配置位置が反映され、読み取り専用ソースは書き換えられないこと。
- 純粋計算・コマンド・DOMのテストは`tests/renderer/`、再配置とUndo/Redoの実機記録は`tests/verification/`へ置くこと。今回は設計の更新であり、これらの実装テストを行ったという記録ではありません。
