# 3B. 複合セルタイプ設計

## 3B.1 対象と不変条件

本章は[[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 - 04 コンポーネント図の表現|外部仕様4.7節]]を実現する。複合セルタイプの**定義**と、その型を参照する外側の**セルインスタンス**を区別する。

1. 読み込んだ複合型のインスタンスは通常セルと同じ矩形・名前・型名・外部ポート・外部結合で表示する。
2. 内部セル・内部結合・ポート転送を図上で展開しない。ダブルクリック、Enter、その他の操作から内部図へ遷移しない。
3. 図上で複合セルタイプの定義を新規作成・編集しない。既存の型を使う外側セルの作成・移動・名前や属性の編集・結合は、通常セルの編集可否に従う。
4. 未対応構文があれば、選択した外側セルのプロパティ欄に「未対応構文があります」のような存在通知だけを示す。構文の本文、位置、件数、内部構造は同欄に出さず、編集 UI も設けない。
5. 読み込んだ複合定義の原文は、外側セルを編集して保存しても変化させない。

複合型のインスタンスを新規に置くことは、複合型の**定義**を新規作成することには当たらない。未解決のセルタイプは既存の未解決セル表示・診断に従う。

## 3B.2 モジュールとデータ

| 責務 | 配置 | 契約 |
|---|---|---|
| 複合定義の解析 | renderer の `cdl/cst.ts` | 外部ポート・属性、定義の原文、未対応構文の有無を `CompositeDecl` として返す |
| 型レジストリとインスタンス化 | renderer の `cdl/document-builder.ts`、`model/celltype.ts` | `CelltypeRef` に外部インタフェースと未対応フラグを保持し、通常の `Cell` と `CPort`/`EPort` を生成する |
| 表示と操作 | renderer の `render/svg-renderer.ts`、`app/shell.ts`、`app/property-panel.ts` | 外側のセルだけを描画し、内部図への遷移を配線しない。プロパティ欄にフラグだけを表示する |
| 保存 | renderer の `cdl/serializer.ts` | 元の複合定義を原文のまま保持し、保存後の一致を確認する |

main/preload への新しい IPC は設けない。外部ポートと属性には既存の `PortTemplate`、`CelltypeRef`、`Cell` を用いる。`CompositeStructure.rawText` は保存検証のために保持する。既存の内部セル・ポート転送の解析結果を保持してもよいが、図とプロパティ欄の表示入力には使用しない。

`CompositeDecl` と `CelltypeRef` に `hasUnsupportedSyntax: boolean` を追加する。値は型定義に属し、同じ複合型の各インスタンスで共有する。セルごとの保存データや `__tool_info__` へ複写しない。読み込みのたびに CST から再計算し、別ファイルに切り替えた際に前の値を残さない。

## 3B.3 読み込みと未対応構文の判定

`CdlDocumentBuilder.collectComposite()`はtree-sitterの複合定義から外部ポート・属性・定義原文を抽出する。署名とnamespaceは通常セルタイプと同じ規則で解決する。`CdlDocumentLoader.loadSources()`は主ファイルと追加読み込みファイルの複合定義を型レジストリへ登録し、通常CDL由来の複合セルも編集可能とする。Plugin生成CDL由来のセルだけを読み取り専用とする（第7C章7.7.5節）。

未対応構文の判定は原文への正規表現では行わない。複合定義の CST を走査し、次のいずれかがあれば `hasUnsupportedSyntax` を真にする。

- 複合定義の本文にある節をラッパーノードから取り出した結果、外部ポート・属性として抽出する節と、原文保持対象として認識する内部セル・内部結合・ポート転送以外の節がある。
- 認識した節でも、図に必要な外部ポート名・署名など必須フィールドを抽出できない。
- 複合定義内に tree-sitter の `ERROR` または `MISSING` ノードがある。この構文エラーは従来どおり診断にも出す。

内部セル・内部結合・ポート転送は**非表示だが原文保持対象**であり、存在するだけでは未対応としない。型が複合であるだけでも未対応としない。認識できない節は原文を保持して読み込みを継続し、外側のセルと解決できた外部ポートは残す。フラグは存在の真偽だけを公開し、未対応節の本文や数を UI へ渡さない。

## 3B.4 描画・操作・プロパティ

`SvgRenderer` と `CellRenderer` は複合型の外側セルに専用の内部図を重ねず、既存の通常セル描画を使う。ポートの位置、結合候補、結合線、選択、検索、ズーム・パンも通常セルの経路を使う。`AppShell` は複合型セルのダブルクリックと Enter を内部図の `openCell()` へ結び付けない。`CompositeDiagramView` は表示経路から外し、内部図のボタンやキーボード導線を出さない。

`PropertyPanelView.renderCell()` は既存の通常セルの項目と編集可否を維持する。`doc.getCelltype(cell.celltypeName)?.hasUnsupportedSyntax` が真の場合だけ、読み取り専用の通知を一つ追加する。偽の場合は未対応に関する項目を出さない。通知は構文の種類や raw text を含まない。複合型の定義・内部セル・内部結合・ポート転送を編集するフィールドやコマンドは設けない。

`PaletteView` と `AddCellCommand` は既存の型を使う外側セルの作成に限って使える。複合型そのものを定義するメニュー・コマンドは追加しない。外側セルの編集・Undo/Redo は通常セルのコマンドに従う。

## 3B.5 診断と保存

`W-COMPOSITE-UNSUPPORTED` のような、複合型の存在だけを理由とする一律警告は生成しない。未対応構文の存在通知はプロパティ欄専用で、診断一覧にも追加しない。構文エラー、署名未解決、結合先不在など、独立した既存の診断は維持する。

既存の CDL を開いた場合、`CdlSourceTemplate` に複合定義の原文を保持する。`CdlSerializer.serializeFromTemplate()` は外側セルと `__tool_info__` に必要な編集だけを適用し、複合定義の本文を書き換えない。保存後に複合定義の個数・名前・`rawText` が元と一致しなければ保存を失敗させる。新規文書から複合型の**定義**を合成する経路は設けない。

## 3B.6 検証条件と実装差分

- 複合型の外部 `call`/`entry` ポートと属性を持つ CDL を開き、外側セルと通常セルとの外部結合が表示される。内部セル・内部結合は図に現れない。
- 複合型セルをダブルクリックし Enter を押しても内部図が開かない。外側セルの通常操作と編集可否は維持される。
- 認識済みの内部構文だけなら未対応通知は出ない。未知の節または抽出不能な節を含む場合は、プロパティ欄に存在通知だけが出る。他の複合型へ選択を変えると通知状態も切り替わる。
- 無編集保存と外側セルの編集後保存で、複合定義の原文が完全一致する。読み込み直し後も外側のポートと結合が復元される。
- 未対応構文があっても外側セルを保持する。構文エラーは診断に残し、複合型の存在だけでは診断を増やさない。

現行コードは外部ポートの登録と複合定義の保存検証を備える。一方、内部図を開く `AppShell.bindCompositeDrilldown()` と `CompositeDiagramView` は本仕様と異なり、未対応フラグの検出・プロパティ表示も未実装である。実装時はこの差分を解消する。
