# 4F. 配列ポートの要素削除

[[TECSCDE-DT外部仕様 - 06A 編集操作（前半）]]が継承する[[TECSCDE外部仕様 - 06A 編集操作（前半）]]6.3.2の削除規則を具体化します。配列種別・グループ・安定したPortIdは[[TECSCDE-DT-EL内部仕様 - 04E 可変長配列ポートの要素挿入|4E]]と共用します。2026-11-07の内部設計案であり、実装済みを意味しません。要素挿入の契約は変更しません。

## 4F.1 Deleteの優先関係

外部仕様は、ポート選択からの結合削除と、固定長・添字0の配列要素削除拒否を両方要求します。接続済み配列要素へのDeleteの優先関係は未規定のため、**内部設計では「結合ありなら結合だけ、結合なしなら要素削除」**とします。

`AppShell`はポートだけを選択した状態で`KeyboardEvent.key === 'Delete'`を受けたとき、次の順に処理します。テキスト入力中・IME変換中・別の入力操作中は横取りしません。セルや結合バーを選択した通常の削除は、既存のカスケード・結合削除処理へ委譲します。

1. 選択ポートの結合IDを集めます。呼び口は`joinId`、受け口は`joinIds`の**全件**を対象とし、同じ結合IDは重複除去します。
2. 結合が1本以上あれば、既存`DeleteCommand([], joinIds)`等の結合削除経路を使います。**このDeleteでは配列要素を削除しません**。結合削除の編集可否を既存規則で確認し、固定長・添字0という要素削除制約だけを理由に結合解除を拒否しません。
3. 選択ポートすべてが未結合なら、配列要素削除の計画を作ります。選択中の一部だけに結合がある場合も、まず結合削除だけを行い、未結合の別要素を同じキー操作で同時に消しません。

この優先関係により、接続済みの可変長要素は1回目のDeleteで接続を解除し、再度のDeleteで要素自体を削除できます。固定長・添字0は、接続がなくなったあとで要素削除を要求された場合に拒否通知を出します。削除確認ダイアログは設けません。

## 4F.2 配列要素の削除条件

以下は**要素自体の削除**へ進む場合の判定です。操作開始時点で選択したPortId集合と、その時点の添字で判定します。

| 対象 | 判定・通知 |
|---|---|
| 編集可能セルの可変長配列、添字1以上、未結合 | 削除可能 |
| 固定長配列 | 拒否。「固定長配列の要素は削除できません。」 |
| 可変長配列の添字0 | 拒否。「先頭要素は削除できません」 |
| 非配列 | 個別のポート削除は拒否。ポートはセル削除に伴ってのみ除去 |
| 配列種別未解決、読み取り専用セル | 拒否し、対象と理由を通知 |
| 選択なし | 変更なし |

複数配列・複数要素の選択は、削除対象IDを一つの計画へまとめます。削除可能な要素と拒否対象が混在した場合は、**内部設計案として要素削除計画全体を拒否**し、対象別の理由をまとめて通知します。黙って一部だけ消しません。

添字0は操作前の要素の同一性で保護します。例えば添字1と2の同時削除は、1を消して2を再添字してから次の対象を探す処理にしません。両方の元IDを削除し、最後に残存要素へ再添字します。添字0を残すため、可変長配列の最後の1要素も削除されません。

## 4F.3 計画と純粋なコマンド

```ts
interface ArrayPortElementDeletionPlan {
  readonly groups: readonly {
    readonly cellId: CellId;
    readonly direction: 'call' | 'entry';
    readonly declarationKey: string;
    readonly expectedElementIds: readonly PortId[];
    readonly deletePortIds: readonly PortId[];
  }[];
  // 残存要素の添字、参照先添字、保存変更元等の確定した更新内容も保持
}
// prepareArrayPortElementDeletion(doc, selectedPortIds)
//   → 計画、または対象別の拒否理由
// DeleteArrayPortElementsCommand(plan).apply(doc) → TecscdeDocument
```

計画はdispatch前に作り、選択IDを重複除去します。対象の所属グループ、配列種別、編集可否、添字、未結合条件に加え、再添字で更新する参照元ソースの編集可否も検証します。

`apply()`は同期・副作用なしで次を一括適用します。

1. 全グループの要素ID列と削除条件を検査します。対象が既にない、新しい接続が付いた、編集不可へ変わった等の前提不一致があれば、**一部を変更せず**元のdocを返します。
2. 削除対象のPortIdだけを各グループから取り除きます。所有セルやセルタイプ宣言は削除しません。
3. 残存要素の順序を保ち、各添字を「元の添字−それより前で削除した要素数」へ更新します。要素のID、シグニチャ、所属辺・位置は維持します。表示名と要素数も同じ更新に含めます。
4. 残存する呼び口・受け口の結合端点は、同じ残存PortIdを参照し続けます。受け口への複数結合も全件維持し、補助的な添字情報と保存用の参照を新しい添字へ更新します。消えた添字と同じ番号になった別要素へ、IDに結び付いた接続を移し替えません。
5. doc内の削除要素のレイアウト等の参照を除去します。doc外の型索引・選択・表示状態は`apply()`から変更せず、4F.4の確定後の同期へ分けます。

削除対象は未結合という前提なので、このコマンドで結合を新たに削除しません。結合が付いた古い計画を、接続ごと消す指示として再解釈しません。同じ計画の二重適用は対象が存在しないためno-opになります。

## 4F.4 履歴・選択・描画

結合解除の1操作、または複数要素削除の1操作を、それぞれ**1回のUndo**にまとめます。2段階のDeleteを一つの履歴へまとめず、利用者が行った各操作を戻せるようにします。要素削除のUndo/Redoは、元のPortId・添字・要素数・位置・結合の参照関係を再現します。`History`の既存の再生方式を使い、逆操作を別実装しません。

拒否とno-opはdirty・履歴を変えません。計画は履歴再生中の選択やUI状態から作り直しません。拒否通知も履歴の外で行います。

削除に成功した要素IDだけを選択から外し、残存選択は同じIDのまま保持します。同じ添字になった別要素を自動選択しません。Undo/Redo後も存在しないIDを選択に残さないよう、選択を現モデルに対して整合させます。削除済みポートを指す表示用の結合強調状態も解除します。

第3章3.4節の`PortTypeIndex`はdoc外の`AppStore`に保持するため、commit・Undo・Redoの確定後に、ストアが現在のdocと保持している宣言・型解決情報から要素別の索引を再導出・同期します。削除時にだけ破棄する処理にはせず、Undoで復元した要素の型情報も再現します。選択・表示状態の同期と併せ、描画通知前に確定モデルへ合わせます。これらの同期を履歴再生中の`apply()`の副作用にはしません。

残存ポートの位置は変えず、削除後の空きを自動整列で埋めません。したがって添字だけが変わる残存結合は経路を維持します。結合解除時は対象線だけを除去し、通常の要素再描画を同じ確定モデルから行います。

## 4F.5 定義元別保存

[[TECSCDE-DT-EL内部仕様 - 04C ファイル別保存契約|4C]]と[[TECSCDE-DT-EL内部仕様 - 04E 可変長配列ポートの要素挿入|4E.5]]の保存契約を共用します。

- 要素削除・再添字で変更した呼び口配列の結合は、現在の添字を使う変更済みの代入として出力します。添字省略形式を無変更の原文として戻しません。
- 受け口の添字変更では、その受け口を参照する**全呼び口側**の出力を更新します。参照元が別ソースなら、そのソースも変更保存対象とします。書き換えが必要な読み取り専用ソースがある場合は、要素削除計画を事前に拒否します。
- 4F.1の結合解除で削除した代入、削除要素の保存レイアウトを元テンプレートから復活させません。関係しない配列とソースの原文は保持します。
- 未結合要素数は外部5.1.x・4E.5の`array_elements`で復元します（2026-11-08決定）。削除後の現在個数へ更新し、削除した要素の位置情報を除去します。古い個数・位置をテンプレートから復活させません。

## 4F.6 拒否通知と実装時の検証

要素削除の拒否には`W-ARRAY-PORT-DELETE-REJECTED`（案、warning、`source: 'consistency'`）を用います。固定長と先頭要素の拒否文言は4F.2のとおりとし、第9章形式で対象と理由を示します。複数対象の拒否をまとめても、どの要素が拒否されたかを失わせません。確認ダイアログではなく、操作後の拒否通知です。

計算・コマンド・DOMのテストは`tests/renderer/`、実機のキー操作記録は`tests/verification/`に置き、次を確認します。

- 接続ありの呼び口・受け口・固定長・添字0で、Deleteがまず結合だけを削除すること。受け口の全結合と重複排除、既存の読み取り専用制約も確認します。
- 未結合の可変長要素の中間・末尾・複数要素削除で、残存IDと接続相手を維持し、後続添字・表示名を一度だけ更新すること。
- 固定長・添字0・非配列・未解決・読み取り専用と削除可能対象が混在した場合、要素削除全体を拒否してモデル・dirty・履歴を維持すること。
- 先頭要素の拒否文言を表示し、黙って無視しないこと。確認ダイアログを出さないこと。
- 複数グループと受け口の複数参照元、別ソースの保存更新、読み取り専用参照元がある場合の全体拒否を確認すること。
- 古い計画、削除済み要素、新たに結合された要素への計画を適用しても、一部変更や不意の結合削除を起こさないこと。
- 各Delete操作のUndo/Redoで、要素数・ID・添字・位置・結合・選択の整合が保たれること。入力欄やIME変換中のDeleteで図が変わらないこと。
- 保存後の出力に削除した代入・要素レイアウトが残らず、残存結合の添字が現在のモデルと一致すること。未結合末尾要素の削除後に保存・再読み込みし、縮小後の個数と残存位置が復元されること。
