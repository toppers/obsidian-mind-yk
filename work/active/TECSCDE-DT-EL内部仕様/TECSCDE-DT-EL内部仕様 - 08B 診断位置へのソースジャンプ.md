# 8B. 診断位置へのソースジャンプ

[[TECSCDE-DT外部仕様 - 09 エラーと警告]]9.1・9.3、および継承元[[TECSCDE外部仕様 - 09 エラーと警告]]9.1.2の、位置情報からCDLの該当箇所へ移動できる要件を具体化します。継承元TS内部仕様8.4の「図要素がなければテキスト位置の提示に留める」は、DT-ELでは本節で置き換えます。以下は2026-11-08の内部設計案であり、実装済みを意味しません。

## 8B.1 一覧からの移動先

| 診断の情報 | 一覧のジャンプ操作 |
|---|---|
| 有効な`relatedElement`がある | 既存の図要素へのジャンプ・強調を使う |
| 図要素がなく、有効な`location`とソース識別がある | 読み取り専用のソース表示ビューを開き、該当行へスクロールし、列位置を示す |
| 図要素とソース位置が両方ある | 既存の図ジャンプを既定とし、同じジャンプ操作欄に「ソースへ」も提供 |
| どちらもない | 移動操作を無効にし、「移動先なし」を説明する |

古い図要素IDが無効になっていても、ソース位置が有効ならソースへ移動できます。位置情報だけの診断で、一覧に行・列を表示するだけで完了した扱いにしません。ソース表示は[[TECSCDE-DT-EL内部仕様 - 02B V0.2.0画面構成]]2B.3の`DefinitionFileView`の読み取り専用表示を共用し、位置指定付き表示を追加します。

種別・該当箇所・メッセージ・ジャンプ操作という4列表は維持します。図ジャンプには第6章の既存の検索巡回・パン・フィルタ緩和を利用し、ソースジャンプで図のフィルタや選択を変更しません。

## 8B.2 原位置と補助情報

既存の`Diagnostic.location = { file, line, column }`は、診断生成時の原値として保持します。表示のために行・列を書き換えたり、ファイル欄を現在の主ファイルで埋めたりしません。ジャンプ用に次の補助情報を関連付ける契約案とします。

```ts
interface DiagnosticSourceRef {
  readonly sourceId: string;
  readonly displayName: string;
  readonly snapshotId?: string;
  readonly absolutePath?: string;
  readonly diagnosticCwd?: string;
  readonly origin: 'file' | 'generated' | 'preprocessed' | 'memory';
  readonly capturedAt?: string;
  readonly matchesAnalyzedInput?: boolean; // 実際に解析した本文との一致を確認できた場合だけtrue
}
interface DiagnosticCoordinateKind {
  readonly lineBase: 0 | 1;
  readonly columnBase: 0 | 1;
  readonly columnUnit: 'utf8-byte' | 'utf16-code-unit' | 'unicode-code-point' | 'unknown';
}
// Diagnosticに sourceRef? と coordinateKind? を追加する契約案。
// mainから返す場合もstructured clone可能な値のみ。
```

ローダーは各入力ソースの診断を、解析したソースID・取得世代・スナップショットへ関連付けます。ビルダーの未補完の空のファイル名を、そのまま主ファイルへの移動として解釈しません。非同期の診断集約後も、元のソースとの対応を失わせません。

各producerのアダプタが、実際の位置の基数・列単位を確認して`coordinateKind`を設定します。「tree-sitterだから必ずバイト単位」「tecsgenだから必ず文字単位」と未検証で固定しません。位置の原値と、表示ビューが使う位置への変換を分離します。新規に生成する位置付き診断は、この変換情報を用意することを実装条件とします。

旧診断に情報がない場合は、生成元の位置規則を確認できるアダプタだけで補います。列単位を確定できない場合は対象行を強調し、「列位置は未確定」と原値を併記します。行の基数も確定できなければ、ソースは表示しても正確な行への移動を装いません。

## 8B.3 ソースの取得とパス解決

**診断が実際に解析した原文を保持できる場合は、そのスナップショットを優先**します。ローダー・tecsgen結果の取り込み時に、診断が参照するソース本文を`DiagnosticSourceRegistry`（案）へ登録します。これは診断世代に紐付く表示用データであり、現在の図を再serializeした本文ではありません。

本文の取得時点と、実際に解析した本文との一致確認有無を保持します。アプリ内の解析器へ直接渡した文字列、保持した生成本文、外部実行の結果取得時に通常ファイルから読み取った本文を区別します。特に、外部tecsgenが実行中に通常ファイルが変更される場合、結果取得時の読み取りだけでは一致を保証できません。一致未確認の本文には「診断取得時と異なる可能性」を表示し、保持済みというだけで正確な位置対応を保証しません。

- 通常ファイルは、元の正規化済み絶対パスと解析時本文を対応付けます。同じファイル名の別ファイルへ、basenameだけで解決しません。
- tecsgenの相対ファイル名は、**診断取得時に実際に使ったcwd**で解決します。mainは実行結果にそのコンテキストを添え、ジャンプ時のアプリcwdや新しい主ファイルの位置を使いません。Windowsのドライブ文字を含むパスを、行・列区切りのコロンと誤って分割しないことも解析条件とします。
- Plugin生成物は一時ディレクトリを削除する前に、診断対象となった本文を保持します。表示名は`plugin:`等の生成ソース用の識別名とし、一時パスを利用者の通常の定義元やセッションへ登録しません。
- 前処理後の診断は、元ソースとの位置対応が確認できる場合だけ変換します。対応がなければ実際の前処理後本文を、その種類と原位置が分かる名称で表示します。別の本文へ同じ行番号をそのまま当てません。
- 未保存・メモリ上の入力も、sourceIdと本文があれば表示できます。空のパスを現在の主ファイルと推測する必要はありません。

スナップショットがない通常ファイルだけ、mainの副作用のないテキスト読込APIを`FileGateway`経由で使います。既存APIを安全に再利用できなければ、`file:readTextForView`（案）を追加します。ファイルを図として開く・セッションへ追加するAPIとは分離します。文字コードとI/O失敗は第7章7.8の規則を使います。

ディスクの現在の本文を使った場合は「現在のファイル内容。診断取得時と異なる可能性があります」と明示します。取得時の内容と一致すると確認できなければ、診断位置の対応を保証した表示にしません。外部変更を戻したり、未保存の図を保存したりして位置を合わせません。

生成・前処理ソースのスナップショットがない場合は、「診断時の生成元ソースは利用できません」と知らせます。消えた一時パスへ再読込したり、ジャンプのためにtecsgenやプリプロセッサを再実行したりしません。

## 8B.4 読み取り専用ビューの位置表示

ビューは本文を`textContent`等で表示し、HTMLとして解釈しません。ファイル／生成ソースの表示名、取得時の本文か現在のディスク内容か、診断の原行・列を示します。行番号を表示し、対象行を見える範囲へスクロールして強調します。列変換が確定する場合はその文字位置にキャレット相当の記号または範囲強調を置きます。

ビュー用の座標へ変換する際は、改行を含む本文に対して次を検証します。

1. 原位置が有限の整数で、宣言された基数に対して有効か検証します。行の位置を決め、CRLFを二重の改行に数えません。
2. 行内の列を、指定された単位からDOMで使うUTF-16位置へ変換します。UTF-8のバイト途中やサロゲートペアの途中等、確定した文字位置へ変換できない値を正確な位置として示しません。タブの表示幅を文字数へ混ぜません。
3. 行末・EOFは境界位置として扱い、最後の改行や空行も保持します。列欠落・単位不明なら行だけを強調します。
4. 行が範囲外なら本文を表示して「診断の行が現在の本文の範囲外」と伝え、原位置を残します。最終行へ黙って丸めて移動済みとは表示しません。列だけ範囲外なら対象行を示し、列の不一致を説明します。

削除済み・アクセス拒否・復号失敗はビュー内で表示し、現在の図を保持します。表示失敗を同じ一覧へ再帰的に診断として積み上げません。関連する図要素が利用できる場合は、別の図ジャンプ操作を使えるようにします。

## 8B.5 非同期処理・寿命・非干渉

`AppShell`の`DiagnosticNavigator`（案）が一覧から移動先を解決し、ビューを開きます。要求トークンは最初のawait前に発行し、本文取得後と表示直前に最新要求かを確認します。先に押した診断Aの読み込みが後から完了しても、新しい診断Bの表示を上書きしません。診断世代・対象文書が切り替わった場合も古い要求を無効にします。

Registryは現在保持する診断と、開いているソース表示が必要とする本文だけを保持します。診断群の置き換えやビューの破棄時に不要な本文を解放し、診断世代を無制限に蓄積しません。開いているビューは、表示中の本文と位置を一組で保持します。

ソースジャンプではドキュメント、現在ファイル、dirty、Undo/Redo、図の選択・ズーム・パン・フィルタを変更しません。図要素ジャンプだけが既存規則で選択・パン等を更新します。ビュー内で本文を選択・コピーできますが、編集・保存・再解析・図への取り込みは行いません。

2B.3のプロパティから開く「定義ファイル表示」は従来どおりディスクの内容を表示します。診断からの表示は解析時本文を優先する**別の取得モード**として共通ビューへ渡し、両方の由来を取り違えません。

## 8B.6 実装時の検証条件

- `relatedElement`だけ、`location`だけ、両方、どちらもない診断で、移動操作の表示と優先順位が一致すること。
- 位置だけの診断から読み取り専用本文へ移動し、対象行・列の強調が見えること。図とdirty・履歴・現在ファイルが変わらないこと。
- 各producerのASCII・日本語・タブ・絵文字等の入力を使い、原位置の基数・単位を実測して変換すること。CRLF、空行、空ファイル、EOF、列なし、行／列範囲外も確認すること。
- 相対パスと実行時cwd、Windowsのドライブ文字、同名ファイル、空のファイル名とsourceIdを確認し、現在の主ファイルへの誤解決を防ぐこと。
- 診断後の外部変更・図の未保存変更でも解析時の本文へ移動し、スナップショットがない場合は現在内容である旨を表示すること。
- 外部tecsgen実行中に通常ファイルを変更した場合、結果取込時に読んだ本文を解析時本文と断定しないこと。取得時点・一致確認の有無と表示文言を確認すること。
- 生成一時ディレクトリの削除後も保持した本文を表示し、保持がなければ利用不能と知らせること。再生成やセッション登録を行わないこと。
- A・Bの連続ジャンプで非同期完了順が逆転してもBを維持し、診断置き換え時の古い要求・不要本文を残さないこと。
- DOM・変換・ナビゲータのテストは`tests/renderer/`、副作用のない読込のテストは`tests/main/`、実機の移動記録は`tests/verification/`に置くこと。今回は契約更新であり、実装テストの実行済み記録ではありません。
