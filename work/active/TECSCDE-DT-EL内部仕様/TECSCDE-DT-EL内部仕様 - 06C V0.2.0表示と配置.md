# 6C. V0.2.0表示と配置

[[TECSCDE-DT-EL内部仕様]]第3〜6章のV0.2.0追加・変更設計です。根拠は[[TECSCDE-DT外部仕様 - 04 コンポーネント図の表現]]4.1.x・4.9.x、[[TECSCDE-DT外部仕様 - 07 表示機能]]7.3.y・7.5.x・7.6です。新規識別子は契約案であり、V0.2.0差分の実装適合は未確認です。6Bに記録された従来版のフィルタ・色分け・スタブ・検索連携まで未実装とする意味ではありません（2026-11-08、監査#19）。

## 6C.1 状態と操作の配置

| 状態・操作 | 所有先 | 履歴・dirty | 保存 |
|---|---|---|---|
| activeの判定 | セルタイプの既存`active`指定を参照 | 表示時に変更なし | 既存CDLの意味を維持 |
| activeOnly | `DisplayFilters`の真偽値、既定false | 対象外 | 保存しない |
| 結合強調 | `AppStore`の`connectionFocusEnabled`（既定false）。強調するポートは`SelectionState`から導出し、コピーを持たない | 対象外 | 保存しない |
| リージョン矩形モード | `ViewState.regionOutlineMode`、既定false | 対象外 | `.cde`にも前回セッションにも保存しない（外部仕様4.9.x項目7） |
| activeセルの最上段への移動 | `Command`をdispatch | 1履歴、変更時dirty | 編集可能セルの位置を既存方式で保存 |

青背景はフォーカス中や選択中のセルという意味ではありません。`isActiveCell(doc, cell)`を純粋な判定として共用し、そのセルの型の`active`指定を使います。複合型の内部を展開してactiveを推定する仕様は追加しません。

表示制御バーを廃止し、既存のリージョン／ネームスペースフィルタ・色分け・シグニチャ名・セル名強調の操作をツールバー上の表示機能用コントロールへ移す設計案とします。「表示」ボタンや領域開閉機能は再導入しません。`activeOnly`もここに追加する案とし、最終的な並び・UI配置は実装前に確定します。リージョンバーと凡例は従来どおり残します。

## 6C.2 active背景と表示フィルタ

`SvgRenderer`へactive判定を渡し、背景を青色にするための描画属性を生成します。既存の編集可否・不完全・未結合との塗り／枠の優先順位は、外部仕様4.1.xで2026-11-08に決定されました。**塗りと枠を別の軸**として独立に決めます。

| 軸 | 優先順位（高 → 低） |
|---|---|
| 塗り | アクティブ（青） > 編集不可（灰） > 通常（白） |
| 枠の色と線種 | 不完全（橙の破線） > 編集不可（淡灰の実線） > 通常（濃灰の実線） |

`CellRenderer`は、セルの矩形に状態ごとの修飾クラス`active`・`readonly`・`unresolved`を**排他にせず独立に**付与します。判定は`isActiveCell(doc, cell)`と、5B.1の`deriveCellVisualState`を使います。

```css
.cell-rect            { fill: var(--cell-fill);          stroke: var(--cell-stroke); }
.cell-rect.readonly   { fill: var(--cell-fill-readonly); stroke: var(--cell-stroke-readonly); }
.cell-rect.active     { fill: var(--cell-fill-active); }                                  /* 塗りだけ */
.cell-rect.unresolved { stroke: var(--cell-stroke-warn); stroke-dasharray: 3 2; }         /* 枠だけ */
```

1. 塗りは`active`が`readonly`に勝ち、枠は`unresolved`が`readonly`に勝ちます。この優先順位はCSSの宣言順に頼らず、規則の分担（`active`は塗りだけ、`unresolved`は枠だけ）で保証します。
2. `.cell-rect.active.readonly`と`.cell-rect.active.unresolved`の明示的な規則を置き、順序の入れ替えで結果が変わらないようにします。
3. 色はCSS変数（トークン）で定義し、セル名・セルタイプ名の文字と背景のコントラスト比が4.5:1以上になることをトークンの組で検証します。青の具体的な値は実装時に決めます。
4. 未結合は塗りにも枠にも影響させず、記号Uだけで示します。選択枠・検索一致の枠・リージョンの帯・状態記号は塗りと枠の上に重ねる別の機構で、これらの有無で塗りと枠の色は変わりません。
5. 画像出力（7F、7.10.4）は、同じ状態スナップショットから解決済みの塗り・枠の色をSVGへ埋め込みます。CSSクラスの参照だけにしません。

色の合成とは独立して、[[TECSCDE-DT-EL内部仕様 - 05B 色に依存しない状態表示|5B]]のRO・!・Uを併記する契約を追加します（2026-11-07、監査#14）。activeの青背景でも各記号を識別できる背景・輪郭とし、activeと編集不可を同じ記号にしません。activeの有無は青の背景だけで示し、色以外の補助記号は設けません。色覚への配慮が必要になった場合は将来検討します（TBC）。

可視セル集合は、6Bの既存フィルタを満たすセルと、`activeOnly === false || isActiveCell(doc, cell)`を満たすセルの積集合です。モデルからセルや結合を削除しません。非表示側の結合スタブは6Bの規約に従います。検索ハイライトの描画とヒットテストは同じ可視集合を使い、見えない要素が通常のクリック対象に残らないようにします。検索リストは6B.8に従い、フィルタによらずモデル全体の結果を保持します。非activeの検索結果へジャンプする際は、既存のリージョン緩和に加えactiveOnlyを解除し、`revealed`印で知らせる設計案です。フィルタ変更だけで選択・履歴を編集しません。

## 6C.3 結合したセル群の赤色表示

外部仕様7.6で2026-11-08に決定された指定操作（トグルに追従）と探索範囲（直接の結合のみ）の内部設計は次のとおりです。

1. **状態**: `AppStore`は`connectionFocusEnabled: boolean`（既定false）だけを持ちます。強調するポートは**コピーを持たず**、描画のたびに`SelectionState`から導出します。ポートはセルID、ポートID、呼び口／受け口の別、配列要素の添字で識別し、名前だけで識別しません。古いIDが残らず、ドキュメントの差し替えやポートの削除では、導出結果が自然に空になります。
2. **導出**: `resolveHighlightedJoinIds(doc, selectedPorts): ReadonlySet<JoinId>`は純粋関数です。呼び口なら、その呼び口から出る結合を返します。受け口なら、その受け口に入るすべての結合を返します。複数のポートを選択している場合は、結果の和集合です。複合セル内部や間接結合はたどらず、推移閉包を取りません。
3. **メモ化**: 結果は、docの参照と選択の参照が同じ間は再利用します。
4. **描画**: `CanvasView.focusedJoinIds`を追加し、`JoinRenderer`は該当する可視の結合に`join-focus`クラスを付けて、線を赤にして太くします。変更検出は6Bの`regionColors`と同じく、集合の比較で行います。非表示セルを再表示せず、スタブも同じ結合IDを引き継ぎます。強調がなくなれば通常の描画属性を再計算します。
5. **UI**: 表示機能のツールバーにトグルを追加し、`aria-pressed`を同期させます。ポートの選択・ドラッグ・結合作成の入力は変更しません。結合のないポートを選択したときは、ステータス表示に「結合なし」を示します。
6. **履歴・保存**: 履歴にもdirtyにも影響させず、保存もしません。画像出力は7Fの共通スナップショットに含めます。強調色と既存の検索・選択装飾の併存は受入確認に含めます。

**代替案（不採用）**: ポートの選択だけで常に強調する案は、通常の選択の見た目と混ざるため採りません。

## 6C.4 activeセルの最上段への移動

`MoveActiveCellsToTopCommand`（案）は、指定時点で確定した対象IDと配置結果を受け取ります。対象はactiveかつ編集可能なセルです。選択状態や表示フィルタによって読み取り専用セルを移動対象に加えません。

最上段に収まらないときの扱いは、外部仕様7.3.yで2026-11-08に決定されました。内部設計は次のとおりです。

### 配置の計画

`prepareMoveActiveToTop(doc)`は副作用のない純粋な関数とします。戻り値は`ActiveTopPlan`（案）で、`orderedCellIds`・`moves`・`joinRoutes`・`topRowCellIds`・`spilledCellIds`・`precondition`を持ちます。走査は[[TECSCDE-DT-EL内部仕様 - 04G 再配置コマンド設計|4G.3]]と同じ格子（原点(10, 10) mm、横55 mm刻み、右端は用紙幅−30 mm、行送りは縦30 mm）を使います。

1. 対象は、activeかつ編集可能なセルのみとします。対象外の全セル（非active、読み取り専用、別ソース、非表示を含む）は固定の障害物とします（4G.2と同じ）。選択状態や表示フィルタで対象を増減しません。
2. 各対象を、操作開始時の`doc.cellValues()`の列挙順に、第0行（縦10 mm）の左から、**重ならない最初の候補**へ置きます。行が埋まれば次の行へ進みます。
3. **4Gのずらしフォールバック（横8 mm・縦6 mm）は使いません。** 重なりを許容する分岐を持たないよう、共通の格子走査関数に`allowOverlap: false`を指定して共用します。通常再配置のフォールバックを自動適用しません。
4. 行の走査は、用紙の高さを超える手前で打ち切ります。全対象が置ければ成功とし、1つでも置けなければ**計画全体を配置不能**として返します。部分適用、セルの縮小、用紙の変更はしません。
5. `spilledCellIds`は、第0行以外に置いた対象のIDです。空でなければ`W-ACTIVE-TOP-OVERFLOW`を1回だけ通知します。配置不能の場合は`W-ACTIVE-TOP-FAILED`を通知します（8.5）。

### コマンド

`MoveActiveCellsToTopCommand(plan)`は、`RelayoutCellsCommand`（4G.5）の適用処理を共用します。

1. 関連する結合の経路を、全対象の新位置を置いた最終モデルで再計算し、配置と経路の更新を1コマンドにまとめます。
2. `apply(doc)`は同期・副作用なしとし、前提（対象・障害物・用紙）が変わった、または対象がなくなった場合は元のdocを返します（no-op）。Undo/Redoは既存`History`の再生方式を使い、`invert()`は追加しません。1回の操作は1コマンド・1Undoです。
3. 配置不能、対象なし、または位置と経路がすべて変更なしの場合は、履歴もdirtyも変更しません。
4. 診断は、呼び出し側が計画の最終結果から一度だけ登録します。`apply()`からは追加しません。Undoで操作が外れたら該当警告を解除し、Redoで再構成します。

### 操作入口（2026-11-08 決定）

1. **ボタン**: `AppShell`のツールバーに`data-action="moveActiveToTop"`のボタン「アクティブを最上段へ」を追加します。位置は`relayoutSelected`・`relayoutAll`の直後です（4G.1と同じ並び）。メニュー項目、ショートカット、右クリックメニューは設けません。
2. **有効条件**: `canMoveActiveToTop(doc)`（純粋な判定）は、`isActiveCell(doc, cell) && cell.editable`を満たすセルが1つ以上あるときにtrueを返します。ストアの通知ごとに再評価し、`setDisabled`で反映します（`shell.ts`の既存の方式）。無効のときのツールチップに理由を示します。
3. **実行**: `runAction("moveActiveToTop")`が`prepareMoveActiveToTop(doc)`を呼びます。計画が成功なら`store.dispatch(new MoveActiveCellsToTopCommand(plan))`を実行します。計画が配置不能なら、dispatchせずに`W-ACTIVE-TOP-FAILED`を登録します。診断は呼び出し側が計画の最終結果から一度だけ登録します（8.5）。
4. **対象の選び方**: `SelectionState`と表示フィルタを読みません。対象は`doc`から導出するだけで、非表示のアクティブセルも含めます（4G.1と同じく可視性で絞らない）。
5. **ステータス表示**: 成功時にのみ、移動したセル数を示す文言を出します。選択・検索・フィルタ・ズーム・パンは変更しません（4G.5と同じ）。
6. **試験**: 有効・無効の切り替え（activeでないセルだけ、読み取り専用のactiveだけ、activeなし）、非表示のアクティブセルが対象に含まれること、選択状態が結果に影響しないこと、成功・溢れ・拒否の各結果での診断とステータス表示、1回のUndoで元に戻ることを確認します。

青色表示・activeOnlyはこの編集コマンドを呼びません。

## 6C.5 リージョン矩形モード

モデルの`RegionTree`とセルの所属を入力に、表示層で矩形集合と外周描画用の線分を導出します。セルの位置を動かしたり、矩形をCDLモデルに追加したりしません。色は6Bのリージョン色割り当てを再利用します。

アルゴリズム案は次のとおりです。

1. `computeRegionOutlines(doc, visibleCellIds, regionTree)`は純粋関数です。根を除く各リージョンRについて、**表示中で、Rの部分木（自身と子孫）に属するセル**の境界矩形（セル本体のみ。ポートやラベルは含めない）を、同一の図座標で集めます。非表示のセル（フィルタ・リージョンごとの非表示・activeOnly）は含めません。
2. 各矩形を、`margin(R) = 1 mm + 1 mm × (Rの部分木の高さ)`だけ外側へ広げます（葉のリージョンは1 mm）。これにより、親の外周は子の外周の外側に間隔をあけて位置し、祖先と子孫の線が重なりません。値は暫定で、実装時に調整できます。
3. 元の矩形は分割せず保持します。広げた矩形の和集合を、座標圧縮した格子で求めます。塗りと空きの境界の辺を取り出し、同一直線上で連続する辺を結合して、外周の線分とします。外周線分の計算上の区間分けと、元の矩形領域の分割は区別します。
4. 残った外部境界の線分だけを、6Bの`regionColorMap`の色で描画します。名前は、外周の最も左上の角に置きます。図の背景側に`region-outlines`グループ（専用SVGレイヤ）を置き、`pointer-events: none`としてセルやポートのヒットテストを遮りません。
5. 描画順は、深さの浅い順、同じ深さならリージョンIDの順です。祖先と子孫の関係にない領域の重なりも、この順で決定的に描きます。
6. 移動・追加・削除、リージョンの変更、フィルタの変更、モードの切り替え時に再計算します。入力が同じ間は結果を再利用します。

モードは`ViewState.regionOutlineMode`（既定false）で持ち、履歴にもdirtyにも影響させません。`.cde`にも前回セッションにも保存せず、起動時はオフです（外部仕様4.9.x項目7）。既存のリージョン色分け・凡例は置き換えません。画像出力には7Fの共通スナップショットでモードと線分を含めます。

## 6C.6 実装時の受入確認

- active型と非active型、選択・フォーカスの違いを判定し、既存フィルタとの積集合・結合スタブ・検索表示が一致します。
- 1対1／受け口への複数結合／配列要素／複数ポートの選択／結合のないポート／解除／ポートの削除／ドキュメントの差し替え／非表示セルとのスタブで赤色対象が正しく、複合セル内部や間接結合をたどらず、表示操作は履歴・保存内容に影響しません。トグルのオフで強調が解除され、オンのままポート以外を選択すると強調がなくなることも確認します（2026-11-08）。
- 最上段配置は読み取り専用セルを保持し、結合再計算・Undo/Redo・再生時no-opが成立します。
- 最上段への配置の容量の試験（2026-11-08追加）:
  - 全対象が第0行に収まる場合、警告が出ないこと。
  - 第0行を固定セルが塞ぐ場合に、次の行へ送られ、`W-ACTIVE-TOP-OVERFLOW`の件数が正しいこと。
  - どこにも置けない場合に、操作全体が拒否され、`W-ACTIVE-TOP-FAILED`が出て、位置・履歴・dirtyが変わらないこと。
  - 操作の結果、新しい重なりが生じないこと。
  - 読み取り専用のactiveセルが動かず、障害物として扱われること。
  - 対象の並び順が安定していること。
- 色の優先順位の試験（2026-11-08追加）: `active`×`readonly`×`unresolved`の8通りで、クラスの組と決定される塗り・枠の色を確認します。選択・検索一致・リージョンの帯を重ねても塗りと枠が変わらないことも確認します。
- 離れた矩形、重複、包含、辺の共有、角だけの接触で外部境界だけが描かれます。
- 親子リージョン（2026-11-08追加）: 親が子孫のセルを含み、余白の差で親子の線が重ならないこと、根を描かないこと、同色の親子を区別できること、祖先と子孫の関係にない領域の重なりが深さ・ID順で決定的に描かれること、非表示のセルが領域に含まれないこと、モードが`.cde`にも前回セッションにも保存されず起動時にオフであることを確認します。
- 計算とコマンドのテストは`tests/renderer/`、色とモードレス操作の確認記録は`tests/verification/`に置きます。
