# TECSCDE-DT-EL 複合セルタイプ対応案

## 位置づけ

2026-10-02に提示された対応案。**2026-10-03に方針として採用した**（ユーザー決定）。採用したのは対応の方向と下記の段階案で、段階1の「表示・編集できる範囲」は未決のまま、外部仕様で決める。現行の[[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 - 04 コンポーネント図の表現|TECSCDE-DT外部仕様第4章]]は複合セルタイプを範囲外とし、読み込み時の未対応警告を規定する。実装前に表示・編集できる範囲を外部仕様で決める必要がある。対象実装は[[work/active/TECSCDE-DT-EL実装/TECSCDE-DT-EL実装|TECSCDE-DT-EL実装]]。

## 目標と構造

複合セルタイプは、外側に通常のセルタイプと同様の受け口・呼び口・属性を持ち、内側にセル、内部結合、外部ポートとの対応を持つ。外側のセルインスタンスを図上で扱う機能と、内側を展開して閲覧・編集する機能は分けて設計する。

TECS CDLの例では、呼び口の輸出は `InnerWorker.cMotor => composite.cMotor`、受け口の輸出は `composite.eTask => InnerTask.eTask` の向きになる。属性値には `val = composite.val` のような参照もある。提示されたCDL例の構文と対象プロジェクトでの解釈は、実際のtecsgenをオラクルとして確認する。

## 現行実装の確認点

- `src/renderer/cdl/cst.ts` の `CompositeDecl` は名前だけを保持し、`document-builder.ts` は複合セルタイプごとに `W-COMPOSITE-UNSUPPORTED` を出す。namespace内の複合セルタイプも抽出経路を確認する必要がある。
- `src/renderer/model/celltype.ts` の `CelltypeRef` には外部ポート・属性の情報があるが、複合種別、内部セル、内部結合、ポート輸出の対応表はない。
- `src/renderer/cdl/serializer.ts` は元テキストを雛形にして通常のセル宣言を再生成する。複合宣言の文字列が残る場合も、意味的な保存・再読込の保証にはならない。

## 段階的な対応案

1. **仕様の境界を決める**：外側を通常セルとして表示するか、内部を展開するか、図上で新規定義や編集を許すか、未対応構文をどう示すかを外部仕様で決める。まずは外側の閲覧・通常セルとの結合を目標とし、内部の図編集は後段に置く案。
2. **構文・モデル・名前解決を拡張する**：CSTから外部インタフェース、内部セル、内部結合、ポート輸出を別々に抽出する。`CelltypeRef` へのフラグ追加だけで済ませず、複合定義とインスタンスの関係、namespace、参照先の型とポートの解決を表現する。
3. **保存と診断を保証する**：実CDLを読み込み、無編集保存と外側の編集後保存の双方で、tecsgenが解釈する複合定義・内部結合・ポート輸出が変わらないことを確認する。対応済み範囲だけ警告を解除し、未対応構文には警告を残す。単に `W-COMPOSITE-UNSUPPORTED` を消さない。
4. **UIを拡張する**：初段は複合型インスタンスを外部ポート付きのブラックボックスとして表示する。次段で内部セルと結合をサブダイアグラムに表示し、ナビゲーション、選択、編集、Undo/Redo、保存まで定義する。

## ロードマップ（Phase 1〜3）

2026-10-03に追加提示された実装順（AI の回答をそのまま記録。コード上の確認は未実施で、(inferred)）。上の「段階的な対応案」の段階2〜4を、実装の単位に切り直したもの。

| Phase | 内容 | 対応する上の段階 |
|---|---|---|
| **Phase 1** インターフェース解決 | 複合セルタイプの外部ポート（entry/call）と属性をパースして Celltype レジストリへ登録する。複合セルタイプをインスタンス化したセルが、通常のセルと同様に結合・可視化できるようにする（外枠・受け口・呼び口を持つブラックボックス表示）。`W-COMPOSITE-UNSUPPORTED` を抑止する | 段階2の一部＋段階4の初段 |
| **Phase 2** 内部構造の保持とシリアライズ | 内包セル・内部結合・ポート転送（`composite.eTask => InnerTask.eTask` など）をデータモデルとして保持し、CDL 保存時に壊さず往復（round-trip）できるようにする | 段階2の残り＋段階3 |
| **Phase 3** 階層ダイアグラム | 複合セルの内部を、サブダイアグラム（ドリルダウン）として表示・編集する（ダブルクリックや階層ナビゲーション） | 段階4の次段 |

提示された実装箇所（いずれも未確認）: 構文抽出は `src/renderer/cdl/cst.ts`、モデルは `src/renderer/model/celltype.ts`（`isComposite` フラグまたは `CompositeCelltype` 型）と `document-builder.ts`（警告生成の削除）、保存は `src/renderer/cdl/serializer.ts`。

**採用済みの原則との食い違い（要判断）**: 提示は Phase 1 で `W-COMPOSITE-UNSUPPORTED` を抑止するとしているが、Phase 2（往復の保証）より前に警告を消すと、複合定義の保存が保証されないまま「対応済み」に見える。上の段階3は「対応済みの範囲だけ警告を解除する。単に消さない」としており、Phase 1 の警告抑止は、Phase 2 の往復確認が済むまで、複合定義そのものについては警告を残すか、範囲を限定して解除するのが整合する。Phase 1 のどこまでを「対応済み」とするかは、段階1（外部仕様での範囲決定）で決める。

なお、提示の CDL 例（`composite` の記法、`composite.cMotor` の転送、`composite.eTask => InnerTask.eTask`）は、実際の tecsgen で受理されるか未確認。上の「目標と構造」の方針どおり、tecsgen をオラクルとして確認する。

## 検証条件

- 実際のtecsgenが受理する、受け口・呼び口・属性・内部結合・namespace・複合型インスタンスを含むCDLを用意する。
- 読み込み、外部ポートの型解決と結合検査、図表示、無編集保存、編集後保存、再読込を通して比較する。
- 未対応構文を含む場合は、データを保持し、対応済みと誤認させない診断を出す。
