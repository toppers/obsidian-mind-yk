## 6. 編集操作

本章は選択・移動・削除・結合の作成/削除・プロパティ編集・アンドゥ／リドゥ・クリップボード・グループ操作を規定する。現行版の事実は制御層 `cdelib/tcontrol.rb`（781行、マウス/キーボードのイベント分配とモード遷移を担う）、モデル層 `cdelib/tmodel.rb`（アンドゥ機構 `ChangeSet`/`ChangeSetManager` を含む）、パレット定義 `cdelib/palette.rb`、および未使用ダイアログ `cdelib/cell_plugin_dialog.rb` に基づく。

マウスイベントは `Control#pressed_on_canvas` / `motion_on_canvas` / `released_on_canvas` に、キーボードイベントは `Control#key_pressed` に分配される。後者は GTK から渡される keyval を **`& 0xff` でマスクして**分岐する実装になっており、本章の随所でこのマスクに起因する意図しないキー衝突が見つかる（6.1・6.2）。

### 6.1 要素の追加

#### 6.1.1 現行版の動作

パレットの「New Cell」トグルボタンでモードを `:MODE_NEW_CELL` に切り替えたのち、セルタイプ一覧（3.3）で行を選択して空白のキャンバス上を左クリックすると、`TECSModel#new_cell` がクリック位置にセルを生成する。**セルタイプ一覧で何も選択していない状態でクリックしても、エラーなく黙って何も起きない。**

セル名は `new_cell2` が自動決定する。セルタイプ名から先頭の `t` を除去し、`@cell_hash` に同名が既にあれば連番を追加する（上限なしのループ）。既定サイズは幅・高さとも下限があり（幅 20 mm・高さ 13 mm、テキスト幅に応じてさらに広がる）。

**所属リージョンはクリック位置に関わらず常にルートリージョンになる。** `TECSModel#get_region_by_location(x, y)` は座標を受け取りながら使わず、`@root_region` を返すだけの未実装スタブである（`# mikan` コメント付き。第4章までに見つかった開発中断の目印と同種）。CDL ファイルから読み込んだセルは別経路（`get_region_from_tecsgen_region`）で正しくリージョンが決まるため、この欠落はマウスで新規作成したセルにのみ影響する。

ポートはセル生成時に自動生成され、ユーザが個別に追加するものではない。ただし配列ポート（添字なし可変長）に限り、要素の挿入は可能である。ハイライト中のポートに対し **Insert キー**（Shift 併用で前挿入・単独で後挿入）を押すと `TmPortArray#insert` が挿入する。固定長配列は「Array size is fixed」のメッセージボックスで拒否される。

**キー衝突の副作用**: `key_pressed` が keyval を `& 0xff` でマスクするため、GTK の `Insert`（`0xff63`）と小文字 `c`（`0x63`）は同じマスク後の値になる。結果として、**ポートを選択した状態で `c` キーを押しても Insert と同じ挙動（配列要素の挿入）が発生する** — 意図しないキー衝突である。

#### 6.1.2 JS 版の規定

- セルタイプ未選択時のクリックは、現行版のように黙って無視せず、**ステータス表示または軽い警告でセルタイプの選択を促す**（9章）。
- 新規セルの既定所属リージョンは**ルート**とする（現行版を踏襲）。ただし現行版と異なりリージョンはクリック位置ではなく明示的な選択操作でのみ変更する — 6.5 で規定するプロパティパネルからの変更を正規の経路とし、「クリック位置から自動決定する」機能は持たない（現行版の未実装スタブを、実装するのではなく仕様として不要と位置付けて解消する）。
- セル名の自動導出（先頭 `t` 除去＋連番）は現行版を踏襲する。
- 配列ポートの要素挿入は Insert キーで提供する。**ブラウザの `KeyboardEvent.key` は名前付き文字列（`"Insert"` 等）で渡されるため、現行版のビットマスク方式に起因するキー衝突（`c` と Insert の混同）は構造的に発生しない。**
- 固定長配列への挿入拒否は現行版の挙動を踏襲し、メッセージは 9章のメッセージ形式に統一する。

### 6.2 要素の選択・移動

#### 6.2.1 現行版の動作

クリックによる選択は Shift（追加選択）・Ctrl（トグル）・修飾キーなし（単一選択に置き換え、ただし既に選択済みのオブジェクトをそのままクリックした場合は選択を維持する）の3系統。セル／結合バー（`TmJoinBar`）、呼び口、受け口はそれぞれ独立に同じ規則で選択されるが、**ポートとセル/結合バーは同時にハイライトできず、異なるセルに属するポート同士も同時にハイライトできない** — この制約に反する選択操作はまず既存の選択をリセットしてから行われる（`Hilite_objs#reset_if_ncessary`、原文ママの綴り誤りがコメントにもある）。

ドラッグ移動はマウスの移動量を **1.0 mm グリッド（`ALIGN`）にスナップ**し、グリッド未満の移動量は次のイベントまで持ち越して蓄積する。ドラッグ完了（マウスアップ）で `set_undo_point` が呼ばれるため、**1回のドラッグは移動量に関わらず1つのアンドゥ単位になる**。矢印キーでも1グリッド（1.0 mm）単位の移動ができる。

`TmJoinBar` の移動は直感に反する: バー N をドラッグすると実際には**1つ前のバー N-1 が動く**。最初のバーをドラッグした場合は呼び口自体が、最後のバーをドラッグした場合は受け口自体が動く（コード中に「1本目と最後のバーは動かせない（呼び口・受け口の移動が必要になる）」という注記がある）。

`find_near` の解決順位はポート → セル本体 → 結合バーで、**結合バーはモデル全体の全結合の中から最も近いものを探す**（キャンバス上で近くに見える他のバーより先に、遠く離れた場所にある別の結合のバーが候補になり得る）。セル・ポートが1つでも近くにあれば、バーは常にそちらに負ける。

**キー衝突の副作用（6.1 と同型）**: 矢印キーの masked keyval（`0x51`〜`0x54`）は大文字 `Q`/`R`/`S`/`T`（すなわち Shift+q/r/s/t）と一致するため、**これらのキーを押しても選択オブジェクトが1mm動く**。Home/End/PageUp/PageDown も同様に `P`/`W`/`U`/`V` と衝突するが、これらの分岐は空実装（no-op）のため実害はない。

#### 6.2.2 JS 版の規定

- 選択の Shift（追加）／Ctrl（トグル）／無修飾（置換、ただし既選択オブジェクトのクリックは維持）という規則、およびポート/セルの排他制約は現行版を踏襲する。
- ドラッグ移動のグリッドスナップ（1.0 mm）と、ドラッグ完了時に1アンドゥ単位とする粒度は現行版を踏襲する。矢印キー1回＝1グリッド移動も踏襲する。
- **結合バーの移動は現行版の「隣のバーが動く」間接性を廃止する。** ドラッグしたバー自身の位置を直接変更し、両端に接続する隣接バーの座標は直交を保つよう自動調整する（一般的な直交結線エディタの挙動）。実装都合による分かりにくさを、規定として改める。
- `find_near` のヒット優先順位（ポート＞セル＞結合バー）は踏襲するが、**結合バーの探索範囲をクリック位置から一定のピクセル半径内に限定する**（現行版のモデル全体探索を改める）。半径外では空白クリックとして扱い、近くに何もない場所でモデル中の遠い結合が意図せず選択される現行版の挙動を改善する。
- キーボードは `KeyboardEvent.key` の名前付き値（`"ArrowLeft"` 等）で判定するため、6.1 と同じ理由で現行版のビットマスク衝突（Shift+Q/R/S/T が矢印移動を誤爆する等）は構造的に発生しない。

### 6.3 要素の削除

#### 6.3.1 現行版の動作

削除はキーボードの **Delete キーのみ**で行う（メニュー・ボタンはない）。ハイライト中の全オブジェクトについて、結合バーなら所属する結合ごと、セルなら `TmCell#delete`、配列要素ポートなら `delete_hilited` を呼び、**確認ダイアログなしに即座に削除**する。

`TmCell#delete` は `is_editable?` が偽（読み込み専用ファイル由来）なら黙って何もしない。編集可能なセルは所属する呼び口・受け口・結合を先にカスケード削除してから本体を削除する。

配列ポートの削除は `TmPortArray#delete_hilited` が担い、次の2条件で拒否される（いずれもメッセージボックス表示）: **固定長配列**、および**添字 0 の要素**（「cannot delete array member with subscript==0」— 添字0の要素は理由の記載なくUIから恒久的に削除不能）。単一（非配列）ポートはセル削除に伴ってのみ消える。

結合の削除は「結合バーを選んで Delete」からしか到達できない。呼び口・受け口を直接選んで Delete しても `TmJoin#delete` は呼ばれない（`delete_hilited` は配列要素専用のため）。

**Delete キーの分岐は毎回 `set_undo_point` を無条件に呼ぶ**ため、複数オブジェクトを一括削除しても1アンドゥ単位にまとまる。

#### 6.3.2 JS 版の規定

- 削除操作は Delete キーで行い、**確認ダイアログは設けない**。6.6 で規定するアンドゥ機構が完全に機能する（現行版と異なり最初の変更からリドゥまで正しく動く）ため、確認ダイアログの代わりにアンドゥを安全網とする設計判断とする。
- カスケード削除（セル削除→所属ポート・結合も削除）と、読み込み専用オブジェクトの削除拒否は現行版を踏襲する。
- **結合の削除は結合バー・呼び口・受け口のいずれを選択していても行えるようにする。** 現行版の「バー経由でしか消せない」制約はUI上の理由が見当たらない実装都合であり、廃止する。
- 配列要素ポートの削除制約（固定長拒否）は踏襲する。**添字0の要素が削除できない制約は目的が不明なため踏襲しつつ、9章のメッセージとして「先頭要素は削除できません」と明示し、黙って拒否しない**（現行版もメッセージボックスは出すため実質的な挙動は踏襲）。
- 一括削除を1アンドゥ単位にまとめる粒度は現行版を踏襲する。

### 6.4 結合の作成・削除

#### 6.4.1 現行版の動作

結合されていない呼び口を（Shift/Ctrl なしで）クリックすると `:SM_JOINING` に入る。**既に結合済みの呼び口をクリックすると「既存の結合を先に削除せよ」というメッセージボックスが出て、結合モードには入らない**（Shift クリックでハイライトのみは可能）。これは呼び口が結合を最大1本しか持てないという制約（`TmCPort` の `@join` は単一値）の直接の帰結。

結合モード中、シグニチャが一致する受け口の上にカーソルを合わせると `CURSOR_JOIN_OK` に変わる（3.7 で規定済み）が、**ドラッグ中に仮の結線（ラバーバンド線）は描画されない** — カーソル形状のみが唯一のフィードバックである。マッチする受け口の上でマウスを離すと `TECSModel#new_join` が結合を生成する。それ以外の場所（空白・不一致ポート・セル）で離すと**エラーメッセージなしに黙って結合作成をキャンセル**する。

受け口は呼び口と非対称に**複数の結合を持てる**（`@joins` は配列）。結合の折れ線ジオメトリは呼び口・受け口の辺の位置関係で3パターン（`create_bars_a`/`create_bars_c`/`create_bars_e`、それぞれ5本・4本・5本のバー）に自動生成される。

結合の削除は 6.3 のとおり結合バー経由に限られ、`is_editable?` が偽なら黙って拒否される。

#### 6.4.2 JS 版の規定

- 呼び口1本につき結合1本まで、受け口は複数結合可、という非対称な制約は 4.3/4.4 で規定済みの内容と同一であり、本章でも踏襲する。
- **結合済みの呼び口をクリックした場合の挙動は現行版を踏襲する**（メッセージで案内し、Shift クリックでのハイライトのみ許可）。
- **ドラッグ中は仮の結線（プレビュー線）を描画する。** 現行版のカーソルのみのフィードバックは、結合が長距離になる図では操作の予測がしづらい。SVG 上に破線などで暫定経路を描き、3.7 のカーソル4状態と併用する。
- マッチしない場所でのドロップは現行版と同じく**エラーを出さず静かにキャンセル**する（誤操作のたびに警告を出すのは煩雑なため、直前の項で規定したドラッグ中の視覚フィードバックで十分と判断する）。
- 結合ジオメトリの自動生成（直交する水平・垂直バーの組み合わせ）は 4.6 の規定に従う。
- **結合の削除は結合バー・呼び口・受け口のいずれの選択からも行えるようにする**（6.3.2 と同一の改善）。
