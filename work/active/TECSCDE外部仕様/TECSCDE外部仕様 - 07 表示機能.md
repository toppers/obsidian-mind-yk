## 7. 表示機能

本章は表示制御バー（3.1.2 で位置を規定済み）とナビゲータ（3.5 で位置のみ規定済み）が担う、図の見え方に関する機能を規定する。現行版の事実は描画層 `cdelib/tview.rb` の表示制御バー実装（408〜449行）・`Gtk::ScrolledWindow`（244〜255行・322行）、モデル層 `cdelib/tmodel.rb` の `ALIGN` 定数・`TECSModel.round_length_val`（244行・425〜430行）、および読み込み時のフォールバック配置（`cdelib/saveload.rb`、5.3.1 で既述）に基づく。検索機能・表示フィルタ（7.4・7.5）に対応する実装は `cdelib` 全9ファイルのどこにも存在せず、本仕様で新規に規定する。

### 7.1 ズーム・パン

#### 7.1.1 現行版の動作

表示倍率は表示制御バーの `HScale` 1つに集約されている（3.1.1 で規定済み）。

| 項目 | 値 |
|---|---|
| 範囲 | `ScaleValMin` = 5（%）〜 `ScaleValMax` = 200（%） |
| 既定値 | `ScaleValIni` = 100（%） |
| 刻み | 整数（`set_digits 0`） |
| 変更契機 | スライダのドラッグのみ。`"value-changed"` シグナルで `resize_canvas` → `paint_canvas` を呼ぶ |

パン（表示位置の移動）は、キャンバスを `add_with_viewport` で内包する `Gtk::ScrolledWindow` の水平・垂直スクロールバーに完全に委ねられている。パン専用の操作（スペースキー＋ドラッグ、中クリックドラッグ等）は実装されていない。マウスホイールでのスクロールは GTK の既定動作に依存し、コード中に明示的なホイールハンドラは存在しない。

倍率変更時の `resize_canvas` はキャンバスウィジェットの `set_size_request` を呼び直すのみで、スクロール位置（`Gtk::Adjustment`）を明示的に調整する処理を持たない。ウィジェットの原点（左上）を基準にサイズが変わるため、**倍率を変えると表示中に見えていた図の部分は保たれず、左上を基準にずれる**。3.2.3 が JS 版の要件として「表示倍率の変更時は…スクロール位置を保つ」と定めているのは、この現行版の欠落を指す。

ナビゲータ（図全体の縮小表示）に相当する機能は存在しない。3.5 で述べたとおり、既定用紙サイズ（A3横）が既定倍率（100%）で表示領域に収まらないことへの対応は、現行版では持たれていない。

キーボードによる倍率変更（+/−キー等）は `tcontrol.rb` に対応する分岐がなく、存在しない。

#### 7.1.2 JS 版の規定

- スライダの範囲・既定値・整数刻みは 3.2.1 で規定済みの内容（5%〜200%、既定100%）をそのまま用いる。
- **倍率変更時は、変更前に表示領域の中央にあったモデル座標（mm）を、変更後も表示領域の中央に保つ。** 現行版の「左上基準でずれる」動作を改める。これが 3.2.3 の「スクロール位置を保つ」の具体的な意味である。
- マウスホイールによるズーム（Ctrl+ホイール）を新規に追加する。ポインタ位置のモデル座標を固定点とし、その点が画面上で動かないように倍率とスクロール位置を同時に更新する。現行版にない機能だが、SVG ベースの図編集ツールとして標準的に期待される操作であるため新規要件とする（6.6 でのアンドゥ・リドゥへのショートカット追加と同じ判断）。
- キーボードショートカット（Ctrl+ / Ctrl− / Ctrl+0）を追加する。Ctrl+0 は既定倍率（100%）へのリセットとする。
- パンは、3.1.2 で規定した各領域内のブラウザ標準スクロールに加え、**スペースキーを押しながらのドラッグ**によるパンを追加する。3.1.2 でキャンバス以外の領域（セルタイプ一覧・プロパティ）を新設したことで、現行版のメインウィンドウ全体に比べてキャンバスの表示領域が相対的に狭くなるため、スクロールバー操作だけに頼らない手段を補う。
- ナビゲータ（3.5）は次のとおり動作する。
  - キャンバス領域の隅に、用紙全体を縮小表示する。
  - 現在の表示範囲を示す矩形をナビゲータ上に重ねる。
  - ナビゲータ上のクリックまたはドラッグで、対応するモデル座標を表示範囲の中央に移動する。
  - 用紙全体が表示範囲に収まる程度まで縮小表示している間は、ナビゲータの矩形と用紙の外形がほぼ一致し実利が薄いため、自動的に非表示としてよい。3.5 で規定した「表示／非表示を切り替えられる」は、この自動判定を利用者が上書きするための手段として用いる。

### 7.2 グリッド・スナップ

#### 7.2.1 現行版の動作

グリッド単位は `ALIGN = 1.0`（mm）で固定されたクラス定数であり、`TECSModel.get_alignment` が返す値を変更する setter や UI は存在しない。

セル・ポートの位置や大きさに関わる値は、生成時・移動時に `TECSModel.round_length_val` を通して例外なく `ALIGN` の倍数に丸められる（`TmCell#initialize`・`TmCell#move`・`TmPort#move` 等、6.2.1 で言及した移動処理を含む）。

**グリッド線はキャンバス上に描画されない。** `tview.rb` の描画処理（`paint_canvas`・`drawCell`・`clearCanvasPixmap` を含む全体）にグリッド線の描画に相当するコードは存在しない。1.0 mm という単位は、セルの既定サイズ（25 × 15 mm、4.1.1）に対して十分に細かく、視覚的な整列補助というよりは**浮動小数点の座標ドリフトを防ぐための丸め処理**として機能している。

現行版にはステータスバー自体がない（3.1.1）ため、ドラッグ中の正確な座標を数値で確認する手段もない。利用者がグリッドへの整列を意識する手段は事実上存在しない。

#### 7.2.2 JS 版の規定

- **グリッド単位は現行版と同じ 1.0 mm を維持し、変更不可とする。** 5.5 の「保守的な復元」が座標の許容誤差判定を前提にしており、単位を可変にすると既存の `.cde` ファイルとの座標互換性の保証が複雑になるため、変更対象としない。
- スナップ処理（丸め）自体は現行版と同じく常時有効とし、利用者が無効化できるオプションにはしない。
- **グリッド線の表示は新規に追加する。** 表示制御バー（3.1.2）にグリッド表示の切り替えを設け、既定は非表示（現行版と同じ見た目を既定とする）とする。現行版にはこの視覚的な補助が一切なく、整列の確認手段が実質的になかったため、要望に応じて可視化できる手段を用意する。
- ドラッグ中の現在座標（mm）を 3.1.2 のステータス表示に常時示す。現行版がグリッド線も座標表示も持たなかったことへの対応であり、いずれか一方ではなく両方を提供する。

### 7.3 自動レイアウト

#### 7.3.1 現行版の動作

**利用者が任意のタイミングで起動できる自動配置・整列機能は存在しない。** パレット（3.3.1）の6フレームに該当するボタンはなく、`tcontrol.rb` にも対応するキー割り当てはない。

自動的な配置が行われるのはただ1箇所、CDL/CDE 読み込み時に**レイアウト情報を持たないセル**への一度限りのフォールバックである（5.3.1 で規定済み）。起点 (10, 10) から X 方向へ 55 mm 刻みに並べ、用紙幅 − 30 mm を超えたら Y を 30 mm 進めて X を戻す、重なりを許した巻き戻し配置である。この処理は読み込みの瞬間にのみ働き、読み込み後に利用者が再実行する経路はない。

結合の経路（4.6・6.4）も生成時に自動計算されるが、**既存のセル矩形を避ける処理を持たない**（4.6.2 で既述）。セルの上を結合線が横切ることは現行版で普通に起こる。

> [!info] 第4章の記載との整合
> [[#4.6 結合（Join）|4.6.2]] は結合経路の自動生成について「将来の自動レイアウト（7.3）で扱う」と保留していた。本節 7.3.2 がその内容にあたる。

#### 7.3.2 JS 版の規定

- **読み込み時のフォールバック配置**は現行版のアルゴリズム（起点・刻み・巻き戻し）をそのまま踏襲する（5.3.2・5.5.2 で規定済みの内容と同一）。
- **複数セル選択時の整列操作を新規に追加する。** 「上端をそろえる」「左端をそろえる」の2種を提供し、基準は選択順で最初に選択したセルの位置とする。グリッドへの丸め（7.2）は整列後の位置にもそのまま適用される。
- **結合経路の障害物回避を軽量な範囲で追加する。** 4.6.2 の保留に対する回答として、結合の経路を生成・再計算する際、始点・終点間に他のセルの矩形と重なる候補経路と重ならない候補経路の両方が存在する場合は、重ならない経路を優先する。すべての交差を除去する保証は行わない（一般のグラフ描画における経路探索問題であり、本仕様の範囲を超える）。既存の折れ線パターン（`HBar`／`VBar` のみで構成する制約、4.6.2）の範囲内で選べる候補に限定する。
- **図全体を対象にした自動レイアウト（力学的レイアウトや交差最小化アルゴリズムなど）は本仕様の範囲外とする。** 4.7.2（複合セルタイプ）と同じ理由による — セルの配置は利用者の意図（リージョンやレビューのための並び）を反映するものであり、アルゴリズムによる一括再配置は既存の配置を破壊しうるため、採否には別途の検討を要する。

### 7.4 検索・ハイライト

#### 7.4.1 現行版の動作

**検索機能は存在しない。** 名前によるセルの検索、フィルタ、ジャンプのいずれも実装されていない（`cdelib` 全9ファイルに `search` に相当する語は一切現れない）。

名前が近い機能として「Emphasize Cell Name」トグル（3.1.1 の表示制御バー、`tview.rb` 408〜414行・527〜540行）があるが、これは**全セルに対して一律にかかる表示モード**であり、特定のセルを指定してハイライトするものではない。オンにするとセル名を大きいフォント（`CELL_NAME_L`）で表示し、幅が足りなければ2行に折り返したうえでセルタイプ名は表示しなくなる。オフの既定状態ではセル名・セルタイプ名を通常フォントで2段に表示する。すなわちこのトグルは検索の代替にはならない。

もう一つ名前が近い `find_near`（6.2.1）はマウス位置からオブジェクトを解決する空間的なヒットテストであり、名前文字列による検索ではない。

#### 7.4.2 JS 版の規定

- **セル名強調表示（Emphasize Cell Name）は JS 版でも維持する。** 表示制御バーのトグルとして提供し、オンでセル名を大きく表示しセルタイプ名を隠す、オフで両方を通常表示する現行版の挙動を踏襲する。ただし以下に規定する検索ハイライトとは独立した機構とし、両者は同時にオンにできる。

現行版に検索の前例がないため、以下は新規要件として規定する（6.7・6.8 と同じ位置付け）。

- ツールバー（3.1.2）に検索ボックスを設ける。検索対象はセル名・セルタイプ名・シグニチャ名（4.5 の結合ラベル）とする。
- 一致したセル・結合は強調表示する。**この強調表示は選択状態の二重矩形（4.1.1・4.1.2）とは異なる視覚表現とする。** 検索を行っている間に別のオブジェクトが選択されている状態を区別できるようにするためである。
- 「次を検索」「前を検索」で一致箇所を巡回し、対象が現在の表示範囲外にあれば 7.1 のパン操作で表示範囲に収める。
- 一致件数を検索ボックス付近に数値で示す。0件のときはその旨を示し、エラーとしては扱わない（9章の対象としない — モデルの不整合ではなく検索条件との不一致であるため）。
- **検索は 7.5 の表示フィルタの状態に関わらずモデル全体を対象とする。** フィルタで非表示になっている要素が一致した場合、その要素を含むよう表示フィルタを一時的に緩めたうえで強調表示する。検索条件を変えるたびにフィルタを操作させるのは煩雑なため、検索を優先する。
- Esc キーで検索の強調表示を解除する。

### 7.5 表示フィルタ（ネームスペース・リージョン単位）

#### 7.5.1 現行版の動作

**現行版に「表示フィルタ」— 特定のリージョンやネームスペースのセルを非表示にする機能 — は存在しない。すべてのセルは常に描画される。**

リージョンに関連する唯一の表示切り替えは「Color by Region」チェックボックス（`tview.rb` 415〜424行）であり、これは非表示ではなく**塗り分けの基準を切り替えるだけ**である。塗り分けの実体は `get_cell_paint_color`（`tview.rb` 1186〜1214行）が担う。

| チェックボックスの状態 | 塗り分けの基準 |
|---|---|
| オフ（既定） | セルを定義した**ファイル**単位。ただし編集可能なセル（`.cde` 側で新規作成されたセル）は `is_editable?` が真であれば常に固定色（`Color_editable_cell`）になる |
| オン | セルの所属**リージョン**単位。編集可否による分岐はなく、編集可能なセルも所属リージョンの色で塗られる |

色の割り当ては固定パレット（`@@cell_paint_colors`）を先着順に消費するだけで、利用者が色を指定する手段はない。ボタンのラベルは常に `"Color by Region"` のままで、オン時に `"Color by File"` へ切り替える処理はコメントアウトされている（421行）ため、**オフ状態が実際には「ファイル単位の色分け」であることはラベルからは分からない**。

ネームスペース単位の表示切り替えは存在しない（4.8.1 のとおりネームスペースはリージョンに統合された概念であり、リージョン以外の切り口を持たない）。

シグニチャ名（4.5）の表示・非表示を切り替える手段もない。`drawJoin`（`tview.rb` 719〜768行）は、該当する結合が受け口側の最初の結合であり、かつ配列添字が0または無添字の場合に**常に**ラベルを描く。利用者が消す方法はない。

`TmRegion#get_color` は中身のない空スタブ（`tmodel.rb` 1042行、4.9.1 で既述）であり、リージョンに利用者が色を割り当てる経路は現行版のどこにもない。色は上記の自動割り当てが全てである。

#### 7.5.2 JS 版の規定

表示制御バー（3.1.2）に、次の独立した3種の表示切り替えを設ける。

| 切り替え | 内容 | 現行版との関係 |
|---|---|---|
| リージョン／ネームスペースフィルタ | 4.9 のリージョン木構造を一覧表示し、チェックを外したリージョンに属するセルを**非表示**にする | 新規。現行版は色分けのみで非表示機能を持たない |
| 色分け表示 | リージョンごとに色分けする。オン／オフを切り替え可能とする | 4.9.2 で規定済みの内容を本節で具体化。ファイル単位の色分けは廃止する（後述） |
| シグニチャ名表示 | 結合ラベルの表示・非表示を切り替える | 4.5.2 で予告済みの内容を本節で規定する。既定はオン（現行版の常時表示を踏襲） |

- **ネームスペース単位のフィルタは、リージョンフィルタと同じ機構で提供する。** 4.8.1 のとおりネームスペースはリージョン識別子（`::` 区切り）そのものであるため、リージョン木の各ノードがネームスペースの階層と一致する。独立した2つ目の UI は設けない。
- **フィルタで非表示にしたリージョンに属するセルへの結合は、黙って消さない。** 一端が非表示、もう一端が表示中の結合は、非表示側の境界でスタブ（途切れの記号）を付けて描画し、表示中のセルが実際には結合を持っていることを示す。両端が非表示の結合のみ完全に非表示とする。4.3.2 で require 呼び口の不可視化に警告表示を課したのと同じ理由（黙って消える表示は利用者に誤解を与える）による。
- **ファイル単位の色分けモードは廃止する。** 現行版のオフ状態が実質的にファイル単位の色分けだった（かつラベルにその説明がなかった）こと自体が分かりにくさの原因であり、JS 版では「色分けなし」と「リージョンで色分け」の2状態のみとし、ファイルという第三の切り口は表示フィルタ（リージョン／ネームスペース）でカバーされるため設けない。
- 色分け表示をオンにした場合は、4.9.2 の規定のとおりリージョン名の凡例を併せて表示する。色の値は実装に委ねるが、割り当ての再現性（同じリージョンには常に同じ色）を要件とする。
- 表示フィルタの状態はモデルの一部ではなく画面表示のみに関わる状態であるため、5.1 の `.cde` 形式には含めない。保存・読み込みの対象外とする。
