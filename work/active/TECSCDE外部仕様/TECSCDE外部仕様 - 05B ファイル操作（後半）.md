## 5. ファイル操作

### 5.4 保存・名前を付けて保存

#### 5.4.1 現行版の動作

パレットの save ボタンは `@model.save(@model.get_file_editing)` を呼ぶ。すなわち**編集中のファイルへの上書き保存のみ**である。

- 保存先を選ぶ操作がない（「名前を付けて保存」は存在しない）
- 上書きの確認がない
- 保存前に作業ディレクトリを `$run_dir` へ変更する（`Dir.chdir $run_dir`）ため、相対パスの解釈が起動時のディレクトリに固定される
- 書き込みは通常の `open(fname, "w")` であり、一時ファイルを経由しない。**書き込み中に失敗すると元のファイルが壊れる**
- 失敗時はメッセージボックスで通知する（`fail to save …`）

書き出す対象は**編集可能なセルのみ**である（`save_cells` の `if ! cell.is_editable? then next`）。取り込み元のファイルで定義されたセルは再出力されず、`__tool_info__("tecsgen")` の `direct_import` に取り込み指示として記録されることで整合が保たれる。

#### 5.4.2 JS 版の規定

保存操作を次の2つに分ける。

| 操作 | 動作 |
|---|---|
| 保存 | 直近の保存先が分かっていればそこへ書き戻す。分からなければ「名前を付けて保存」と同じ動作にフォールバックする |
| 名前を付けて保存 | 保存先を指定してダウンロードする |

ブラウザ単体構成では、**アプリケーションが任意のパスへ黙って書き込むことはできない**（2.3）。したがって「上書き保存」は現行版と同じ意味では実現できない。実装が File System Access API を利用できる場合は取得済みのファイルハンドルへの書き戻しとして上書きを実現してよいが、**本仕様はそれを前提としない**。利用できない場合はダウンロードとして扱い、同名ファイルの重複はブラウザの規則に委ねる。

現行版から改める点は次の2つである。

- **保存先を選べるようにする。** 現行版に「名前を付けて保存」が無いことは、図を別名で派生させる作業を CDL の手動コピーに追いやっている。
- **書き込みの失敗で既存データを失わない。** ダウンロードは既存ファイルをその場で置き換えないため、この性質は構成から自然に得られる。File System Access API を用いる実装でも、書き込み完了まで既存の内容を破棄しないこと。

用紙の既定値は A4 横（内容領域 277 × 190 mm）とする。5.1 の形式に記録される用紙情報は 5.6.1 に述べる制約を持つため、既定値の選択は現行版に合わせる。

### 5.5 レイアウト情報の復元

#### 5.5.1 現行版の動作

`__tool_info__("tecscde")` の JSON は、読み込み時にスキーマ検証を受ける（`TECSModel#validate`、スキーマ定義は `saveload.rb` の `@@TECSCDE_schema`）。検証を通らない場合は `validate error in __tool_info__("tecscde")` を報告し、**レイアウト情報を適用しない**（グローバル変数 `$b_force_apply_tool_info` で強制適用も可能）。この場合、図は 5.3.1 の自動配置のまま表示される。

スキーマは3つの情報を定義する。

| キー | 内容 |
|---|---|
| `paper` | 用紙の大きさ（`"A4"` / `"A3"` / `"A2"`）と向き |
| `cell_list` | セルごとの `location`（`[x, y, w, h]`、mm）・所属リージョン・ポート位置（辺と辺上のオフセット、mm。配列ポートは添字つき） |
| `join_list` | 結合ごとの呼び口側・受け口側の特定情報と、経路を構成する `bar_list`（`HBar` / `VBar` と位置） |

スキーマ定義では、キー名の先頭に `__` を付けた別エントリ（`:__tecscde`・`:__port_location`・`:__join_location`）で**省略可能な項目**を表している。配列ポートの添字や用紙情報がこれにあたる。

注目すべきは**結合経路の復元が保守的**である点である。`set_join_location_from_tecsgen` は、次の条件をすべて満たす場合にのみ保存された経路を適用する。

1. 経路を構成するバーが2本以上ある
2. 最初のバーの向きが、呼び口が接する辺の向きと直交している
3. 最後の2本のバーの位置が、受け口の実際の位置と許容誤差（`MAX_ERROR_IN_NOR` / `MAX_ERROR_IN_TAN`）の範囲で一致する

条件を満たさない場合は保存された経路を**黙って捨て**、自動計算された経路のままとする。これは、セルやポートの位置が図の側で変わった結果として保存済みの経路が破綻している場合に、破綻した線を復元するよりも引き直したほうが良いという判断である。CDL を手で編集した場合にも同じ経路をたどる。

#### 5.5.2 JS 版の規定

**保守的な復元という設計方針を引き継ぐ。** 保存されたレイアウトは「復元できるなら復元する、整合しないなら捨てて引き直す」ものとして扱い、整合しない情報を無理に反映しない。座標情報は図の見た目に関する補助情報であり、CDL の意味論（どのセルがどう結合されているか）より優先度が低いためである。

現行版から改める点は次の3つである。

- **捨てたことを利用者に伝える。** 現行版は経路を捨てても何も表示しないため、「保存したはずの配置が戻らない」という現象の原因が利用者から見えない。JS 版は破棄した対象の件数を警告として提示する（9章）。
- **スキーマ検証の失敗を全か無かにしない。** 現行版は検証に失敗するとレイアウト情報を全件破棄する。JS 版は `cell_list` と `join_list` を**要素単位で検証**し、妥当な要素は適用する。1セルの座標の誤りで図全体の配置が失われることを避ける。
- **未知のキーを保持する。** 検証で未知のキーを見つけた場合、拒否せず保持して書き戻す（5.1.2 の方針と同じ）。

許容誤差の具体値は実装が定めてよいが、現行版と同様に「ポート位置との一致判定」に用いる誤差であり、利用者が図を操作した結果の微小なずれを吸収する目的に限る。

### 5.6 エクスポート

#### 5.6.1 現行版の動作

**エクスポートできる形式は PDF のみである。** SVG・PNG への出力は実装されていない（`cdelib/` 全体で `PNGSurface`・`SVGSurface` の出現はなく、`Cairo::PDFSurface` のみが使われる）。

パレットの export ボタンは `MainView#export` を呼び、次のように動作する。

- 出力ファイル名は編集中のファイル名の `.cde` を `.pdf` に置換して**自動的に決める**。保存先を選ぶ操作はない
- **出力先に既存のファイルがあれば先に削除する**（`File.unlink`）。そのうえで PDF を生成するため、生成に失敗すると既存の PDF は失われる
- 用紙は `__tool_info__` に記録された用紙設定を用い、四辺に 10 mm（`PAPER_MARGIN`）の余白を取る
- 内容は余白の内側に**クリップされる**。図が用紙に収まらない場合、はみ出した部分は出力されない（縮小して収める処理はない）
- 用紙の右下に編集中のファイル名を、内容の外周に矩形の枠線を描く
- 出力中は表示倍率を PDF 用（72 DPI 基準。画面は 96 DPI）へ一時的に切り替え、終了後に元へ戻して再描画する

用紙設定には**スキーマと実装の食い違い**がある。`@@TECSCDE_schema` は `orientation` の値として `"LANDSCAPE"` と `"PORTRAIT"` を挙げているが、`tmodel.rb` の `Paper` 定数に定義されているのは `A4L`・`A3L`・`A2L` の**横向き3種のみ**である。縦向きを指定した CDL を読み込んでも一致する用紙が見つからず、`set_paper_from_tecsgen` は既定値を保ったまま黙って処理を続ける。すなわち**縦向きはスキーマ上は表現できるが、実装では選択できない**。

これは第3章の「glade に定義されているが起動されないダイアログ」、第4章の「言語には存在するが TECSCDE には無い複合セルタイプ」と同じ、**記述と実装の乖離**の3例目である。

#### 5.6.2 JS 版の規定

エクスポート形式を次のとおり定める。

| 形式 | 対応 | 備考 |
|---|---|---|
| SVG | **対応する（第一の形式）** | 2.3 により描画自体が SVG であるため、表示中の内容をほぼそのまま出力できる |
| PNG | 対応する | SVG を経由してラスタライズする。出力倍率を指定できるようにする |
| PDF | **本仕様の範囲では対応しない** | ブラウザ単体で PDF を生成するには外部ライブラリが必要である。2.2 が唯一の外部依存として認めるのは CDL 解析系のみであり（2026-09-13 改訂）、描画・出力系のライブラリ追加はこの例外に含まれない |

PDF は現行版が唯一持っていた形式であるため、対応しないことは機能の後退にあたる。ただし**印刷経由での PDF 出力はブラウザの標準機能として利用できる**ため、用途としては代替される。JS 版は印刷時に図全体が1ページに収まる印刷用スタイルを提供することでこれに応える。

現行版から改める点は次の3つである。

- **出力範囲を選べるようにする。** 用紙固定・はみ出し切り捨てではなく、「用紙に合わせる」と「図の内容に合わせる」を選択できるものとする。現行版のクリップは、図が育ったときに黙って一部を失う挙動になっている。
- **出力先を選べるようにする。** 現行版のファイル名自動決定は、既存ファイルの削除と組み合わさって意図しない上書きを起こしうる。
- **用紙の向きを縦にも対応させる。** スキーマが `"PORTRAIT"` を規定している以上、読み込んだ値を実装が扱えないという状態を解消する。

### 5.7 終了時の扱い

#### 5.7.1 現行版の動作

パレットの quit ボタンは `Gtk.main_quit` を呼ぶだけである。**未保存の変更があっても確認しない。**

現行版は変更の有無を示すフラグ自体を持たない。`tmodel.rb` の `modified` は名前に反して「変更を undo 用の変更集合に記録する」ためのメソッドであり（`add_change_set` を呼んでから処理を実行する）、保存済みかどうかの状態管理には使われていない。ウィンドウタイトルにも変更を示す表示はない（3.1.1）。

#### 5.7.2 JS 版の規定

**未保存の変更がある状態でページを離れようとした場合、確認を求める。** 実現手段はブラウザの標準機能（`beforeunload`）とする。

そのために JS 版は**未保存状態を保持する**。具体的には、保存操作の完了時点を基準とし、以降に図を変更する操作が行われたかどうかを保持する。この状態は次の3つに反映する。

| 反映先 | 内容 |
|---|---|
| ステータス表示（3.1.2） | 未保存である旨を文字で示す |
| ページタイトル | 未保存を示す接頭辞を付ける |
| 新規作成・読み込み | 実行前に破棄の確認を求める（5.2.2・5.3.2） |

現行版がこれを持たないことは、GUI ツールとしては欠落だが、致命的にはなりにくかった。図の情報が編集対象の CDL に同居しており（5.1.1）、コンソールから起動する使い方では作業内容が手元のファイルとして残るためである。JS 版はブラウザのタブを閉じるだけで状態が消えるため、**同じ欠落がそのまま作業の消失につながる**。この差を根拠に、未保存状態の管理を JS 版の要件とする。
