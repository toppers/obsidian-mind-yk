## 5. ファイル操作

本章は第2章 2.3 で導いた制約（ファイル入出力はブラウザの許可範囲に限られる）が最も直接に効く章である。同時に、現行版と JS 版の差が全章中で最も大きい章でもある。現行版のファイル操作は tecsgen に強く依存しており、その依存を外すことが JS 版の設計上の中心的な課題になる。

本章の現行版の事実は保存・読み込み層 `cdelib/saveload.rb`（26.5 KB）、制御層 `cdelib/tcontrol.rb`、描画層 `cdelib/tview.rb` の `export`、およびパレット定義 `cdelib/palette.rb` に基づく。

> [!important] 目次案からの構成変更
> 本章は当初の目次案（5.1 新規作成／5.2 開く／5.3 保存・名前を付けて保存／5.4 CDL エクスポート／5.5 画像エクスポート）から構成を変えている。理由は 5.1 で述べるとおり、**現行版には「ネイティブ保存形式」と「CDL エクスポート」の区別が存在しない**ことが判明したためである。目次案が想定していた `.tcd` というネイティブ形式は実在しない。あわせて、レイアウト情報の復元（5.5）と終了時の扱い（5.7）を独立させた。

### 5.1 ファイル形式

#### 5.1.1 現行版の形式

**保存形式は `.cde` の1種類のみであり、その中身は CDL ファイルそのものである。**

これは本章で最も重要な事実である。`TECSModel#save` が出力するファイルは、次の3ブロックをこの順に連結したものである（`saveload.rb` の `save` → `save_tecsgen` / `save_cells` / `save_info`）。

| ブロック | 出力メソッド | 内容 |
|---|---|---|
| ① `__tool_info__("tecsgen")` | `save_tecsgen` | tecscde 版数・cde 形式版数・保存日時、および tecsgen の再実行に必要な情報（`base_dir`・`define_macro`・`import_path`・`direct_import`・`cpp`） |
| ② セル定義 | `save_cells` | `cell <セルタイプのネームスペースパス> <セル名> { … }` — 呼び口の結合と属性値。**通常の CDL 構文** |
| ③ `__tool_info__("tecscde")` | `save_info` | 用紙・セル配置・結合経路の座標情報を JSON で記述 |

`__tool_info__` は tecsgen が受理する構文であり、tecsgen は自分に向けられていないツール名のブロックを読み飛ばす。したがって **`.cde` はそのまま tecsgen に入力できる CDL ファイル**である。拡張子が `.cdl` でないのは、編集対象であることを示す慣習にすぎない。

この設計の帰結として、次が成り立つ。

- **「保存」と「CDL エクスポート」は同一の操作である。** 別々の機能として存在しない。
- **図の情報は CDL の中に同居する。** 別ファイルのサイドカーではないため、CDL を渡せばレイアウトも一緒に渡る。
- **CDL を手で編集しても図の情報は失われない**（`__tool_info__` ブロックを壊さない限り）。`save_info` が出力するコメントヘッダに「詳しくない場合は触らないこと」と明記されているのはこのためである。

形式の版数は `cdelib/version.rb` で管理され、V0.5.1 時点で `$tecscde_version = "0.5.1.0"`・`$cde_format_version = "0.5.0.0"` と、**ツール版数と形式版数が別立て**になっている。

#### 5.1.2 JS 版の規定

**現行版の `.cde` 形式を JS 版の入出力形式としてそのまま採用する。** 独自のネイティブ形式（目次案の `.tcd` にあたるもの）は定義しない。

理由は3つある。

1. 形式が CDL である以上、独自形式を作れば tecsgen との往復のたびに変換が必要になり、2.3 の「tecsgen を直接起動できない」という制約と組み合わさって手数が増える。
2. 現行版で作成した図を JS 版で開けることが移行の前提であり、読み込み互換を持つなら書き出しも同じ形式にするのが素直である。
3. レイアウトが CDL に同居する設計は、ファイルを1つだけ受け渡せばよいという点でブラウザ単体構成と相性がよい。ブラウザからは複数ファイルの同時保存が扱いにくいためである。

ただし次の2点を JS 版の規定として追加する。

- `__tool_info__("tecsgen")` の `base_dir`・`import_path`・`cpp` は**ローカルの絶対パスやコマンド名を含む**。ブラウザからはこれらを解決できないため、JS 版は**読み込み時にこれらを解釈せず、保持して書き戻すだけ**とする（往復で失わないことを保証する）。tecsgen 実行時にこの情報を使うのは利用者の環境であり、JS 版ではない。
- `cde_format_version` を読み込み時に確認し、JS 版が想定する版数より新しい場合は警告を提示したうえで読み込みを続行する（9章）。拒否はしない。未知の情報を保持して書き戻す方針と整合させる。

### 5.2 新規作成

#### 5.2.1 現行版の動作

**新規作成の機能は存在しない。** パレットの File フレームにあるボタンは save・export・quit の3つのみで（`palette.rb`）、新規作成に対応するボタンもメニュー項目もない。

現行版は常にコマンドラインからファイルを指定して起動する。空の図から始めるには、存在しないファイル名を引数に与えて起動するという間接的な方法しかない。

#### 5.2.2 JS 版の規定

**新規作成をツールバーの操作として提供する。** 空の図を作成し、用紙は既定値（5.4.2 参照）を適用する。

新規作成時に**ファイル名は決めない**。ブラウザでは保存先の決定が保存操作の時点でしか行えないため、名前の決定を保存まで遅らせる（5.4.2）。

未保存の図がある状態で新規作成を行う場合は、5.7 の破棄確認に従う。

### 5.3 開く（読み込み）

#### 5.3.1 現行版の動作

**アプリケーション内からファイルを開く経路は存在しない。** ファイル選択ダイアログは `cdelib/` 全9ファイルのどこにも現れない（`FileChooser`・`FileSelection` ともに出現数 0）。読み込みは**起動時のコマンドライン引数によってのみ**行われる。

読み込みの実体は `TECSModel#add_cell_list_from_tecsgen` であり、**TECSCDE 自身は CDL を解析しない**。tecsgen が解析した結果のセル一覧（`@tecsgen.get_cell_list`）を受け取ってモデルを構築する。すなわち現行版は tecsgen を内部に抱えており、これが 2.1 で述べた「tecsgen V1.3.1.0 以降に対応」というバージョン依存の実体である。

編集対象ファイル名 `@file_editing` は最後の引数から次のように決まる。

| 引数の末尾 | `@file_editing` |
|---|---|
| `.cde` | そのまま |
| `.cdl` | 拡張子を `.cde` に置換 |
| 上記以外 | 末尾に `.cde` を付加 |
| 引数なし | 空文字列 |

読み込み時の要素の扱いは次のとおりである。

| 状況 | 動作 |
|---|---|
| セル名が重複している | 2件目以降を**読み飛ばす** |
| セルタイプが解決できない | そのセルを**読み飛ばす**（コンソールに出力するのみ） |
| 結合先のセルが読み込まれていない | その結合を**作らない** |
| レイアウト情報がない | セルを左上から自動配置（後述） |

自動配置は座標 (10, 10) を起点に X 方向へ 55 mm 刻みで並べ、用紙幅 − 30 mm を超えたら X を 10 mm に戻して Y を 30 mm 進める。Y が用紙高さ − 15 mm を超えたら Y も 10 mm に戻る（**重なりを許して巻き戻す**）。

各セルには `set_editable(cell.get_locale)` により編集可否が設定される。`locale` は定義元のファイルと行を指すため、**編集中のファイル以外で定義されたセルは編集不可**となる。これが 5.4.1 の「編集可能なセルだけを書き出す」動作と対になっている。

#### 5.3.2 JS 版の規定

読み込みの経路を次の2つとする。いずれもユーザ操作を起点とする（2.3 の制約）。

| 経路 | 手段 |
|---|---|
| ファイル選択 | ツールバーの「開く」から `<input type="file">` によりファイルを選択する |
| ドラッグ＆ドロップ | キャンバス領域へのファイルのドロップを受け付ける |

現行版と異なり、**JS 版は CDL を自ら解析する**。tecsgen を内部に持てないためである（2.3）。解析の対象は本仕様の範囲では次に限る。

- `cell` 定義（セルタイプのネームスペースパス・セル名・呼び口の結合・属性値）
- `__tool_info__` ブロック
- `import` / `import_C` などの取り込み指示は**解析するが追跡しない**（参照先のファイルをブラウザから読めないため）。取り込み先で定義されているセルタイプは未解決として扱う。

未解決要素の扱いは、現行版の「黙って読み飛ばす」を**改める**。

| 状況 | JS 版の動作 |
|---|---|
| セル名が重複 | 2件目以降を読み飛ばし、**警告として提示**（9章） |
| セルタイプが解決できない | セルは**配置する**が未解決状態として表示し、警告として提示 |
| 結合先のセルが存在しない | 結合を作らず、警告として提示 |
| 複合セルタイプを含む | 4.7.2 の規定に従い、未対応の旨を警告として提示 |

セルタイプが解決できない場合にセルを消さないのは、現行版で図からセルが黙って消える挙動が、原因の特定を難しくするためである。未解決のセルタイプは呼び口・受け口の構成が不明なため、ポートを持たない矩形として表示し、プロパティに未解決である旨を示す。

編集可否は現行版と同じく定義元で決める。JS 版では取り込み先を追跡しないため、**編集中のファイルで定義されたセルのみが編集可能**となる。

### 5.4 保存・名前を付けて保存

#### 5.4.1 現行版の動作

パレットの save ボタンは `@model.save(@model.get_file_editing)` を呼ぶ。すなわち**編集中のファイルへの上書き保存のみ**である。

- 保存先を選ぶ操作がない（「名前を付けて保存」は存在しない）
- 上書きの確認がない
- 保存前に作業ディレクトリを `$run_dir` へ変更する（`Dir.chdir $run_dir`）ため、相対パスの解釈が起動時のディレクトリに固定される
- 書き込みは通常の `open(fname, "w")` であり、一時ファイルを経由しない。**書き込み中に失敗すると元のファイルが壊れる**
- 失敗時はメッセージボックスで通知する（`fail to save …`）

書き出す対象は**編集可能なセルのみ**である（`save_cells` の `if ! cell.is_editable? then next`）。取り込み元のファイルで定義されたセルは再出力されず、`__tool_info__("tecsgen")` の `direct_import` に取り込み指示として記録されることで整合が保たれる。

#### 5.4.2 JS 版の規定

保存操作を次の2つに分ける。

| 操作 | 動作 |
|---|---|
| 保存 | 直近の保存先が分かっていればそこへ書き戻す。分からなければ「名前を付けて保存」と同じ動作にフォールバックする |
| 名前を付けて保存 | 保存先を指定してダウンロードする |

ブラウザ単体構成では、**アプリケーションが任意のパスへ黙って書き込むことはできない**（2.3）。したがって「上書き保存」は現行版と同じ意味では実現できない。実装が File System Access API を利用できる場合は取得済みのファイルハンドルへの書き戻しとして上書きを実現してよいが、**本仕様はそれを前提としない**。利用できない場合はダウンロードとして扱い、同名ファイルの重複はブラウザの規則に委ねる。

現行版から改める点は次の2つである。

- **保存先を選べるようにする。** 現行版に「名前を付けて保存」が無いことは、図を別名で派生させる作業を CDL の手動コピーに追いやっている。
- **書き込みの失敗で既存データを失わない。** ダウンロードは既存ファイルをその場で置き換えないため、この性質は構成から自然に得られる。File System Access API を用いる実装でも、書き込み完了まで既存の内容を破棄しないこと。

用紙の既定値は A4 横（内容領域 277 × 190 mm）とする。5.1 の形式に記録される用紙情報は 5.6.1 に述べる制約を持つため、既定値の選択は現行版に合わせる。

### 5.5 レイアウト情報の復元

#### 5.5.1 現行版の動作

`__tool_info__("tecscde")` の JSON は、読み込み時にスキーマ検証を受ける（`TECSModel#validate`、スキーマ定義は `saveload.rb` の `@@TECSCDE_schema`）。検証を通らない場合は `validate error in __tool_info__("tecscde")` を報告し、**レイアウト情報を適用しない**（グローバル変数 `$b_force_apply_tool_info` で強制適用も可能）。この場合、図は 5.3.1 の自動配置のまま表示される。

スキーマは3つの情報を定義する。

| キー | 内容 |
|---|---|
| `paper` | 用紙の大きさ（`"A4"` / `"A3"` / `"A2"`）と向き |
| `cell_list` | セルごとの `location`（`[x, y, w, h]`、mm）・所属リージョン・ポート位置（辺と辺上のオフセット、mm。配列ポートは添字つき） |
| `join_list` | 結合ごとの呼び口側・受け口側の特定情報と、経路を構成する `bar_list`（`HBar` / `VBar` と位置） |

スキーマ定義では、キー名の先頭に `__` を付けた別エントリ（`:__tecscde`・`:__port_location`・`:__join_location`）で**省略可能な項目**を表している。配列ポートの添字や用紙情報がこれにあたる。

注目すべきは**結合経路の復元が保守的**である点である。`set_join_location_from_tecsgen` は、次の条件をすべて満たす場合にのみ保存された経路を適用する。

1. 経路を構成するバーが2本以上ある
2. 最初のバーの向きが、呼び口が接する辺の向きと直交している
3. 最後の2本のバーの位置が、受け口の実際の位置と許容誤差（`MAX_ERROR_IN_NOR` / `MAX_ERROR_IN_TAN`）の範囲で一致する

条件を満たさない場合は保存された経路を**黙って捨て**、自動計算された経路のままとする。これは、セルやポートの位置が図の側で変わった結果として保存済みの経路が破綻している場合に、破綻した線を復元するよりも引き直したほうが良いという判断である。CDL を手で編集した場合にも同じ経路をたどる。

#### 5.5.2 JS 版の規定

**保守的な復元という設計方針を引き継ぐ。** 保存されたレイアウトは「復元できるなら復元する、整合しないなら捨てて引き直す」ものとして扱い、整合しない情報を無理に反映しない。座標情報は図の見た目に関する補助情報であり、CDL の意味論（どのセルがどう結合されているか）より優先度が低いためである。

現行版から改める点は次の3つである。

- **捨てたことを利用者に伝える。** 現行版は経路を捨てても何も表示しないため、「保存したはずの配置が戻らない」という現象の原因が利用者から見えない。JS 版は破棄した対象の件数を警告として提示する（9章）。
- **スキーマ検証の失敗を全か無かにしない。** 現行版は検証に失敗するとレイアウト情報を全件破棄する。JS 版は `cell_list` と `join_list` を**要素単位で検証**し、妥当な要素は適用する。1セルの座標の誤りで図全体の配置が失われることを避ける。
- **未知のキーを保持する。** 検証で未知のキーを見つけた場合、拒否せず保持して書き戻す（5.1.2 の方針と同じ）。

許容誤差の具体値は実装が定めてよいが、現行版と同様に「ポート位置との一致判定」に用いる誤差であり、利用者が図を操作した結果の微小なずれを吸収する目的に限る。

### 5.6 エクスポート

#### 5.6.1 現行版の動作

**エクスポートできる形式は PDF のみである。** SVG・PNG への出力は実装されていない（`cdelib/` 全体で `PNGSurface`・`SVGSurface` の出現はなく、`Cairo::PDFSurface` のみが使われる）。

パレットの export ボタンは `MainView#export` を呼び、次のように動作する。

- 出力ファイル名は編集中のファイル名の `.cde` を `.pdf` に置換して**自動的に決める**。保存先を選ぶ操作はない
- **出力先に既存のファイルがあれば先に削除する**（`File.unlink`）。そのうえで PDF を生成するため、生成に失敗すると既存の PDF は失われる
- 用紙は `__tool_info__` に記録された用紙設定を用い、四辺に 10 mm（`PAPER_MARGIN`）の余白を取る
- 内容は余白の内側に**クリップされる**。図が用紙に収まらない場合、はみ出した部分は出力されない（縮小して収める処理はない）
- 用紙の右下に編集中のファイル名を、内容の外周に矩形の枠線を描く
- 出力中は表示倍率を PDF 用（72 DPI 基準。画面は 96 DPI）へ一時的に切り替え、終了後に元へ戻して再描画する

用紙設定には**スキーマと実装の食い違い**がある。`@@TECSCDE_schema` は `orientation` の値として `"LANDSCAPE"` と `"PORTRAIT"` を挙げているが、`tmodel.rb` の `Paper` 定数に定義されているのは `A4L`・`A3L`・`A2L` の**横向き3種のみ**である。縦向きを指定した CDL を読み込んでも一致する用紙が見つからず、`set_paper_from_tecsgen` は既定値を保ったまま黙って処理を続ける。すなわち**縦向きはスキーマ上は表現できるが、実装では選択できない**。

これは第3章の「glade に定義されているが起動されないダイアログ」、第4章の「言語には存在するが TECSCDE には無い複合セルタイプ」と同じ、**記述と実装の乖離**の3例目である。

#### 5.6.2 JS 版の規定

エクスポート形式を次のとおり定める。

| 形式 | 対応 | 備考 |
|---|---|---|
| SVG | **対応する（第一の形式）** | 2.3 により描画自体が SVG であるため、表示中の内容をほぼそのまま出力できる |
| PNG | 対応する | SVG を経由してラスタライズする。出力倍率を指定できるようにする |
| PDF | **本仕様の範囲では対応しない** | ブラウザ単体で PDF を生成するには外部ライブラリが必要であり、2.2 の「依存ライブラリなし」と両立しない |

PDF は現行版が唯一持っていた形式であるため、対応しないことは機能の後退にあたる。ただし**印刷経由での PDF 出力はブラウザの標準機能として利用できる**ため、用途としては代替される。JS 版は印刷時に図全体が1ページに収まる印刷用スタイルを提供することでこれに応える。

現行版から改める点は次の3つである。

- **出力範囲を選べるようにする。** 用紙固定・はみ出し切り捨てではなく、「用紙に合わせる」と「図の内容に合わせる」を選択できるものとする。現行版のクリップは、図が育ったときに黙って一部を失う挙動になっている。
- **出力先を選べるようにする。** 現行版のファイル名自動決定は、既存ファイルの削除と組み合わさって意図しない上書きを起こしうる。
- **用紙の向きを縦にも対応させる。** スキーマが `"PORTRAIT"` を規定している以上、読み込んだ値を実装が扱えないという状態を解消する。

### 5.7 終了時の扱い

#### 5.7.1 現行版の動作

パレットの quit ボタンは `Gtk.main_quit` を呼ぶだけである。**未保存の変更があっても確認しない。**

現行版は変更の有無を示すフラグ自体を持たない。`tmodel.rb` の `modified` は名前に反して「変更を undo 用の変更集合に記録する」ためのメソッドであり（`add_change_set` を呼んでから処理を実行する）、保存済みかどうかの状態管理には使われていない。ウィンドウタイトルにも変更を示す表示はない（3.1.1）。

#### 5.7.2 JS 版の規定

**未保存の変更がある状態でページを離れようとした場合、確認を求める。** 実現手段はブラウザの標準機能（`beforeunload`）とする。

そのために JS 版は**未保存状態を保持する**。具体的には、保存操作の完了時点を基準とし、以降に図を変更する操作が行われたかどうかを保持する。この状態は次の3つに反映する。

| 反映先 | 内容 |
|---|---|
| ステータス表示（3.1.2） | 未保存である旨を文字で示す |
| ページタイトル | 未保存を示す接頭辞を付ける |
| 新規作成・読み込み | 実行前に破棄の確認を求める（5.2.2・5.3.2） |

現行版がこれを持たないことは、GUI ツールとしては欠落だが、致命的にはなりにくかった。図の情報が編集対象の CDL に同居しており（5.1.1）、コンソールから起動する使い方では作業内容が手元のファイルとして残るためである。JS 版はブラウザのタブを閉じるだけで状態が消えるため、**同じ欠落がそのまま作業の消失につながる**。この差を根拠に、未保存状態の管理を JS 版の要件とする。
