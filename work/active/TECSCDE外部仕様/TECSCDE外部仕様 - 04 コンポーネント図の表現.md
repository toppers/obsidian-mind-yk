## 4. コンポーネント図の表現

本章は図を構成する要素そのものを規定する。第3章がそれらを「どこに置くか」（画面領域）を定めたのに対し、本章は「何を、どんな形で表すか」を定める。

現行版の事実は tecscde V0.5.1 のモデル層 `cdelib/tmodel.rb`（1863行）と描画層 `cdelib/tview.rb`（1178行）に基づく。モデル層のクラス構成は次のとおりで、**本章の 4.1〜4.9 はこの構成にほぼ一対一で対応する**。

| クラス | 対応する節 |
|--------|-----------|
| `TmCell` | 4.1 セル |
| （なし。tecsgen の `Celltype` を参照するのみ） | 4.2 セルタイプ |
| `TmPort` → `TmCPort` / `TmCPortArray` | 4.3 呼び口 |
| `TmPort` → `TmEPort` / `TmEPortArray` | 4.4 受け口 |
| （なし。`TmJoin` 経由で参照） | 4.5 シグニチャ |
| `TmJoin`・`TmJoinBar` → `HBar` / `VBar` | 4.6 結合 |
| **（存在しない）** | 4.7 複合セルタイプ |
| （`TmRegion` に統合） | 4.8 ネームスペース |
| `TmRegion` | 4.9 リージョン |

寸法は全て mm（モデル座標。3.2 で規定）。位置は格子 `ALIGN = 1.0 mm` に丸められる。

### 4.1 セル

#### 4.1.1 現行版の表現

セルは矩形で表す（`TmCell`）。

| 項目 | 値 |
|------|-----|
| 既定サイズ | **幅 25 mm × 高さ 15 mm** |
| 保持する幾何情報 | 左上座標 `@x`・`@y`、`@width`・`@height` |
| 表示する文字 | セル名（`CELL_NAME`）、セルタイプ名（`CELLTYPE_NAME`） |
| 属性 | `@attr_list`（属性名 → 式）。図上には表示しない |
| 所属 | `@owner` = `TmRegion`（4.9） |

選択中のセルは**二重の矩形**で示す。内側と外側の間隔は `GapActive = 1 mm`。

色は状態を表す。図の意味ではなく編集状態の表現である点に注意する。

| 色 | 意味 |
|------|------|
| `gray97` | 編集可能なセルの塗り |
| 黒 | 編集可能 |
| 青 | 編集不可（`.cdl` 由来で図から変更できない要素） |
| マゼンタ | 強調表示中／未結合 |
| 赤 | 不完全（結合が欠けている等） |

#### 4.1.2 JS 版の規定

- セルは矩形とし、既定サイズは現行版と同じ 25 × 15 mm とする。
- セル名とセルタイプ名を矩形内に表示する。両者は書体または大きさで区別できること。
- 選択状態は二重矩形に限定しない。ただし**色のみで選択状態を示してはならない**（3.7 でモードをカーソル形状のみに依存させないと定めたのと同じ理由による）。
- 上表の6色が担っている「編集可否」「不完全」「未結合」の区別は維持する。ただし色の値は実装に委ね、**色覚特性によらず判別できること**を要件とする。編集不可・不完全・未結合は色に加えて形状または記号でも示す。
- 属性は図上に表示せず、プロパティ領域（3.4）で編集する。

### 4.2 セルタイプ

#### 4.2.1 現行版の表現

**セルタイプは図の要素ではない。** モデル層に `TmCelltype` に相当するクラスは存在せず、`TmCell` が tecsgen の `Celltype` オブジェクトを `@celltype` として参照するだけである。

セルタイプが図に現れるのは次の2点に限られる。

- セル矩形内に表示されるセルタイプ名（`CELLTYPE_NAME`）
- パレットのセルタイプ一覧（3.3）— 配置可能なセルタイプの選択肢として

セル生成時、セル名はセルタイプ名から機械的に導出される（先頭の `t` を除去し、重複する場合は連番を付す）。

#### 4.2.2 JS 版の規定

- セルタイプを独立した図要素として描画しない。現行版と同じくセルの属性として扱う。
- セルタイプの定義（ポート構成・シグニチャ）は CDL に属する情報であり、本ツールでは**編集対象としない**。読み込んで参照するのみとする。
- セル名の自動導出規則は現行版を踏襲する。導出結果は編集可能とする。

### 4.3 呼び口（Call Port）

#### 4.3.1 現行版の表現

呼び口は `TmCPort`（配列の場合 `TmCPortArray`）で表し、セル矩形の**辺の上**に置かれる。

| 項目 | 値 |
|------|-----|
| 所属する辺 | `@edge_side` = `EDGE_TOP` / `EDGE_BOTTOM` / `EDGE_LEFT` / `EDGE_RIGHT` の4値 |
| 辺上の位置 | `@offs`（mm）。上辺・下辺なら左端から、左辺・右辺なら上端からの距離 |
| 配列添字 | `@subscript`（配列でなければ `nil`） |
| 既定の間隔 | `CPGap = 10 mm` |
| 記号 | 一辺 `Triangle_Len = 3 mm`・高さ `Triangle_Height = 2.598 mm` の三角形 |

移動時の制約が重要である。`TmPort#move` は `@edge_side` に応じて**片方の軸の増分を 0 に落とす** — 左右の辺なら水平移動を、上下の辺なら垂直移動を捨てる。すなわち**ポートは所属する辺の上をスライドすることしかできず、辺をまたいで移動できない**。`@offs` は 0 以上かつ辺の長さ以下に制限され、範囲外になる移動は無視される。

制約がもう1つある。`TmCell#initialize` は `port_def.is_require?` が真の呼び口を `@cports` に**登録しない**。すなわち **require 指定の呼び口は図に現れない**。

呼び口が持てる結合は最大1本である（`cport.set_join` は単一の代入）。

#### 4.3.2 JS 版の規定

- 呼び口はセル矩形の辺上に配置し、4辺のいずれかに所属させる。辺上の位置は辺の始点からの距離で保持する。
- **ポートは所属する辺の上のみを移動できる。** 辺をまたぐ移動は、明示的な「所属辺の変更」操作としてのみ許す（現行版の暗黙の制約を、意図的な操作として明示する）。
- 呼び口の記号は三角形とし、寸法は現行版を踏襲する。向きで呼び口・受け口を区別する。
- 呼び口が持てる結合は1本までとする（TECS の意味論による）。
- require 指定の呼び口を図に表示しない現行版の挙動を踏襲する。ただし**この事実をステータス表示または警告で利用者に伝える** — 現行版は何の表示もなく省くため、図が不完全に見える原因になる。

### 4.4 受け口（Entry Port）

#### 4.4.1 現行版の表現

受け口は `TmEPort`（配列の場合 `TmEPortArray`）で表す。幾何的な性質は 4.3 の呼び口と同一で、`TmPort` を共通の親クラスとする。既定の間隔は `EPGap = 10 mm`。

呼び口と決定的に異なる点が1つある。受け口は結合を**複数**持てる（`eport.add_join` はリストへの追加）。呼び口が `set_join` で単一なのと対をなす。これは「1つの受け口が提供する機能を、複数の呼び口が要求できる」という TECS の意味論をそのまま反映している。

#### 4.4.2 JS 版の規定

- 受け口の幾何的な扱いは呼び口と共通とする（所属辺・辺上位置・移動制約）。
- **受け口は結合を複数持てる。** 呼び口の上限1本との非対称性を実装上も保持する。
- 呼び口と受け口は記号の向きで区別し、**色のみに依存しない**。

### 4.5 シグニチャ

#### 4.5.1 現行版の表現

**シグニチャは独立した図要素ではない。** モデル層に対応するクラスはなく、描画層が結合の中点に文字列として描くだけである（`tview.rb`: `draw_text( xm, ym, join.get_signature.get_name.to_s, SIGNATURE_NAME, ... )`）。

すなわちシグニチャは**結合のラベル**として存在する。ポートの属性としては描かれない。

#### 4.5.2 JS 版の規定

- シグニチャは結合のラベルとして、結合の中点付近に表示する。
- シグニチャ名の表示は切り替え可能とする（結合が密集する図では可読性を損なうため。7章の表示フィルタで扱う）。
- シグニチャ定義そのものは CDL に属する情報であり、本ツールでは編集しない（4.2 と同じ方針）。

### 4.6 結合（Join）

#### 4.6.1 現行版の表現

結合は `TmJoin` で表し、**呼び口1つと受け口1つを結ぶ**（`@cport`・`@eport`）。

線は直線ではない。`@bars` として `HBar`（水平）と `VBar`（垂直）の列を持ち、**水平・垂直の線分のみで構成される折れ線**として描かれる。生成は `create_bars` が行う。

| 定数 | 値 | 用途 |
|------|-----|------|
| `DIST_PORT` | 4 mm | ポートから最初の折れ点までの距離 |
| `NEAR_DIST` | 2 mm | 折れ線の掴み判定の許容範囲 |
| `MAX_ERROR_IN_NOR` | 0.5 | 法線方向の許容誤差 |
| `MAX_ERROR_IN_TAN` | 2 | 接線方向の許容誤差 |

結合の可否はシグニチャの一致で判定する（3.7 のカーソル形状「結合先として有効」の判定と同一）。

#### 4.6.2 JS 版の規定

- 結合は呼び口1・受け口1を結ぶ。呼び口側の多重結合は許さない。
- 線は**水平・垂直の線分のみで構成する**（斜線を用いない）。現行版の `HBar`／`VBar` 構成を踏襲する。
- ポートから最初の折れ点までは `DIST_PORT` 相当の距離を確保し、線がポート記号に重ならないようにする。
- 折れ点は利用者が移動できる。掴み判定の許容範囲を設ける（現行版の `NEAR_DIST` 相当）。
- 結合可能性の判定はシグニチャの一致とする。**判定結果は結合操作の前に視覚的に示す**（3.7 のカーソル4状態）。
- 結合の自動経路生成は、既存のセル矩形を避けることを要件とはしない（現行版も避けていない）。将来の自動レイアウト（7.3）で扱う。

### 4.7 複合セルタイプ（Composite）

#### 4.7.1 現行版の表現

**TECSCDE V0.5.1 は複合セルタイプを表現できない。**

根拠は次の対比である。

| 対象 | `composite` の出現回数 |
|------|----------------------|
| tecsgen コア（`tecslib/core/*.rb`） | `CompositeCelltype` として **144回** |
| TECSCDE モデル層・描画層・保存層（`cdelib/*.rb` 全9ファイル） | **0回**（大文字小文字を問わず） |

すなわち TECS 言語としては複合セルタイプが第一級の概念であるにもかかわらず、TECSCDE のモデルには対応する概念が一切存在しない。`TmCell` は常に単一のセルタイプを参照し、内部に別のセルを含む構造を持たない。

これは第3章のダイアログ（glade に定義されているが V0.5.1 から起動されない）と同種の欠落だが、性質が異なる。ダイアログは**作りかけの痕跡**が残っているのに対し、複合セルタイプは**痕跡すらない** — 設計として最初から対象外だったと解される。

#### 4.7.2 JS 版の規定

複合セルタイプの扱いは**本仕様では未決とし、第4章の範囲外とする。** 理由は、これが表現方法の選択ではなく機能追加の是非の問題であり、決定には以下の判断が必要になるためである。

- 複合セルタイプを含む CDL を読み込んだとき、展開して内部セルを表示するか、単一のセルとして畳んで表示するか
- 畳む場合、複合セルタイプの外部ポートと内部セルのポートの対応をどう示すか
- 図から複合セルタイプを新規に定義できるようにするか（現行版は CDL 側でしか定義できない）

**当面の規定**: 複合セルタイプを含む CDL を読み込んだ場合、**エラーとせず、対応していない旨を警告として提示する**（9章）。現行版は読み込み自体を想定していないため、この警告は JS 版の新規要件である。

### 4.8 ネームスペース

#### 4.8.1 現行版の表現

**ネームスペースは独立した図要素ではなく、リージョンに統合されている。**

`TmRegion` は `@namespace_path`（`NamespacePath` オブジェクト）を保持し、これがそのリージョンの識別子を兼ねる。ネームスペース単体を表すクラスは存在しない。識別子の構文は `IDENTIFIER_RE = /[A-Za-z_][0-9A-Za-z_]*/`、区切りは `::`、根は `::`。

#### 4.8.2 JS 版の規定

- ネームスペースを独立した図要素として描画しない。リージョン（4.9）の識別子として扱う現行版の構成を踏襲する。
- 識別子の構文と `::` 区切りは現行版と同一とする。
- ネームスペース単位の表示フィルタを提供する（7.5）。

### 4.9 リージョン

#### 4.9.1 現行版の表現

リージョンは `TmRegion` で表し、**木構造**をなす。

| 項目 | 内容 |
|------|------|
| 子 | `@sub_region`（名前 → `TmRegion`） |
| 親 | `@owner` = 親 `TmRegion`、または根の場合 `TECSModel` |
| 所属セル | `@cell_list` |
| 識別子 | `@namespace_path`（4.8） |
| 色 | `get_color` を持つ |

リージョンは**矩形として描かれない**。所属を示す手段は色だけであり、メインウィンドウ下端の「Color by Region」チェックボックス（3.1.1）で塗り分けを切り替える。セルの位置からリージョンを逆引きする経路も存在する（`get_region_by_location`）。

#### 4.9.2 JS 版の規定

- リージョンは木構造とし、セルはいずれか1つのリージョンに所属する。
- リージョンの表現は**色による塗り分けを既定とし、現行版と同じく切り替え可能**とする。
- ただし色のみに依存させない。リージョン名を凡例として表示し、セルを選択したときは所属リージョンをステータス表示（3.1.2）に示す。
- **リージョンを矩形で囲む表現は採用しない。** セルの配置がリージョンごとに連続している保証がなく、交差する矩形が生じるためである（現行版が色を選んだ理由もここにあると解される）。
- リージョン単位の表示フィルタを提供する（7.5）。
