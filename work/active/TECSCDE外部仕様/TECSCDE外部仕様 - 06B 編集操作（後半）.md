## 6. 編集操作（後半）

### 6.5 プロパティ編集

#### 6.5.1 現行版の動作

プロパティパネル（3.4 で画面上の位置を規定済み）は、**選択中のセルがちょうど1個のときのみ**内容を表示する。0個・複数選択・セル以外の選択では「(unselected)」表示に固定され、属性一覧も空になる。

セル名編集はキャンバス上のダブルクリック（3.1.2 のインプレース編集）とパレットの名前入力欄の2経路があり、いずれも `TECSModel#rename_cell` に到達する。新しい名前は識別子構文（`[A-Za-z_][0-9A-Za-z_]*`）と重複の有無を検証し、違反時はメッセージボックスで拒否する（この場合ハッシュ等の状態は変更されない）。

**リージョン欄は事実上機能しない。** 入力欄はセルの所属リージョンパスを表示し、編集可能に見えるスタイルで表示されるが、対応するイベントハンドラの中身は**丸ごとコメントアウト**されている。入力しても何も起きない。6.1 で見つかった「新規セルは常にルートリージョンに配置される」スタブと合わせ、**リージョン割り当てを変更するUI上の経路がアプリ全体を通して存在しない**ことになる。

属性値の編集は `Gtk::CellRendererCombo` で行い、選択肢が定義された属性はコンボから選ぶのみ（自由入力不可）、それ以外は自由入力可。**この属性編集の確定処理だけが、ドラッグ完了時やキー入力の末尾ではなく、値確定イベントの中で直接 `set_undo_point` を呼ぶ**唯一の箇所である。

**`CellPluginDialog` は UI のどこからも到達できない。** ダイアログ自体は glade から完成した形で実装されているが、呼び出し元のメソッド `Hilite_objs#cell_plugin_dialog` を呼ぶボタン・シグナルがコード全体に一つもない。第3章で見つかった「glade にあるが起動されないダイアログ」と同型の死んだ機能である。

#### 6.5.2 JS 版の規定

- プロパティパネルは選択が単一セルのときのみ内容を表示する現行版の方針を踏襲する。複数選択時の共通編集項目のみの表示は 3.4.2 で規定済みの内容と整合させる。
- セル名の検証規則（識別子構文・重複禁止）は踏襲し、失敗時は 9章のメッセージ形式で示す。
- **リージョン欄を実際に機能させる。** 現行版の「表示のみで編集不可」を解消し、既存リージョンのツリー（4.9 で規定した木構造）から選択するドロップダウンとして提供する。これにより 6.1 で規定した「新規セルは常にルートリージョンに配置され、以後の変更はプロパティパネルからのみ行う」という設計が実現される。
- 属性値編集は選択肢付き属性はコンボ、それ以外は自由入力とする現行版の区別を踏襲する。**確定と同時に1アンドゥ単位とする粒度も踏襲する。**
- `CellPluginDialog` に相当する機能は**採用しない**。現行版でも実装されながら一度も呼ばれておらず、何を編集するダイアログなのか仕様自体が固まっていなかった機能であるため、3.6.1/4.7 と同じ「実装に至らなかった設計意図の記録」として扱い、JS 版では引き継がない。

### 6.6 アンドゥ・リドゥ

#### 6.6.1 現行版の動作

アンドゥ／リドゥの起動はパレットの Undo／Redo ボタンのみで、**キーボードショートカットは存在しない**（`key_pressed` に Ctrl+Z 等の分岐がない）。

内部実装は本格的なスナップショット型の変更履歴（`ChangeSetControl` モジュール、`TECSModel` に mixin）である。`ChangeSet` は変更されたオブジェクトごとに**変更前の状態を複製して保持**するハッシュで、同一変更ウィンドウ内で同じオブジェクトが複数回変更されても最初のスナップショットだけを保持する。`set_undo_point` が変更集合を確定し、**確定後に新しい変更が来ると、それ以前にアンドゥで戻っていた分の「やり直し履歴」を切り捨てる**（一般的な線形アンドゥ履歴の挙動）。

**2つの不具合がある。**

1. **最初の1回の変更はアンドゥできない。** `undo` は `@change_no > 1` を条件とするため、変更を1回しか確定していない状態（`@change_no == 1`）では Undo が効かない。少なくとも2回変更を確定して初めて Undo が機能し始める、という気づきにくいオフバイワン。
2. **Redo は実装が完成しているにもかかわらず、ボタンが恒久的に無効化されている。** `palette.rb` に `@button_redo.set_sensitive false` と `# currently redo doesn't work well` というコメントがあり、作者が既知の不具合を把握したうえで機能そのものを隠す判断をしたことが読み取れる。

`set_undo_point` はドラッグ完了・新規セル配置・キー入力の末尾（削除やポート挿入を含む）・属性値の確定・名前変更など多くの箇所から呼ばれ、**1つのユーザ操作を1つのアンドゥ単位にまとめる**設計になっている。変更が実際になければ何もコミットしない（無条件呼び出しでも安全）。なお、この変更集合の仕組みは保存要否を示す「dirty フラグ」としては使われておらず、未保存状態の管理（5.7）とは独立している。

#### 6.6.2 JS 版の規定

- **キーボードショートカット（Ctrl+Z / Ctrl+Shift+Z、または Ctrl+Y）を追加する。** 現行版にない機能だが、Undo/Redo は業界標準としてショートカットが期待される操作であるため新規要件とする。
- 線形の変更履歴（確定した変更を配列で保持し、新しい変更でリドゥ側を切り捨てる）という設計方針は現行版を踏襲する。1ユーザ操作＝1アンドゥ単位という粒度（ドラッグ完了・削除の一括処理・属性確定など）も踏襲する。
- **現行版の2つの不具合は両方とも解消する。** 最初の変更から Undo が機能すること、Redo が Undo 同様に常時正しく機能することを要件とする。
- 変更履歴の仕組みを保存要否のフラグとして流用しない設計（5.7 の未保存状態管理とは独立に持つ）は現行版を踏襲する。

### 6.7 クリップボード操作（コピー・貼り付け・切り取り）

#### 6.7.1 現行版の動作

**該当する機能が一切存在しない。** `cdelib` 全体（制御層・モデル層・描画層・パレット・保存層・未使用ダイアログの計8ファイル）を `Clipboard`／`selection_owner`／`clipboard_get` 等で検索しても該当箇所はゼロで、モデル層にも copy/paste/cut に相当するメソッドは定義されていない（`copy_from` はアンドゥ用の内部スナップショット複製であり、ユーザ向けのコピー機能ではない）。`key_pressed` にも Ctrl+C/X/V に相当する分岐はなく、パレットにもクリップボード関連のボタンは存在しない。

#### 6.7.2 JS 版の規定

現行版に前例がないため、本節は新規要件として規定する。

- コピー（Ctrl+C）: ハイライト中のセル、およびその両端がいずれもハイライト範囲に含まれる結合を、**アプリ内のメモリ上のクリップボード**（OS クリップボードとは連携しない）にコピーする。属性値・所属リージョンを含む。
- 貼り付け（Ctrl+V）: クリップボードの内容から新しいセルを生成する。セル名は 6.1 と同じ自動命名規則（重複時は連番）を用いて衝突を避ける。配置位置はコピー元から一定のグリッド単位だけオフセットする。
- 切り取り（Ctrl+X）: コピー後に 6.3 の削除を行う（削除の undo 単位・確認方針をそのまま適用）。
- 読み込み専用（`is_editable?` が偽）のセルはコピーはできるが、貼り付け後の新規セルは編集可能として扱う（複製である以上、複製先は編集可能になるのが自然なため）。
- OS クリップボードとの連携（ブラウザタブ間・アプリ間貼り付け）は本仕様の範囲外とする。実現するにはテキスト化（CDL 断片としてシリアライズする等）が必要になり、5章で規定した `.cde` 形式の読み書きとは別の設計判断を要するため、将来の拡張として保留する。

### 6.8 グループ操作

#### 6.8.1 現行版の動作

**動作する機能は存在しない。** ただし痕跡が2つ見つかる。

`SubmodeList` には `:SM_SURROUNDING_CELLS`（範囲選択中）と `:SM_MOVING_CELL_EDGE`（セル辺の移動中）が宣言されているが、いずれもコード全体で**宣言以外に一度も参照されない** — `@sub_mode` に代入する箇所も、`case @sub_mode` で分岐する箇所も存在しない。ドラッグで矩形を作って複数セルを囲み選択する、いわゆるラバーバンド選択が意図されていたと推測できるが、実装には至っていない。

> [!info] 第3章の記載との整合
> [[#3.7 モードとカーソル|3.7]] のサブモード一覧表は「範囲選択中」を実在する状態として列挙しているが、本章の調査で**コード上は宣言のみで到達不能**であることが判明した。3.7 は「状態として定義されている」という事実は正しく、本節はそれが「到達可能かどうか」という一段深い事実を補足するものであり、矛盾ではなく詳細化である。

`TmRegion` はユーザが選択して作るグループではなく、CDL/tecsgen の C++ ネームスペース階層をそのまま映すための構造で、`.cdl`/`.cde` 読み込み時にのみ所属が決まる（6.1 で見た「クリックでは常にルートに置かれる」スタブと整合する）。`get_color` は中身のない空スタブで、リージョンによる色分け表示（4.9・「Color by Region」トグル）以外にリージョンを操作対象として扱う機能はない。

複数オブジェクトをまとめて操作できる唯一の実体は、シフト/Ctrlクリックで作る一時的な `Hilite_objs` である（6.2）。移動・削除は複数オブジェクトに同時適用できるが、名前を付けて保存する・グループ化/解除するという概念はなく、選択は次のクリックやモード変更で即座に失われる。「すべて選択」のショートカットもない。

#### 6.8.2 JS 版の規定

- **ラバーバンド（矩形ドラッグ）による範囲選択を実装する。** 現行版で宣言だけされていた「範囲選択中」の意図を、実際に動く機能として実現する。空白のキャンバス上でのドラッグは矩形を描き、矩形に完全に含まれるセルをハイライトする。
- グループを**永続的な名前付きオブジェクトとしては導入しない。** 現行版の `Hilite_objs` と同様、選択は一時的なものとし、次の操作で失われる一時集合として扱う（「保存されたグループ」概念は本仕様の範囲外とし、必要になれば将来の拡張として扱う）。
- ラバーバンド選択で得られた集合にも、6.2 の移動・6.3 の削除・6.7 のコピーがそのまま適用できることを要件とする。
- 「すべて選択」（Ctrl+A）を新規に追加する。現行版にない操作だが、矩形選択を実装する以上、対になる操作として自然に要求される。
- リージョン（`TmRegion`）は引き続き 4.9 の規定どおり CDL のネームスペース階層を表すものとし、本節が規定する一時的な選択グループとは独立した概念として扱う（両者を混同しない）。
