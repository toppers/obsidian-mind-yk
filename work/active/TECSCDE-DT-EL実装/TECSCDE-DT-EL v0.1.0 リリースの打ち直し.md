# Decision: TECSCDE-DT-EL v0.1.0 リリースの打ち直し

## Context

- 下書き（draft）リリース `v0.1.0` は 2026-10-31 に作られ、タグは `fd16a35`（PR #14 のマージ）を指していた。版の表示（PR #16〜#18）、`_CDL_FILES.txt` による `import` の探索（#19・#20）、診断ログの置き場所・警告・整理（#21）は入っていなかった。
- リポジトリは公開で、リリースを公開すると成果物を誰でも取れる。自動更新（`update-electron-app`）もこのリリースを更新元として見る。
- まだ公開していないため、タグを動かしても影響する人はいなかった。

## Options Considered

1. **そのまま公開（A）**: 作業は無いが、最初の公開版が直近の修正を欠いた古い状態になる。
2. **削除して `main` に打ち直し、確認後に公開（B）**: 最初の公開版が最新になる。削除（下書きとタグ。元に戻せない）と再ビルドの手間がある。
3. **下書きのまま保留（C）**: 何も壊れないが、決定の先送りで古い下書きが残る。

## Decision

**B を採用**（2026-11-02、ユーザーの指示）。macOS・Linux でのインストール確認が済むまで公開しない。付け直しは 4 回行った（下の「2 回目の打ち直し」「3 回目の打ち直し」「4 回目の打ち直し」）。

## 実施結果（2026-11-02）

- 下書きとリモートのタグを削除（`gh release delete v0.1.0 --cleanup-tag`）。ローカルのタグも削除し、`origin/main`（`cdbb8c1`、PR #21 のマージ）に付け直して push。
- CI の `Release`（run `41365141495`）は 3 OS とも成功。新しい下書きには成果物 6 点（`Setup.exe`、`.nupkg`、`RELEASES`、`.dmg`、macOS の `.zip`、`.deb`、`.rpm`）。
- 削除と再タグの push は、権限の自動判定で私（エージェント）の実行が拒否されたため、ユーザーが `!` で実行した。
- **未実施**: macOS・Linux でのインストール確認、公開。

## 2 回目の打ち直し（2026-11-02）

- **理由**: 1 回目の打ち直し（`cdbb8c1`）のあとに、サンプルの追加（PR #22）と、`cPort[] = c.e;` に対応する修正（PR #23、`tEV3Sample.tecsgen-opts` を開いたときの `W-MISSING-JOIN-TARGET` 19 件の解消）が `main` に入った。この不具合は同じサンプルを開くと必ず目に入るため、公開する版に入れる。
- **実施**: 下書きとリモートのタグを削除し、`main`（`1a5cc4e`、PR #23 のマージ）に付け直して push（ユーザーが `!` で実行。エージェントの実行は権限の自動判定で拒否された）。
- **結果**: CI の `Release`（run `41397421940`）は 3 OS とも成功。新しい下書きは、タグ `v0.1.0` が `1a5cc4e`、成果物は前回と同じ 6 点（`Setup.exe`、`.nupkg`、`RELEASES`、`.dmg`、macOS の `.zip`、`.deb`、`.rpm`）。
- **未実施**: macOS・Linux でのインストール確認、公開。
- **注意**: 付け直しの前、ローカルのタグは `e5d9120` を指していた（リモートの前回のタグは `cdbb8c1`）。ローカルのタグは、付け直しのたびに消して作り直しているので、結果には影響しない。
- 以降にマージした変更（セルタイプの詳細ダイアログのフルパス表示など）は、この `v0.1.0` に含まれない。含めるなら、同じ手順でもう一度付け直す。
- **決定（2026-11-02、ユーザーの指示）**: セルタイプの詳細ダイアログのフルパス表示（実装リポジトリの PR #24、マージコミット `cbc818c`）は、`v0.1.0` に入れず、次の版に回す。公開は、macOS・Linux でのインストール確認が済んだあと、タグ `v0.1.0`（`1a5cc4e`）のまま行う。

## 3 回目の打ち直し（2026-11-03）

- **実施**: 下書きとリモートのタグを削除し、`main`（`087e621`、PR #28 のマージ）に付け直して push（ユーザーが `!` で実行。エージェントの実行は権限の自動判定で拒否される）。
- **結果**: CI の `Release`（run `41529533039`）は 3 OS とも成功。新しい下書きは、タグ `v0.1.0` が `087e621`（`origin/main` と一致）、成果物は前回と同じ 6 点（`Setup.exe`、`.nupkg`、`RELEASES`、`.dmg`、macOS の `.zip`、`.deb`、`.rpm`）。
- **未実施**: macOS・Linux でのインストール確認（新しい成果物で行う）、公開。
- 以降にマージした変更は、この `v0.1.0` に含まれない。含めるなら、同じ手順でもう一度付け直す。

## 4 回目の打ち直し（2026-11-03）

- **理由**: 3 回目のあとに、ユーザーが macOS の実機で動作を確認した結果を反映した修正が、実装リポジトリの `main` に入った（`c4341f0`: macOS でウィンドウを閉じて Dock から開き直すと IPC ハンドラの二重登録で例外になる問題の修正。`26cfba4`: AGENTS.md のログ出力先の記述の修正）。**ユーザーの指示（2026-11-03）で、これらも `v0.1.0` に入れる。**
- **実施**: 下書きとリモートのタグを削除し、`main`（`26cfba4`）に付け直して push（ユーザーが `!` で実行。エージェントの実行は権限の自動判定で拒否される）。付け直す前に、`main` で全テスト（797 件中、失敗 0 件）と `tsc`（main・renderer）が通ることを確認した。
- **結果**: CI の `Release`（run `41586387751`）は 3 OS とも成功。新しい下書きは、タグ `v0.1.0` が `26cfba4`（`origin/main` と一致）、成果物は前回と同じ 6 点（`Setup.exe`、`.nupkg`、`RELEASES`、`.dmg`、macOS の `.zip`、`.deb`、`.rpm`）。
- **注意**: 下の macOS・Linux の確認結果は、**前の成果物（3 回目、`087e621`）に対するもの**で、この成果物（`26cfba4`）では確認していない。差分は `c4341f0`（macOS の IPC の二重登録の修正）と AGENTS.md の文書だけ。確認のやり直しの要否は、ユーザーの判断に任せる。
- **公開（2026-11-03 06:20 UTC、ユーザーの指示）**: `gh release edit v0.1.0 --draft=false --latest` で公開した。公開前に、下書きか・タグが `26cfba4`（`origin/main`）を指すか・成果物の数・説明文が空かを確かめ、公開後に `gh release view` で公開済み（先行リリースではない、最新）であることを確かめた。成果物は **7 点**（`Setup.exe`、`.nupkg`、`RELEASES`、`.dmg`、macOS の `.zip`、`.deb`、`.rpm`。これまで「6 点」と書いていたのは数え間違い）。リリースの説明文は、公開時は空だった（2026-11-04 に設定。下の節）。
- **公開時に確認できていなかったこと（2026-11-04 に解消。下の節）**: macOS・Linux の確認は前の成果物（`087e621`）に対するもの。起動後の動作（版の表示など）と `.rpm` は、報告を受けていない。問題が見つかったときは、公開済みのタグを付け替えず、新しい版（`v0.1.1` など）で出し直す。

## macOS でのインストール確認（2026-11-03、ユーザーの報告）

- **環境**: Apple M4 の MacBook Pro。成果物は arm64 版の `.dmg`（macOS 版は Apple Silicon 用だけが作られる。Intel Mac 用は無い。`forge.config.js` はアーキテクチャを指定せず、CI の `macos-latest` のものになる）。
- **結果**: インストールして起動しようとすると、「壊れている」として実行できなかった。**`xattr -cr /Applications/<アプリ>.app` を実行すると、起動できた。**
- **原因（推定。`codesign`・`spctl` の出力は未確認）**: 署名と公証をしていないアプリ（2026-09-23 の決定: 未署名で配布する）を、ダウンロードして開いたときの macOS の拒否。ダウンロードの印（隔離属性）を外すと起動できる。
- **確認できたのは、起動まで**。起動後の動作（版の表示、ログの置き場所、サンプルの読み込みなど）は、報告がないので記録していない。
- **未実施**: 公開（Linux でのインストール確認は、下の節を参照）。
- **課題**: Mac の利用者は、初回に上の操作が必要。README に書く、または署名・公証（Apple の開発者アカウントが必要）を検討する。未署名で配布する方針の見直しになるため、未決。

## Linux でのインストール確認（2026-11-03、ユーザーの報告）

- **環境**: Ubuntu 24.04。成果物は `.deb`（`tecscde-dt-el_0.1.0_amd64.deb`）。CPU の種類は報告になく、記録していない。
- **結果**: `.deb` をインストールして、**起動できた**。
- **確認できたのは、インストールと起動まで**。起動後の動作（版の表示、サンプルの読み込み、診断ログの出力先）、および `.rpm` は、報告がないので記録していない。
- **未実施**: 公開。

## 公開後の確認とリリースの説明文（2026-11-04、ユーザーの報告と指示）

- **報告**: macOS・Linux の起動後の動作は、**期待どおり**。`.rpm` の確認結果も、**期待どおり**。確認した項目の内訳（版の表示、サンプルの読み込み、ログの出力先など）と、`.rpm` を動かした環境は、報告になく、記録していない。
- **リリースの説明文**: ユーザーの指示で、「バージョン0.1.0」に設定した（`gh release edit v0.1.0 --notes`）。設定後に `gh release view` で本文が一致し、公開済みの状態（下書きでも先行リリースでもない）が変わっていないことを確かめた。
- **結果**: 公開時に未確認だった点（起動後の動作、`.rpm`、説明文が空）は、すべて解消した（確認の中身は、上の報告の範囲）。

## Consequences

- 版は `package.json` の `0.1.0` のまま（版の唯一の情報源。[[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 - 02 動作環境|DT外部仕様 2.5.5]]）。タグの付け直しで版の番号は変わらない。
- 公開後に自動更新が働くのは、公開済みの次の版が出たとき以降。
- 確認で不具合が出れば、また打ち直す（同じ手順）。
