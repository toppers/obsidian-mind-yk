### 配列の受け口の要素展開（旧監査 #23 の残り）

- **2026-11-12 決定**: V0.2.1 に入れる。**最初の作業は、三者監査 #20・#24 の契約で、受け口側の添字の問題が解けるかの確認**（コード変更なし）。
- **現状**: 配列の**呼び口**は要素へ展開済み（固定長 `[N]` は N 個、可変長 `[]` は結合で使われた添字の最大値+1個）で、添字付き結合も解決する。配置ファイルの鍵は配列要素のみ `名前[添字]` で、旧形式の名前だけの鍵も読む（`a9a6512`、2026-10-28、実機確認済み 2026-10-29）。**受け口の配列は未展開**。
- **残っている理由（旧監査の記録）**: 結合記述が受け口側の添字を持たない。そのため、どの要素へ結合するかを結合記述から決められない。**設計が未決**で、実装の前に方式を決める必要がある（TBC）。
- **三者監査 #20 との関係（項目名からの推定、inferred）**: 69件の #20「配列を要素ごとのポートへ展開しない」と重なる。契約側の記述は[[TECSCDE-DT-EL内部仕様 - 監査対応 19-28 配列と配置]]（監査20に「複数ソースからの受け口要素参照」とある）。#20 の扱いは、下の「未決」で一緒に決める。

## v0.2.3（取り下げ）・v0.2.4（公開済み、2026-11-14）

`v0.2.2` の `W-CPP-FALLBACK`（`gcc` が終了コード 1、標準エラー空）を調べて直した。**`v0.2.3` は公開せず、`v0.2.4` で出し直した。**

1. **原因1: DLL の衝突（`v0.2.3`、`04c09ab`）**: PATH 上で `C:\Program Files\Meld\`（GCC ランタイム DLL を同梱）が `C:\Ruby40-x64\msys64\ucrt64\bin` より前にあり、MSYS2 の `gcc.exe` が `cc1.exe` を起動できず、標準エラーなしで終了コード 1 になっていた。`Meld\` と `ucrt64\bin` だけの PATH で再現した。C プリプロセッサのディレクトリを子プロセスの PATH の先頭へ足して直した（`tecsgen-runner.ts`、Windows のみ）。
2. **原因2: `-E` が付かない（`v0.2.4`、`f596b06`）**: 1 を直すと、残りの `W-CPP-FALLBACK`（7 件）が `unknown type name 'ER'` などの**コンパイルエラー**だと分かった。自動検出または設定で決めたコマンドに、`cppArgs` が未設定のとき `-E -DTECSGEN` が付かず、`gcc` がヘッダーを**コンパイル**していた。副作用として、ヘッダーの隣に `.gch`（`tests/hr-tecs` に 4 件）が作られ、成功したヘッダーは標準出力が空で型が取れず、`W-C-TYPE-UNRESOLVED` が 51 件から 206 件に増えた（`v0.2.3` の実機）。
3. **仕様の変更（ユーザー決定、2026-11-14）**: `cppArgs` が**未設定**のときは `-E -DTECSGEN` を既定にする。空欄で保存された場合は、これまでどおり何も付けない。[[TECSCDE-DT-EL内部仕様 - 09E V0.2.1 Cプリプロセッサ設定と失敗詳細|内部仕様 09E]]（「暗黙の既定値なし」を変更）と[[TECSCDE-DT外部仕様 - Cプリプロセッサ設定と失敗詳細(V0.2.1用)|外部仕様]]を更新した。

## v0.2.5（公開済み、2026-11-15）

`v0.2.4` に残っていた `W-PLUGIN-TYPE-LOAD`（tecsgen が `kernel.cdl:63:17` の `TEXPTN` などで構文エラーの列）を調べて直した。

- **原因**: `W-CPP-FALLBACK` と同じ **gcc の DLL 衝突**。tecsgen 自身も `import_C` のヘッダー展開で PATH 上の `gcc` を子プロセスで起動する。`Meld\` が `ucrt64\bin` より先にあると、その `gcc` が標準エラーなしで失敗し、C の型名（`TEXPTN`、`size_t`、`mrb_state` など）が未知になり、構文エラー（G1016）が連なる。`v0.2.4` までの修正（`04c09ab`）は、アプリ自身が起動する `gcc`（C プリプロセッサ）だけで、tecsgen の起動には PATH を足していなかった。
- **再現**: `tEV3Sample.tecsgen-opts` で実際の tecsgen を実行。実機の PATH（`Meld` が先）では終了コード 1・エラー 44〜45 件（アプリと同じ）、`ucrt64\bin` を先頭に足すと終了コード 0・エラー 0 件。
- **修正（`3d32584`）**: `TecsgenRunner` に、解決済みの C プリプロセッサのフルパスを返すプロバイダー（`resolveCppPathProvider`）を渡し、そのディレクトリを tecsgen の子プロセスの PATH の先頭へ足す（Windows のみ、`process.env` は変更しない）。プロバイダーが失敗しても tecsgen は実行する。`index.ts` では `toolSettings.resolveForPreprocess()` のフルパスを渡す。テスト 3 件を追加（`vitest` 1,211 件成功、5 件スキップ）。
- **リリース**: `v0.2.5`（`69c9bda`、run `43664175512`、3 ジョブとも成功、成果物 7 点）。実機にインストールして確認してから公開した（2026-11-15 01:49 UTC、`Latest`）。
