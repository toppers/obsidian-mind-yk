## タグとリリースの経緯（2026-11-13 追記）

- 段1〜4 を `main` に揃えた（`3a2af05`）うえで、`package.json` を `0.2.1` に上げ（`368d8e3`）、注釈付きタグ `v0.2.1` を切って `origin`・`upstream` へ push した。
- **`v0.2.1` のリリース実行（run `43375259357`）は失敗**。macOS は成功、Windows と Ubuntu が失敗した。ドラフトのリリースには macOS の成果物 2 点（`.dmg`、`.zip`）だけが付いた。
  - Windows: `tests/main/tecsgen-command-copy.test.ts` の ps1 の round-trip 3 件（powershell7・powershell5・cmd）。`cwd` の期待値がランナーの 8.3 短縮名（`RUNNER~1`）、実際の値が長い名前（`runneradmin`）で、`argv` は一致していた。製品コードではなくテストの比較の問題。`v0.2.0` の実行（run `43177567586`）も同じ 3 件で失敗していた。
  - Ubuntu: RPM の `%install` で `cp: cannot stat 'usr/*'`。ランナー `ubuntu-latest` が Ubuntu 26.04（rpm 6.0.1）に変わり、maker-rpm 8.0.1 の生成する spec と合わなくなったと推定（rpm 6 の仕様変更との突き合わせは未実施）。RPM の失敗で make が止まり、DEB は作られなかった。
- **修正**（`main`）: `0d035c7`（ps1 のテストの `cwd` の期待値を `realpathSync.native` で長い名前に揃える）、`731e382`（Linux ジョブを `ubuntu-24.04` に固定）。
- **`v0.2.2` で出し直した**（決定6: 公開済みのタグは付け替えず、不具合は次の版で出す）。`package.json` を `0.2.2` に上げ（`6806fb9`）、タグ `v0.2.2` を `origin`・`upstream` へ push。**リリース実行（run `43388823459`）は 3 ジョブとも成功**し、成果物 7 点（Setup.exe、`.nupkg`、`RELEASES`、`.dmg`、`.zip`、`.deb`、`.rpm`）が付いた。リリースはいったんドラフトに留め、確認のうえ **2026-11-13 に公開した**（`gh release edit --draft=false --latest`、公開日時 10:56 UTC、`Latest` は `v0.2.0` から `v0.2.2` に移った）。公開した成果物を実機にインストールして起動する確認は未実施（CI のビルド成功のみ確認）。

## v0.2.3・v0.2.4（2026-11-14 追記）

`v0.2.2` の `W-CPP-FALLBACK` の原因調査と修正の経緯は、計画ノートの[[TECSCDE-DT-EL実装 — V0.2.1 実装計画 — 2026-11-12#v0.2.3（取り下げ）・v0.2.4（公開済み、2026-11-14）|v0.2.3（取り下げ）・v0.2.4]]に書いた。

- `v0.2.3`（`1d3ba50`）: DLL 衝突の修正（`04c09ab`）を入れた。実機で、`W-CPP-FALLBACK` は 11 件から 7 件に減ったが、`W-C-TYPE-UNRESOLVED` が 51 件から 206 件に増えた。公開せず取り下げた（ドラフトのリリースは削除、タグは残した）。
- `v0.2.4`（`cf18c91`）: `cppArgs` 未設定のとき `-E -DTECSGEN` を既定にする修正（`f596b06`）を入れた。実機で、`W-CPP-FALLBACK` と `W-C-TYPE-UNRESOLVED` が 0 件になり、`.gch` も作られなくなったことを確認して、公開した（2026-11-14 23:40 UTC、`Latest`）。
- 検証: 変更後の `vitest` は 1,208 件成功（5 件スキップ）。この環境では、`npm run` が `tsc` を見つけられない（PATH の形式）ため、型検査・ビルド・`vitest`・`dependency-cruiser` を `node` から直接実行した。

## v0.2.5（2026-11-15 追記）

`v0.2.4` に残っていた `W-PLUGIN-TYPE-LOAD` と `W-MISSING-JOIN-TARGET` の調査と修正の経緯は、計画ノートの[[TECSCDE-DT-EL実装 — V0.2.1 実装計画 — 2026-11-12#v0.2.5（公開済み、2026-11-15）|v0.2.5]]に書いた。

- 原因は、tecsgen の子プロセスの `gcc` も、PATH 上の `Meld\` の DLL と衝突して静かに失敗していたこと。C プリプロセッサのディレクトリを tecsgen の子プロセスの PATH の先頭へ足して直した（`3d32584`）。
- `v0.2.5`（`69c9bda`）を実機にインストールし、診断ログの警告が 0 件（`W-PLUGIN-TYPE-LOAD`、`W-MISSING-JOIN-TARGET` とも）になったことを確認して公開した（2026-11-15 01:49 UTC、`Latest`）。
- 検証: `vitest` は 1,211 件成功（5 件スキップ）、型検査と `dependency-cruiser` は通過。実機の PATH（`Meld` が先）で、実際の tecsgen を新しい `TecsgenRunner` 経由で実行し、修正前は終了コード 1・エラー 45 件、修正後は終了コード 0・エラー 0 件を確認した。
