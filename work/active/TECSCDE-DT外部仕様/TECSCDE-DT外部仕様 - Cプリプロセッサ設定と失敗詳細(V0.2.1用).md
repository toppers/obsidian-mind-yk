# TECSCDE-DT外部仕様 — Cプリプロセッサ設定と失敗詳細（V0.2.1）

[[TECSCDE-DT外部仕様]] 第2章（動作環境）、第3章（画面構成）、第8章（CDL連携）、第9章（エラーと警告）のV0.2.1向け拡張仕様です。

## 1. 目的と背景

CDL 内に `import_C("xxx.h")` が記述されている場合、TECSCDE は C 言語ヘッダから関数シグニチャや構造体・型定義（`typedef`, `struct`）を抽出するために C プリプロセッサ（CPP）を実行します。

V0.2.0 までは以下の課題がありました：
1. **失敗原因が不明**: プリプロセスが失敗した際、警告 `[W-CPP-FALLBACK]` が表示されるのみで、「コマンド自体が見つからない（未検出）」のか「インクルードヘッダ不在などの構文・プリプロセスエラー（非ゼロ終了）」なのか、具体的なエラー内容が利用者に伝わりませんでした。
2. **設定の確認・指定ができない**: 実行されるコマンドは既定値（`gcc -E -DTECSGEN`）または CDL ファイル内の `__tool_info__("tecsgen")` に固定されており、利用者が画面から現在使用されているコマンドを確認したり、実行ファイルへのパスやコマンドラインオプションを直接指定することができませんでした。

本仕様では、プリプロセッサの実行失敗原因を明確に通知するとともに、**実行ファイルの決定理由（ユーザ直接指定・自動検出・フォールバック）およびフルパスを保持してパネルエラーに明示**し、情報ダイアログから**ファイルダイアログ等を用いて C プリプロセッサの実行ファイルパスおよびコマンドラインオプションを表示・直接指定可能**とします。

---

## 2. 外部仕様

### 2.1 C プリプロセッサ実行失敗原因の明確化（第9章 9.2 / 9.4 拡張）

`import_C` のプリプロセスに失敗して未展開テキストへフォールバックした際に出力される警告 `W-CPP-FALLBACK` について、失敗の分類、具体的な原因、**Cプリプロセッサ実行ファイルへのフルパス**、および**決定理由（ユーザ直接指定・自動検出・フォールバック）**をメッセージ本文に含めます。

| 失敗種別 | 判定条件 | 提示するメッセージ形式 |
|---|---|---|
| **コマンド未検出** | 指定された実行可能ファイルが PATH または設定パスに存在しない（ENOENT） | `Cプリプロセッサ '${command}'（フルパス: ${fullPath}、決定理由: ${決定理由}）が見つからないため、'${headerPath}' は未展開のまま型を抽出しました（パス設定またはインストールを確認してください）` |
| **プリプロセス失敗** | プリプロセッサが非ゼロの終了コードで終了した（ヘッダ不在、マクロ構文エラー等） | `Cプリプロセッサ '${command}'（フルパス: ${fullPath}、決定理由: ${決定理由}）の実行が失敗したため（終了コード ${code}: ${stderr抜粋}）、'${headerPath}' は未展開のまま型を抽出しました` |
| **起動・実行不能** | タイムアウト（30秒超過）または引数形式不正（引用符の閉じ忘れなど）・権限なし（EACCES・EPERM）などのプロセス起動失敗。**終了コードは無く、「終了コード 1」を作って表示しない**（2026-11-17 決定、v0.2.6 段2、コミット `15e811d`、三者相違一覧 8-3） | `Cプリプロセッサ '${command}'（フルパス: ${fullPath}、決定理由: ${決定理由}）を起動・実行できなかったため（${詳細}）、'${headerPath}' は未展開のまま型を抽出しました` |

- **フルパス（`${fullPath}`）の表示**:
  - 自動検出やユーザ指定により解決された実行ファイルの絶対パス（例: `C:\msys64\ucrt64\bin\gcc.exe`）を表示します。
  - PATH 上に見つからず未検出となった場合は、解決を試みた対象または `未検出` を明記します（例: `未検出 (PATH上)`、ユーザ指定パスが存在しない場合はその指定パス）。
- **決定理由（`${決定理由}`）の表示**:
  - `ユーザ直接指定`: アプリケーション設定（`settings.json` の `cppPath`）または CDL / オプションで明示指定された場合
  - `自動検出`: PATH 上の `*gcc` 探索により自動検出された場合
  - `フォールバック`: PATH 上に候補が見つからず既定値（`gcc`）が採用された場合
- **表示例**:
  - *フォールバック時（ENOENT）*:
    `Cプリプロセッサ 'gcc'（フルパス: 未検出 (PATH上)、決定理由: フォールバック）が見つからないため、'kernel.h' は未展開のまま型を抽出しました（パス設定またはインストールを確認してください）`
  - *自動検出時（非ゼロ終了）*:
    `Cプリプロセッサ 'arm-none-eabi-gcc'（フルパス: C:\ArmGNU\bin\arm-none-eabi-gcc.exe、決定理由: 自動検出）の実行が失敗したため（終了コード 1: fatal error: stdio.h: No such file or directory）、'sample.h' は未展開のまま型を抽出しました`
  - *ユーザ直接指定時（ENOENT）*:
    `Cプリプロセッサ 'C:\mytools\gcc.exe'（フルパス: C:\mytools\gcc.exe、決定理由: ユーザ直接指定）が見つからないため、'target.h' は未展開のまま型を抽出しました（パス設定またはインストールを確認してください）`
- **抜粋の扱い**: 標準エラー出力（`stderr`）に複数行のエラーが出力された場合は、先頭の有効行を中心に最大 200 文字程度を抜粋します。
- **1行1件規則の遵守**: 抜粋内に改行が含まれる場合でも、診断ログ（9.5節、監査#68）の1行1件原則に従い、改行文字は可逆エスケープされます。

### 2.2 C プリプロセッサの表示と指定（第3章 3.8.1 / 第8章 8.1.2 拡張）

ツールバーの「情報」ボタンから開く情報ダイアログ（3.8.1）に、C プリプロセッサの設定セクションを追加します。ユーザは手入力だけでなく、**ネイティブのファイルダイアログを用いて直感的に実行ファイルを指定**できます。

#### 画面項目
1. **現在有効なコマンドラインの表示**:
   - 解決された実行ファイルパスとオプションを結合した実行コマンド全体を表示します。
   - コマンドの決定理由（出どころ）および解決されたフルパスを併記します：
     - `ユーザ直接指定 (CDL: __tool_info__ / .tecsgen-opts)`
     - `ユーザ直接指定 (設定: settings.json)`
     - `自動検出 (PATH上の *gcc)`
     - `フォールバック (既定値: gcc)`
2. **実行ファイルへのパス (`cppPath`) 入力欄とファイルダイアログ参照**:
   - C プリプロセッサの実行可能ファイル（例: `gcc`, `gcc.exe`, `arm-none-eabi-gcc.exe`, `clang`, `C:\msys64\ucrt64\bin\gcc.exe` 等）を指定する 1 行入力欄。
   - **「参照…」ボタン（ファイルダイアログの起動）**:
     - ボタンを押下すると、OS ネイティブのファイル選択ダイアログを表示します。
     - **ダイアログ仕様**:
       - タイトル: `C プリプロセッサ実行ファイルの選択`
       - フィルタ: Windows の場合は実行可能ファイル（`*.exe;*.cmd;*.bat`、すべてのファイル `*.*`）
       - 初期ディレクトリ: すでにパスが入力されていればその親ディレクトリ、未入力の場合は現在有効な実行ファイルのディレクトリ、それも無ければシステム標準の実行ファイルパス
     - ダイアログで実行ファイルを選択して「開く」を押下すると、そのファイルの**絶対パス（フルパス）**が `cppPath` 入力欄に自動設定されます。
     - キャンセルした場合は現在の入力値が維持されます。
3. **コマンドラインオプション (`cppArgs`) 入力欄**:
   - プリプロセス時に渡す引数列（例: `-E -DTECSGEN -I C:/include` 等）を指定する 1 行入力欄。
   - **初期値**: 情報ダイアログ上の本設定項目の初期表示値として `-E -DTECSGEN` を利用します。
   - **既定値**（2026-11-14 変更）: 一度も保存されていない（未設定の）場合は、実行時に `-E -DTECSGEN` を使います。初期表示値と同じです。**空欄のまま保存された場合は**、利用者が意図して付けなかったものとして、C プリプロセッサにオプション指定を渡しません（実行ファイル単体で起動します）。
4. **保存・解除操作**:
   - **「設定を保存」ボタン**: 入力された `cppPath` および `cppArgs` を `settings.json` へ即時保存します。
   - **設定の解除**: パス欄を空にして保存した場合、明示設定が解除され、後述の自動探索・既定値に戻ります。

### 2.3 設定の優先順位（解決規則）と決定理由・フルパスの保持（第2章 2.5 拡張）

C プリプロセッサのコマンド解決は以下の優先順位に従います。また、解決時に**Cプリプロセッサ実行ファイルの決定理由（ユーザ直接指定・自動検出・フォールバック）およびフルパス**を保持し、情報ダイアログの表示およびエラー発生時の診断パネルメッセージ（2.1節）に反映します：

1. **CDL / プロジェクト固有の指定（最優先）**:
   - `.tecsgen-opts` 内の `-c` / `--cpp` オプション（2026-11-17 決定: `import_C` の展開にも使う。Generate・コマンドコピーと同じ値で展開するため）
   - 開いている CDL 内の `__tool_info__("tecsgen")` に記述された `cpp`
   - 両方あるときは、**`.tecsgen-opts` の `-c` を優先する**（Generate の現状と同じ。実際の tecsgen が両方あるときにどちらを採るかは未確認、TBC）。
   - どちらの値も、**引数込みの完全なコマンド**として使い、`cppArgs` は付け足さない。
   - **決定理由**: `ユーザ直接指定`
2. **明示的に指定されたCプリプロセッサ実行ファイルへのパス（アプリケーション設定）**:
   - `settings.json` の `cppPath`（利用者が設定ダイアログのファイルダイアログ選択や手入力で明示指定した実行ファイルへのフルパスまたはコマンド名）。
   - コマンドラインオプションは `cppArgs`。未設定の場合は、既定値として `-E -DTECSGEN` を使います（2026-11-14 変更。ダイアログ上の初期値と同じ）。空欄で保存された場合は、C プリプロセッサにオプション指定を渡しません。
   - **決定理由**: `ユーザ直接指定`
3. **既定の探索・解決規則（未指定時 / 自動検出）**:
   - `PATH` 上の実行ファイルの中から、ファイル拡張子（`.` を含む部分、例: `.exe`）を除いたファイル名の末尾が、**大文字・小文字の区別なく `gcc` であるもの**を探索して採用します。
     - 対象例: `gcc`（`gcc.exe`）、`arm-none-eabi-gcc`、`x86_64-w64-mingw32-gcc`、`riscv64-unknown-elf-gcc`、`GCC.EXE` 等。
     - 対象外例: `gcc-ar`、`g++`、`gcc-nm`、`clang`（末尾が `gcc` ではない）。
   - **探索優先順位**:
     1. 単体の `gcc`（`gcc.exe`）が存在する場合はそれを最優先とします。
     2. 単体 `gcc` がない場合、`PATH` の登録ディレクトリ順に走査し、最初に見つかった対象実行ファイル（拡張子除き末尾が `gcc` のもの）を採用します。
   - 採用された実行ファイル名（またはパス）に、オプション（`cppArgs` が設定されていればその引数列、未設定なら `-E -DTECSGEN`、空欄で保存されていればオプションなし）を組み合わせて有効コマンドを構成します。
   - **決定理由**: `自動検出`
4. **フォールバック（候補未検出時）**:
   - `PATH` 上に該当する実行ファイルが1件も見つからない場合は、フォールバックとして `gcc`（`cppArgs` が設定されていればその引数列、未設定なら `-E -DTECSGEN`、空欄で保存されていればオプションなし）を使用します（実行時に未検出として通知）。
   - **決定理由**: `フォールバック`

※なお、インクルード探索ディレクトリ（`-I`）は、上記の基本コマンドラインに対して、従来通りプロジェクトの探索パス群が自動的に末尾に追加されます。
