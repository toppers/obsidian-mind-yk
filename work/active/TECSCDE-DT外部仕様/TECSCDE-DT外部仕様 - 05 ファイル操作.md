## 5. ファイル操作

### 5.1 ファイル形式

[[work/active/TECSCDE外部仕様/TECSCDE外部仕様 - 05A ファイル操作（前半）|TECSCDE外部仕様5.1節]]の保存形式と往復保持方針を踏襲する。保存形式は`.cde`の1種類のみで、中身はCDLそのもの（`__tool_info__("tecsgen")`・セル定義・`__tool_info__("tecscde")`の3ブロック）である。なお`.tecsgen-opts`（5.3節）は読み込み専用の入力形式で、本ツールは書き出さない（保存形式ではない）。`base_dir`・`import_path`・`cpp`は値を保持して書き戻し、無効であっても読み込みを拒否しない。一方、デスクトップ版は読み込み・生成時にこれらを**解釈・検証する**——`base_dir`・`import_path`は参照先の自動追跡に用い、`cpp`はCプリプロセッサの起動候補として用いる（第8章8.1節）。解釈結果によって保存値を黙って変更しない。また、旧世代のtecscde（Ruby版）が書く`__location_information__ { … }`ブロック（`__cell__`・`__join__`・`HBar`・`VBar`を含む）は、**エラーにせず、読み込んで無視する**（2026-10-22改訂。以前は[[work/active/TECSCDE外部仕様/TECSCDE外部仕様 - 05A ファイル操作（前半）|TECSCDE外部仕様5.1.2節]]にならい「非対応」としていた）。ブロック内の位置情報は図に反映しない。無視するだけで、保存時にも書き換えず、元の位置にそのまま残る（第10章10.1節 #3c）。**入力の文字コードについては、ブラウザ版の「UTF-8に限る」をデスクトップ版には適用せず、次の規定に改める**（2026-10-21、実装に合わせて改訂。第10章10.1節 #3b）。

**入力の文字コード**: ファイルを読み込むとき（開く、`import`の自動追跡、`.tecsgen-opts`、Plugin生成CDL）は、バイト列をまず**UTF-8**として厳密に復号し、できなければ**Shift_JIS**、それもできなければ**EUC-JP**として復号する。復号できた文字コードの種類は、利用者に通知しない。三つとも厳密な復号に失敗した場合は、通常CDLは読み込み失敗、参照先は「参照先を解決できない」（`W-UNRESOLVED-REF-FILE`、第9章9.2節）、Plugin生成CDLは取り込み失敗として扱う。ただし、**`.tecsgen-opts`だけはUTF-8で読み直して解析を続ける**（2026-11-07、監査#7。DT-EL内部仕様7.8節・7.7.4節に合わせた例外）。この読み直しでは不正なバイト列を置換文字にするため、元の文字列が復元できる保証はない。ファイル自体を読めないI/Oエラーまで無視する規定ではない。保存・書き出しは**常にUTF-8**で行い、元のファイルがShift_JISやEUC-JPであっても、保存するとUTF-8になる（元の文字コードで保存する手段は提供しない）。Generate（実行）では、保存済みのUTF-8のファイルをtecsgenへ渡す。**既知の限界**: 文字コードの判定は復号の成否によるため、Shift_JISとEUC-JPのどちらにも復号できる短いデータなどで、誤った文字コードで復号して文字化けすることがある。この判定を利用者が指定する手段は提供しない。

### 5.1.x 可変長配列の要素数の保存（2026-11-08決定）

未結合末尾要素を含む可変長配列の個数を、`__tool_info__("tecscde")`のJSONに追加する`array_elements`へ保存する。配列の各項目は、`cell`（CDLのスコープに基づく完全修飾セル名）、`direction`（`call`または`entry`）、`port`（添字を除く宣言ポート名）、`element_count`（1以上の整数）を持つ。セルインスタンスごとの情報であり、セルタイプ全体へ適用しない。

```json
"array_elements": [
  { "cell": "::Region::Cell", "direction": "call", "port": "cPort", "element_count": 4 }
]
```

- 保存対象の可変長呼び口・受け口ごとに現在の個数を記録する。保存先は所有セルの定義元ファイルであり、他ソースの同名セルへ転用しない。受け口の個数情報と、その受け口を参照する呼び口側の結合代入は、それぞれの所有元へ保存する。読み取り専用・Plugin生成ソースを書き換えない。
- 個数情報がある配列は、`max(CDLの結合から必要な要素数, element_count, 1)`個を復元した後、位置情報を適用する。受け口では、その要素を参照する全結合の添字も必要数へ反映する。添字付き位置情報だけを個数の根拠にしない。架空の結合代入は追加しない。
- 情報のない旧ファイルでは従来の導出規則を維持する。固定長は宣言の`N`を優先する。非配列・未解決・存在しないセルやポートへの指定、不正な個数は警告して適用しない。未解決時の原情報は保持する。個数は安全な整数かつモデルで扱える範囲とし、範囲外を黙って切り詰めない。
- 外部編集で型・配列種別が変わった場合は、現在の宣言と照合する。同じ可変長宣言で結合だけが減った場合、保存個数を尊重する。外部で要素数を縮めるには個数情報も変更・削除する。
- 挿入・削除は個数情報と要素位置を同じ編集で更新する。個数だけの変更も未保存判定とUndo/Redoの対象である。削除済み要素の位置情報や古い個数を原文から復活させない。
- 既存の3ブロック構成を維持する追加キーとし、未知の情報の往復保持を継続する。旧ツールでの個数復元は保証しない。形式版の既存規則を維持し、旧ツールとの実際の読み込み・往復互換性は別途検証する。

### 5.2 新規作成

[[TECSCDE外部仕様]]5.2.2の規定（ツールバーの操作として提供、既定用紙を適用、ファイル名は保存まで決めない）を踏襲する。デスクトップ版では保存先を決めずに新規作成を続けられる点は変わらないが、明示的に「名前を付けて保存」した時点でファイルパスが確定する。

### 5.3 開く（読み込み）

- 本節の本文は[[TECSCDE-DT外部仕様 - 05A 開く（読み込み）|05A 開く（読み込み）]]へ移した（2026-10-22、25KB閾値による逐語分離。内容は変更なし）。通常CDLの追加読み込み、リージョン木とセル所属の復元、`.tecsgen-opts`、システム定義CDL（`-S`）、ファイルブラウザ経路を規定する。

**主ファイルなし・空セッションの復元（2026-11-09）**: 明示的な起動入力がない場合、「有効な前回セッションがあるか」と「主ファイルのパスがあるか」を別々に判定する。主ファイルなしの有効なセッションは復元対象であり、追加CDLがあれば空の主文書と追加CDLを復元し、一つを主へ昇格させない。追加CDLもなければ空状態の復元成功とし、サンプルへ置き換えない。

サンプルを使うのはセッション未設定・不正、またはセッションに保存された主／追加CDLの読み込みが失敗した場合である。オプションファイルだけの失敗は保存済み探索パスへの回復規則とし、通常import先の未解決も別の警告処理とする。前回の未保存本文・選択・履歴を復元する規定ではない。消去後の空主文書・保持した参照集合を、未保存本文の復元対象外という理由で丸ごと除外しない。CLI／関連付けの明示入力が失敗した場合の処理は、その入口の規則を維持し、セッション復元失敗と混同しない。

**復元時のopts再解析と探索パス（2026-11-09、三者監査#8）**: 保存されたoptsを再解析できた場合、その結果の探索パスとシステム定義ディレクトリを組として採用する。探索パスが空でも成功した解析結果を優先し、古い保存値へ戻したり連結したりしない。optsを使わない場合、または読込・解析に失敗した場合だけ保存済み探索パスへ戻し、システム定義ディレクトリは空にする。

探索パスの記述順と重複を保持し、相対値は保存されたoptsの親ディレクトリを基点とする。基点がない相対値を起動ディレクトリで推測しない。採用値はCDLのimport解決前に使い、復元成功後のセッションにも同じ値を保存する。opts内のCDL列挙が変わっても、保存済みの主ファイル・参照集合・読み込み順を置き換えない。「実行(Generate)」時の再解析は別の既存規則とする。

### 5.4 保存・名前を付けて保存

最大の差分がある節。ネイティブファイルシステムアクセスにより、**「上書き保存」が文字どおりの意味で実現できる**。

| 操作 | ブラウザ版（[[TECSCDE外部仕様]]5.4.2） | デスクトップ版（本書） |
|---|---|---|
| 保存 | 直近の保存先が分かればFile System Access APIのハンドルへ書き戻す。分からなければダウンロードにフォールバック | **変更された通常CDLをそれぞれの元のファイルパスへ上書き保存する**（Electron: fs、Tauri: fsプラグイン）。主ファイル以外の変更を主ファイルへ混ぜない |
| 名前を付けて保存 | 保存先を指定してダウンロード | OSネイティブの保存ダイアログ（`dialog.showSaveDialog`等）でパスを選択し、そのパスへ直接書き込む |

書き込み中に失敗しても既存データを失わない（[[TECSCDE外部仕様]]5.4.2の要件）という方針は変わらないが、実現方法が異なる——ブラウザ版はダウンロードという操作の性質上自然に満たされていたが、デスクトップ版は**一時ファイルへ書き込んでから元のファイルへリネームする**（atomic rename）等、明示的な実装上の配慮が必要になる。これは実装方式に関わらずElectron・Tauriいずれでも同じ手法（OSのファイルシステムAPIレベルのアトミックリネーム）で実現できるため、本仕様の要件とする。

用紙の既定値（A4横）は[[TECSCDE外部仕様]]5.4.2と同一。ただし、用紙の指定がないファイルを読み込むときは、自動配置したセルが収まる最小の用紙（横）を選ぶ（[[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 - 05B CDLファイル一覧の作成と自動配置|5.3.x]]項目7、2026-11-03）。

**保存完了と未保存状態（2026-11-08、監査#21）**: 保存成功したソースについて、実際に書き込んだ文書状態だけを保存済みとして記録する。複数ソースの一部が失敗した場合、失敗したソースまで保存済みにしない。保存中に新しい編集が加わった場合、その編集は未保存として残す。「名前を付けて保存」の取消・失敗では、現在のパスと保存済み状態を変更しない。判定の詳細は5.7節の規定に従う。

**重複保存の順序（2026-11-08、三者監査#3）**: 同じ保存先に複数の保存が要求された場合、アプリケーションが受け付けた順に処理し、古い保存が新しい保存の後で書き戻されないようにする。ある保存が失敗しても、後続の保存を一律に失敗扱いにせず個別に処理し、最後に実際に保存成功した内容を保存済み状態とする。異なる保存先の結果を、互いの保存順の根拠にしない。保存先の変更後に届いた旧保存先への完了通知で、現在の保存済み状態を戻さない。

### 5.6 エクスポート

エクスポート形式の判断がブラウザ版と変わる。

| 形式 | ブラウザ版（[[TECSCDE外部仕様]]5.6.2） | デスクトップ版（本書） |
|---|---|---|
| SVG | 対応（第一形式） | 対応（変更なし） |
| PNG | 対応（SVG経由のラスタライズ） | 対応（変更なし） |
| PDF | **非対応**（依存ライブラリなしと両立しないため） | **対応する**（2026-10-22決定）。OSの印刷機構（Electron: `webContents.printToPDF`、Tauri: WebViewの印刷API）でPDFを生成する。外部のPDFライブラリは使わない。向き（横／縦）は用紙設定に従う |

出力範囲選択（用紙に合わせる／内容に合わせる）・出力先選択・用紙の縦向き対応は[[TECSCDE外部仕様]]5.6.2の規定を踏襲する。

**出力の内容（2026-10-22決定）**: エクスポートは、画面に見えているとおりの内容を出力する。シグニチャ名の表示とリージョンのフィルタ（非表示）は、画面の設定をそのまま引き継ぐ（出力時に選ばせない）。選択状態とグリッドは含めない。出力範囲が「用紙に合わせる」のときは、現行版（Ruby/GTK版）と同じく、内容領域の外周に矩形の枠線を描き、用紙の右下に編集中のファイル名（未保存なら`untitled`）を描く。「図の内容に合わせる」のときは、枠線もファイル名も描かず、図だけを出力する。エクスポートの入口は、ツールバーのボタンのみとする（メニューは設けない）。形式は、SVG・PNG・PDFから選ぶ。

### 5.7 終了時の扱い

**未保存判定（2026-11-08、監査#21）**: 現在の保存対象の文書状態を、最後に正常保存した状態（新規空図は初期空状態）と比較する。ソースごとに保存済み状態を保持し、一つでも保存対象の変更が残れば全体を未保存とする。保存日時等の自動生成注記、選択・検索・表示フィルタ・ズーム・パン・診断更新だけで未保存にしない。

Undo／Redoで保存対象が保存済みと同じ状態へ戻った場合は、未保存表示を解除できる。**履歴の長さ・操作件数が保存時と同じという理由だけで解除してはならない。** 保存→Undo→別内容の編集によって同じ履歴長になっても、保存内容と異なれば未保存とする。別の操作列で同じ保存対象の状態へ戻った場合も、状態比較に従う。

**契約の対応（2026-11-08、三者監査#3）**: 5.4節の保存結果と本節の未保存判定は一つの契約である。保存開始時の状態を固定し、成功したソースだけその状態を保存済みにする。保存完了時点の文書全体を無条件に保存済みにしない。実装方式はDT-EL内部仕様7Jの保存チケット・ソース別チェックポイント・保存先別の順序管理に対応する。これは採用済みの要求であり、現行コードの履歴長判定を正とする規定ではない。

保存開始時点の状態と保存完了時点の状態を混同しない。保存中は完了を先取りして未保存表示や終了保護を解除せず、終了操作では保留中の保存結果を待ってから現在の未保存状態を再評価する。部分失敗や保存後の新編集が残る場合も、終了・新規作成・読み込み前の確認を省略しない。タイトル、ステータス、破棄確認は同じ判定を使う。

[[TECSCDE外部仕様]]5.7.2の方針（未保存の変更がある状態で離れようとした場合に確認を求める、ステータス表示・タイトルに未保存を示す）を踏襲する。実現手段は第3章3.1節で述べたとおりウィンドウを閉じる直前のイベントに置き換える。

**終了時の確認（2026-10-22改訂）**: 未保存の変更がある状態でウィンドウを閉じようとした場合（OSの閉じるボタン、メニューの終了、macOSのCmd+Qなど、ウィンドウを閉じる経路すべて）、OSネイティブの確認ダイアログで「保存せずに終了」または「キャンセル」を選ばせる。「キャンセル」を既定とし、キャンセルすればウィンドウは閉じず、編集を続けられる。保存してから終了したい場合は、利用者が先に「保存」操作を行う（新規作成・読み込み直前の破棄確認と同じ2択）。未保存の変更が無いときは、確認せずに閉じる。OSのシャットダウンなど、アプリが止められない終了は対象外とする。確認の手段にブラウザの`beforeunload`は使わない——デスクトップ版の実機で、`beforeunload`による方式は確認なしに終了し、未保存の変更が失われたため。

**保存中の終了判定（2026-11-09、三者監査#4）**: 通常の終了操作では、以前通知した「未保存なし」だけを理由に閉じない。新しい編集・保存要求・文書切り替えの適用を一時停止し、開始済みの保存について、書き込みと保存済み状態への結果反映の両方を待ってから現在の未保存状態を確認する。この待機中も、開始済みの保存結果の処理は進める。

現在の保存状態を確認できない場合は「保存状態を確認できない」旨を示し、同じ「保存せずに終了」「キャンセル」で確認する。応答待ちのタイムアウトを保存成功とみなしたり、受理済みの書き込みを待たずに閉じたりしない。キャンセルでは通常の編集へ戻し、待機中に正常完了した保存結果は維持する。連続した終了操作で確認を重ねず、古い問い合わせへの応答で後の終了操作を許可しない。アプリが止められないOS終了は前段の対象外規則に従う。

**新規作成・読み込み直前の破棄確認（2026-09-22追加）**: [[TECSCDE外部仕様]]5.7.2の表が定める「新規作成・読み込みは実行前に破棄の確認を求める」（5.2.2・5.3.2）は、デスクトップ版でも維持する。実現手段は3.6.2節が禁じるブラウザ標準の`confirm`ではなく、OSネイティブの確認ダイアログ（Electron: `dialog.showMessageBox`、Tauri: `dialog`プラグインの`confirm`/`ask`）とする——3.6.2節の禁止は「表示内容を制御できないブラウザ標準API」を指し、OSネイティブAPIは対象外（`dialog.showSaveDialog`等の既存採用と同じ扱い）。
