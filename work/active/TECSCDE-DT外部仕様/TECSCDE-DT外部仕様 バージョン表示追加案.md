# TECSCDE-DT外部仕様 — アプリ自身の版の確認手段（追加案）

**状態: 手段を採用し、仕様に反映して、V1〜V3 を実装済み（2026-11-01）。**番号は、既存の3.6（ダイアログ）・3.7（モードとカーソル）と重ならないよう、3.8 にした。採用したのは、**① 版の情報源の一本化 → ② バージョン情報ダイアログ → ③ 診断ログの先頭行に版**。余裕があれば **④ コマンドライン `--version`**（Windows では出力が見えない可能性があり、優先度は低い）。ステータスバー・ウィンドウタイトルへの常時表示は採らない。

## 背景（コードを読んで確認、実機では未確認）

- いまは、画面にも、コマンドラインにも、アプリ自身の版を出す手段がない。
- 版は2か所に別々に書かれている。
  - `package.json` の `version`（`0.1.0`）。Forge のインストーラ、自動更新、GitHub のリリースタグ（`v0.1.0`）が使う。
  - `src/renderer/model/tool-info-types.ts` の定数 `TECSCDE_TS_VERSION`（`"0.1.0"`）。保存する `.cde` の `__tool_info__` に `tecscde_version` として書く。
- 2つは手でそろえないとずれる。`package.json` を上げても、保存する `.cde` に書かれる版は変わらない。
- `.cde` の形式の版 `CDE_FORMAT_VERSION`（`0.1.0.0`）は別立て。元の Ruby 版も、ツール版（0.5.1.0）と形式版（0.5.0.0）が別立てだった（[[work/active/TECSCDE外部仕様/TECSCDE外部仕様 - 05A ファイル操作（前半）|TECSCDE外部仕様 5A]]）。本案は、形式の版は別立てのまま変えない。

## 提案する外部仕様

### ① 版の情報源（第2章 2.5 の近く、または第10章）

- アプリケーションの版は、**`package.json` の `version` を唯一の情報源**とする。保存する `.cde` の `tecscde_version`、バージョン情報ダイアログ、診断ログ、インストーラ、リリースタグは、すべてこの版から決まる。
- 形式の版（`cde_format_version`）は、アプリケーションの版とは別に管理する（互換性の判断に使うため）。

### ② 3.8 バージョン情報

1. ツールバーに「**情報**」ボタンを置く。押すと、バージョン情報のダイアログ（モーダル）を開く。
2. ダイアログに次を表示する。
   | 項目 | 内容 |
   |---|---|
   | アプリケーションの版 | `package.json` の版（例: `0.1.0`） |
   | ビルド | コミットの短縮ハッシュ。ビルド時に取得できなかったときは `unknown` |
   | 形式の版 | `cde_format_version`（例: `0.1.0.0`） |
   | tecsgen | 起動時の確認で読み取れた版。確認できていないときは「未確認」（見つからなかったときも「未確認」）と、使われている起動コマンド |
   | 実行環境 | Electron・Chromium・Node の版、OS の種類 |
3. 「**コピー**」ボタンで、上の内容を、1項目1行のテキストとしてクリップボードに入れる（不具合報告に貼る用）。
4. 閉じるボタン、Esc で閉じる。

### ③ 診断ログの先頭行（9.5.2 の規定5を変更）

- 先頭行を `# TECSCDE 診断ログ（起動: <ISO 8601 の日時>、版: <アプリケーションの版>）` にする。

### ④ 起動引数 `--version`（余裕があれば）

- `--version` を付けて起動すると、アプリケーションの版を標準出力に出して、画面を開かずに終了する。
- 注意: Windows のパッケージ版（GUI アプリ）は、コンソールに出力できないことがある。確認する場合は、バージョン情報ダイアログを使う。Electron や Chromium が `--version` を自分で処理する可能性もあるため、衝突するなら別名（`--app-version`）にする（どちらも未確認）。

## 提案する設計（内部仕様）

- **一本化**: `scripts/build-renderer.mjs` の esbuild の `define` で、`package.json` の版とコミットの短縮ハッシュ（`git rev-parse --short HEAD`。取れなければ `unknown`）を、画面側のコードに埋め込む。`TECSCDE_TS_VERSION` の手書きの値をやめ、埋め込まれた値を使う。vitest にも同じ `define` を渡す。main 側は `app.getVersion()`（= `package.json`）をそのまま使う。
- **実行環境の版**: preload に、読み取り専用の `versions`（`process.versions` の Electron・Chromium・Node、`process.platform`）を追加する。
- **tecsgen の版**: 起動時の確認（9C 章）の結果は、診断ログの1行にしか使っていない。確認できた版と、使われた起動コマンドを、`AppStore` に保持する。
- **ダイアログ**: `<dialog>`。既存の `celltype-details.ts` と同じ作りにする。「コピー」は、既存の `ClipboardGateway` を使う。
- **診断ログ**: `LogService` のコンストラクタに版を渡し、先頭行に入れる。
- **`--version`**: main の起動の最初に `process.argv` を見る。

## 論点（既定で進める案）

| # | 論点 | 案 |
|---|---|---|
| 1 | ボタンの名前 | 「情報」（日本語 UI。ほかのボタンは日本語） |
| 2 | 開発ビルドの表示 | 版のあとに `+<ハッシュ>` は付けない。ビルドの項目に出すだけ（版の文字列は `package.json` のまま） |
| 3 | コピーの書式 | `項目名: 値` の1行ずつ。Markdown にはしない（貼り先を選ばない） |
| 4 | 自動更新との関係 | 変更しない（自動更新は `package.json` の版を使う。一本化で、表示される版と更新が見る版が一致する） |

## 未確認・リスク

- コミットのハッシュは、ビルドする環境（CI を含む）が Git の作業ツリーで動く前提。配布物の CI（`release.yml`）は `actions/checkout` を使うため、取れる見込み（未確認）。
- `process.versions` を preload から渡せるかは、Electron の `sandbox` の設定次第（コードで確認する）。

## 実装の状況（2026-11-01）

| 単位 | 内容 | PR |

実装中に、案から変えた点が2つある。
- `TecsgenVersionResult` の `command` は、省略可の項目にした（既存の呼び出し側と、既存のテストを壊さないため）。mainは常に付ける。
- `LogService` のコンストラクタの引数は `dirs, appVersion, now` の順で、版は必須。

実機（Electron）で確認したこと: 「情報」ボタンでダイアログが開き、5項目が表示される／「コピー」の中身が表示と一致する／Esc で閉じる／診断ログの先頭行に版が入る。画面の見え方（レイアウト・配色）を利用者の目で確認すること、macOS・Linux での表示は未確認。
