## 2. 動作環境

### 2.1 現行版（Ruby/GTK版）

[[TECSCDE外部仕様]]2.1節と同一。既存実装 tecscde V0.5.1 の動作環境であり、変更しない。

### 2.2 デスクトップ版（Electron/Tauri両対応）

| 項目 | 内容 |
|------|------|
| 実装言語 | TypeScript（Electron）または Rust（Tauri）。UI層はいずれもHTML/SVG/DOMの標準APIで構成し、特定のUIフレームワークに依存しない |
| 動作確認OS | Windows／macOS／Linux。Electron・Tauriいずれも3OS対応であるため、OS非依存を維持する |
| 依存ライブラリ／ランタイム | ビルド・配布形態（Electron: Chromium同梱、Tauri: OSネイティブWebView利用）はフレームワークに委ねる。UI・描画は標準のHTML/SVG/DOM APIのみを用い、特定のUIフレームワーク・描画ライブラリに依存しない。**CDLの構文解析にのみtree-sitterランタイムと2つの文法（CDL・C宣言）を用いる**という[[TECSCDE外部仕様]]2.2節の例外も踏襲する |
| ツールバージョン | [[TECSCDE外部仕様]]2.2節と同一。tecsgen V1.3.1.0以降が受理するCDLを入出力対象とする。tecsgenの版は起動時に確認し、古い場合は警告する（第8章8.4.2節） |

実行形態は**ネイティブデスクトップアプリケーション**である。ブラウザのタブ内で動作するのではなく、OSが管理する独立したプロセス・ウィンドウとして起動する。サーバ処理系を持たない点は[[TECSCDE外部仕様]]と同じだが、理由が異なる——ブラウザのサンドボックス制約によるものではなく、単に本アプリケーションの機能がサーバを必要としないためである。

「言語非依存」とは、本仕様の範囲において TypeScript/Electron・Rust/Tauri のいずれの実装でも同一の挙動になることを指す。第1章1.3節の要件と対応する。

CDL・C宣言の文法は、tecsgen自身の構文定義（`tecslib/core/bnf.y.rb`・`tecslib/core/C_parser.y.rb`）をtree-sitterの文法DSLへ移植したものを用いる。解析系は構文解析のみを担い、tecsgenの意味解析は代替しない。また、`TYPE_NAME`と`IDENTIFIER`を区別しない簡略化により、tecsgenが拒否する一部の記述を受理し得るという[[TECSCDE外部仕様]]2.2節の制約も共通である。Electron・Tauriの各実装で用いるtree-sitterバインディングや成果物の配布方法は内部仕様で定める。

### 2.3 デスクトップ実行形態が可能にすること（[[TECSCDE外部仕様]]からの解放）

[[TECSCDE外部仕様]]2.3節はブラウザ単体構成に由来する3つの制約（ファイル入出力の限定、tecsgen直接起動不可、SVG描画）を導いていた。デスクトップ実行形態はこのうち前の2つを解消する。

- **ファイル入出力はOSのファイルシステムへ直接アクセスできる。** Electron（Node.jsの`fs`モジュール）・Tauri（Rustの`fs`）のいずれも、利用者が選択したファイルに限らず、任意のパスへの読み書きが可能である。ユーザ操作を起点とする「開く」「保存」という操作の意味は変わらないが、一度開いたファイルへの以降の書き戻しはユーザ操作を都度介さずに行える（第5章）。
- **tecsgenを直接起動できる。** Electron（`child_process`）・Tauri（`std::process::Command`）のいずれも、外部プロセスの起動と標準出力/標準エラー出力の取得が可能である。CDL生成後、利用者の操作でtecsgenをサブプロセスとして実行し、結果を本アプリケーション内に取り込める（第8章）。
- **図の描画はSVGを用いる（変更なし）。** [[TECSCDE外部仕様]]2.3節と同じ理由——要素の選択・ヒットテスト・部分更新をDOMの機構で扱え、画像エクスポートでSVGをそのまま出力できる——がそのまま成り立つ。SVG描画自体はブラウザ・デスクトップいずれでも同じ標準APIで実現できるため、変更する理由がない。

### 2.4 本書が新たに導入する制約

デスクトップ実行形態は制約を解くだけでなく、[[TECSCDE外部仕様]]にはなかった制約も導入する。

- **利用者の環境に依存する外部プロセス（tecsgen本体・Cプリプロセッサ）の有無・バージョンは、本アプリケーションが保証しない。** サブプロセスとして起動を試み、失敗した場合（実行ファイルが見つからない等）はその旨をエラーとして提示する（第8章）。
- **tecsgen本体の起動方法は、環境変数`TECSGEN_COMMAND`で指定できる**（2026-10-22追加。以前は規定がなく、実装だけにあった。設定の全体像は2.5節）。
  - **既定**: `TECSGEN_COMMAND`が無いときは、`PATH`上の`tecsgen`を起動する。
  - **書式**: 設定されていれば、その値を起動コマンドとして使う。空白で区切り、先頭を実行ファイル、残りを先頭の引数とする（例: `ruby "C:\Program Files\tecsgen\tecsgen.rb"`）。空白を含む語は`'`か`"`で囲む。バックスラッシュはパスの区切りとしてそのまま扱う。シェルを介さないので、リダイレクト・パイプ・環境変数の展開は使えない。
  - **適用範囲**: tecsgen本体を起動するすべての操作——「実行(Generate)」（第8章8.4.2）、CDLを開くときのPlugin生成型の取り込み、tecsgenの版の確認（8.4.2）——に適用する。`import_C`のCプリプロセッサの起動には適用しない（そちらは`__tool_info__`のcpp指定、無ければ`gcc -E -DTECSGEN`）。
  - **反映**: アプリケーションの起動時の値を使う。変更したときは、アプリケーションを再起動する。
  - **失敗**: 値が空、または解釈できない（引用符が閉じていない等）ときは、起動に失敗した旨のエラーとして提示する。実行ファイルが見つからないときは、見つからない旨のエラーとし、`PATH`と`TECSGEN_COMMAND`の指定先の両方を案内する（第8章8.4.2）。
  - **Windowsでの注意**: `PATH`上の`tecsgen`がスクリプト（`.bat`等）だと、シェルを介さない起動ができない可能性がある（unverified）。その場合は、`ruby <tecsgen.rbのパス>`のように、実行ファイルと引数を指定する。
- **OS依存の挙動には規定を置かない。** 特にTauriはOSごとに異なるWebView実装を用いるため、WebView固有の描画差異・ショートカットキーの衝突等が生じ得る。本書はそうした差異の解消を規定の対象とせず、実装時の検証課題として扱う（unverified）。
- **配布・インストール・自動更新の方式は本書の範囲外とする。** Electron・Tauriそれぞれに固有の配布パイプラインがあり、外部仕様（利用者から見た挙動）の対象ではないため、本仕様では扱わない。

### 2.5 設定（2026-11-01 追加）

設定の全体像をここにまとめる。個々の設定の詳細は、それぞれの節にとどめ、ここからは参照するだけにする。経緯と論点は[[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 設定節追加案|追加案]]。

**方針**: **V0.2.0 から、設定ダイアログを設ける**（2026-11-05 決定。3.8.1。「情報」ボタンで開くバージョン情報のダイアログに同居させる）。V0.1.0 は設定画面を設けなかった。設定ダイアログで変えられるのは、tecsgen へのパスとCDLファイル一覧の対象ディレクトリ（3.8.2）で（環境変数 `TECSPATH` は表示だけ）、それ以外は、設定ファイル（`settings.json`）と環境変数で行う。`allowEditSystemDefined` は設定ダイアログに載せない（2026-10-22 決定、5.3 節）。tecsgen のパス指定を設定画面で行うかは、内部仕様 11章の未決事項 #3 への回答として、設定ダイアログで行うことに決めた。設定には、利用者が設定するもの（2.5.3）と、アプリケーションが記憶するもの（2.5.4）がある。

#### 2.5.2 設定ファイル

| 項目 | 内容 |
|---|---|
| 名前 | `settings.json` |
| 置き場所 | Windows: `%LOCALAPPDATA%\tecscde-dt-el\settings.json`。それ以外: Electron の `userData` フォルダ（macOS・Linux での具体的なパスは未確認、TBC） |
| 形式 | JSON。文字コードは UTF-8 |
| 読み込み | 起動時に一度。**変更したら、アプリケーションを再起動する**。ただし、設定ダイアログ（3.8.1）で保存した項目は、保存した直後から反映する（V0.2.0） |
| 無い・壊れているとき | エラーにせず、「設定なし」として扱う（すべて既定値） |
| 置き場所の理由（Windows） | PC 固有の設定がローミングされないよう、`%APPDATA%` ではなく Local AppData に置く |
| 不明な項目 | 規定しない（読み込んだ内容は保持され、無視される。エラーにはしない） |

**手で編集するとき**: アプリケーションが記憶する項目（2.5.4）を保存するときは、ファイルの現在の内容を読み込んで、変わった項目だけを書き換える。そのため、手で足した項目は、通常は残る。ただし、**壊れた（JSON として読めない）ファイルは、次にアプリケーションが保存するときに、新しい内容で置き換わる**。手で直す前に、写しを取っておく。

#### 2.5.3 利用者が設定するもの

| 設定 | 場所 | 型・既定 | 意味 | 詳細 |
|---|---|---|---|---|
| `allowEditSystemDefined` | `settings.json` | 真偽値、既定 `false`。**`true`（真偽値）のときだけ有効**で、文字列 `"true"` などは無効 | システム定義 CDL（`-S` のディレクトリ配下）のセルも、通常の CDL と同じく編集可能にする。既定では閲覧のみ | [[work/active/TECSCDE-DT外部仕様/TECSCDE-DT外部仕様 - 05A 開く（読み込み）|5.3 節（5A 章）]] |
| `TECSGEN_COMMAND` | 環境変数 | 文字列、既定は `PATH` 上の `tecsgen` | tecsgen 本体の起動コマンド | 2.4 節、第8章8.4.2 |
| `tecsgenPath` | `settings.json`、設定ダイアログ（3.8.1） | 文字列、既定は未設定（V0.2.0） | tecsgen へのパス。未設定のときは、環境変数 `TECSPATH` の値が実在すればそれを、なければ `PATH` を先頭から探して見つかったパスを使い、設定として保存する。環境変数 `TECSGEN_COMMAND` が設定されているときは、そちらが優先される | 3.8.1、8.4.3 |
| `cdlFilesRoot` | 同上 | 文字列、既定は未設定（V0.2.0） | CDLファイル一覧の作成（5.3.y）の対象ディレクトリ | 3.8.2 |

環境変数の変更は、アプリケーションの再起動後に反映する。設定ダイアログで保存した値は、保存した直後から反映する。`PATH` は OS の変数で、tecsgen の既定の探索先として使う。

#### 2.5.4 アプリケーションが記憶するもの（利用者は編集しない）

| 項目 | 内容 | 規定している節 |
|---|---|---|
| `fileBrowserRoot` | ファイルブラウザのルートフォルダ。次回起動時に復元する | 3.5.1 |
| `lastSession` | 前回終了時に開いていたファイルの集合（編集対象、参照、追加の取り込み先、オプションファイル）。次回起動時に復元する | 5.3 節（セッションの復元） |

診断ログ（9.5 節）は、設定ファイルと同じフォルダ配下の `logs/` に置く。

#### 2.5.5 アプリケーションの版（2026-11-01 追加）

- アプリケーションの版は、**`package.json` の `version` を唯一の情報源**とする。保存する `.cde` の `__tool_info__` の `tecscde_version`、バージョン情報ダイアログ（3.8）、診断ログの先頭行（9.5）、インストーラ、自動更新、リリースタグは、すべてこの版から決まる。
- **形式の版**（`cde_format_version`）は、アプリケーションの版とは別に管理する。ファイルの互換性の判断に使うためで、アプリケーションの版が上がっても、形式が変わらなければ変えない（元の Ruby 版も、ツール版と形式版を別立てにしている）。
- 版を確認する手段は、バージョン情報ダイアログ（3.8）。
