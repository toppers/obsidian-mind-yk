# TECSCDE-DT外部仕様 - 08 CDL 連携 — 8.5 tecsgen 相当の内部処理

[[TECSCDE-DT外部仕様 - 08 CDL 連携|第8章]]の8.5節を分離した（2026-11-17、25KB閾値）。原文のまま。第8章の他の節は、親ノートにある。

### 8.5 tecsgen 相当の内部処理（V0.2.0 で追加、2026-11-05）

tecsgen を**呼ばずに、アプリケーションの内部で**処理する機能を設ける。8.4.2 の外部プロセスの実行とは別の経路。

1. **仮想ファイル**: ファイルシステムの代わりに、**メモリ上の仮想的なファイル**へ入出力する。入力の CDL も、出力の生成物も、ディスクには書かない。
2. **プラグイン相当**: tecsgen のプラグイン（8.1 の Plugin 生成型の取り込みなど）に相当する処理を、アプリケーション内で行う。
3. **外部実行との関係**（2026-11-08 決定。**併用であり、置き換えではない**）。
   1. 内部処理が担うのは、**Plugin 生成型の取り込み**（8.1）だけである。「実行(Generate)」と、tecsgen の版の確認は、従来どおり外部の tecsgen を使う。
   2. 利用者は、設定ダイアログ（3.8.1）で「Plugin 生成型の取り込み」の方式を選ぶ。**外部 tecsgen（既定）**または**内部処理**とする。保存した後の、次の読み込みから使う。
   3. 実行中に、外部から内部へ、または内部から外部へ**自動で切り替えない**。どちらの方式を使ったかは、診断ログに記録する。
4. **内部処理を選んだときの動作**:
   1. 対象プラグイン（次項）の `generate(...)` だけを内部で処理する。
   2. 対象外のプラグインの `generate(...)` は取り込まず、警告 `W-PLUGIN-UNSUPPORTED`（9.2）で、プラグイン名とともに知らせる。開く処理は続ける。
   3. 失敗の扱い、部分的な生成物を取り込まないこと、同名時の優先、生成セルの読み取り専用、保存・セッションの参照先に含めないこと、上限（10,000ファイル、合計100MiB）は、8.1 と同じとする。失敗は `W-PLUGIN-TYPE-LOAD` で知らせる。
5. **対象プラグイン**（2026-11-08 決定）:
   1. 対象は、「生成物が CDL で、`generate(...)` の引数だけで決まり、外部の状態に依存しないプラグイン」から選ぶ。
   2. 初版の対象は `MrubyBridgePlugin` 系である（実際のサンプル CDL で多用されている）。**外部の tecsgen の生成物と同じ CDL が得られることを、基準データとの照合で確認できたものだけ**を、本章の付表（対象プラグインの一覧）に載せる。V0.2.1（2026-11-13）で `MrubyBridgePlugin` と `MrubyBridgeCellPlugin` を実装し、tecsgen 1.9.1 の出力（55ファイル）と**完全に一致する**ことを確認して、付表に載せた（2026-11-17 に、本文を実装に合わせて更新。それまでの本文は「照合できるまで付表は空」だった）。付表に無いプラグインは、内部処理を選んでも対象外として扱う。
   3. `MrubyBridgePlugin` 系を付表に載せる条件（2026-11-08 の外部 tecsgen 1.9.1 の出力の調査による。以下の条件は V0.2.1 で満たした）。
      1. **署名の C 型の解決**: 署名の関数の引数にある構造体（`T_RTSK` など）から、構造体用のセルタイプ名を導く必要がある。C ヘッダ（`import_C`）の typedef・struct を解決できること。
      2. **処理順の再現**: 初期化セルの並びは、`generate(...)` の処理順で決まる。順序まで一致すること。
      3. **プラグイン連鎖の再現**: 生成物の中の `generate(...)` が、別のプラグインを呼ぶ（多段）。これを再現すること。
      4. **tecsgen の版**: 照合した版（基準データは 1.9.1）を付表に記す。プラグインのソースは版で異なる。
      5. 基準データは `tests/fixtures/tecsgen-golden/sample1-mruby-bridge/`（55ファイル）。改行は、両者を LF に正規化して比べる。
   4. `HRP2*Plugin` 系は、この調査で CDL の生成物が**すべて0バイト**だった（カーネル設定の生成が主）。CDL を生成しないため、内部処理の対象にならず、初版の対象外とする。
   5. Ruby プラグインの互換実行と、tecsgen 全体との互換は保証しない。
   6. **付表（2026-11-17）**:

      | プラグイン | 照合した tecsgen の版 | 基準データ |
      |---|---|---|
      | `MrubyBridgePlugin`（署名・セルタイプ・セルを振り分ける） | 1.9.1 | `tests/fixtures/tecsgen-golden/sample1-mruby-bridge/`（55ファイル、完全一致） |
      | `MrubyBridgeCellPlugin`（セルのみ） | 1.9.1 | 同上 |

      付表に載るのは、基準データとの一致を確認できたものだけで、差を見つけたら付表から外す（次の6）。「情報」ダイアログの Plugin 型取り込みの欄に、この付表と版を表示する。
6. **同一性**: 内部処理の生成物が外部の生成物と異なる場合は、外部の生成物を正とする。差を見つけたプラグインは、付表から外す。
7. **仮想内容の表示**: 内部処理で生成した型は、セルタイプの詳細ダイアログ（第4章4.2.x）の「定義ファイル」欄に、`plugin:<プラグイン名>/<ファイル名>`（仮想）と表示する。「定義ファイルの表示」ボタンを使え、定義ファイルウィンドウに内容を**読み取り専用**で表示する。実在するパスではないため、パスのコピーと保存は行えない。
8. 仮想ファイルは、ディスクに書かない。
