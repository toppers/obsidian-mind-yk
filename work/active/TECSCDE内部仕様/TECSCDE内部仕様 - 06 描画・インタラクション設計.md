## 6. 描画・インタラクション設計

### 6.1 SVGツリー構造

外部仕様3.2.2の規定どおり、キャンバスのルートを単一の`<svg>`要素とし、図要素をその子要素として保持する。

```
<svg>
  <g id="regions-underlay">   … 色分け表示（7.5.2）
  <g id="cells">              … セルごとに<g class="cell">（矩形・文字・ポート）
  <g id="joins">              … 結合の折れ線とシグニチャラベル
  <g id="join-preview">       … 結合作成中の仮結線（6.4.2、新規）
  <g id="selection-overlay">  … 選択中の強調表示（最前面、4.1.1）
  <g id="grid">               … グリッド線（7.2.2、新規、既定非表示）
</svg>
```

### 6.2 更新戦略

`CellId`/`JoinId`とSVG要素の対応を`Map<Id, SVGElement>`で保持し、モデル変更イベント（コマンド適用後にstoreが発行）を購読して**該当要素の属性のみ**更新する。3.2.2が禁じる「図全体の再描画」は、この対応表を持つことで構造的に発生しない（差分がなければどの要素も触らない）。

### 6.3 ヒットテスト

外部仕様6.2.1の優先順位（ポート＞セル＞結合バー）を踏襲しつつ、6.2.2が改善を要求する2点を反映する。

- 結合バーの探索を**クリック位置から一定ピクセル半径内**に限定する（現行版のモデル全体探索を改める）。半径外は空白クリックとして扱う。
- ポート／セルとの排他制約（同時ハイライト不可）は現行版の`reset_if_necessary`相当のロジックとして`hit-test.ts`に実装する。

### 6.4 ドラッグ状態機械

外部ライブラリ（XState等）はランタイム依存として使わず、`gesture.ts`に自前の小さな有限状態機械を実装する。状態は外部仕様3.7の4状態（通常／呼び口の上／結合操作中／結合先として有効）に対応させ、遷移の終端で5章のコマンドを発行する。E（描画）・G（UIシェル）はこの状態機械を経由してのみモデルを変更でき、CやDへの直接書き込み経路を持たない（2.2の保証をコードでも表現する）。

### 6.5 選択状態・ラバーバンド選択

選択状態はモデルの一部ではなく、`render/`層が保持する一時的なUI状態とする（4.9.2のリージョンとは独立、6.8.2の「一時的な集合」という位置付けと整合）。矩形ドラッグによるラバーバンド選択（6.8.2で新規追加）は、矩形に完全に含まれるセルをヒットテストで求め、この一時集合に対して移動・削除・コピーのコマンドをそのまま適用できるようにする。

### 6.6 結合プレビュー線

結合モード中（6.4.2）、ドラッグ中の仮結線を`#join-preview`グループに破線で描画する。現行版のカーソル形状のみのフィードバックを補うための新規要件であり、モデルには一切書き込まない。
