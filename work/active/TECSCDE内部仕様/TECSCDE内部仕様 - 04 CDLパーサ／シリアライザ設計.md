## 4. CDLパーサ／シリアライザ設計

> [!info] 本章は2026-09-13に全面改訂した
> 改訂前の本章は**手書きの再帰下降パーサ**（`cdl/lexer.ts`・`cdl/parser.ts`）を規定していた。根拠は[[TECSCDE外部仕様]]2.2節の「依存ライブラリなし」だったが、同節が同日にCDL解析系のみを例外とする形へ改訂され、tecsgen自身の構文定義から移植したtree-sitter文法の採用が決まったため、本章もそれに追随する。決定の経緯: [[work/active/CDLParser(tree-sitter利用)/TECSCDE外部仕様 tree-sitter反映案|TECSCDE外部仕様 tree-sitter反映案]]、[[Key Decisions]]。既存実装との差分は4.7節。

### 4.1 対象文法範囲

外部仕様5.3.2の改訂に合わせ、**「パーサが解析する範囲」と「モデルへ反映する範囲」を分離する**。改訂前はこの2つを区別せず「サブセットのみ解析する」としていたが、採用する文法はtecsgenの構文定義（`bnf.y.rb`）の移植であり、解析範囲を絞る手段も理由も無い。

| 構文 | 解析 | モデルへの反映 |
|---|---|---|
| `cell`定義ブロック | する | **する**（完全に変換する） |
| `__tool_info__("tecsgen")` / `__tool_info__("tecscde")` | する（文法のJSONリテラル規則として） | **する**（スキーマ検証を伴う。4.2・4.6参照） |
| celltype / signature 定義 | する | **する**（ポート構成の解決に必要な範囲のみ、読み取り専用。外部仕様8.1.2） |
| `import` / `import_C` | する（ノードとして識別できる） | しない（参照先を自動追跡しない。理由はブラウザのファイルアクセス制約であって解析能力ではない。外部仕様8.1.2・8.2.2） |
| composite / region / generate / `typedef` 等 | する | しない（**CST上の区間として保持し、保存時にそのまま書き戻す**。4.6参照） |
| 複合セルタイプ本体 | する | しない（外部仕様4.7.2のとおり警告として提示する） |

「反映しない」構文を**読み飛ばす**のではなく**構文木として保持する**点が改訂前との実質的な差である。これにより外部仕様8.2.2が要求する「入力時の生テキストのまま書き戻す」を、テキストの当てずっぽうな切り出しではなくCSTノードのバイト区間として正確に実現できる（4.6）。

### 4.2 パーサ構成

**tecsgen自身の構文定義から移植したtree-sitter文法2種を用いる。**

| 文法 | 移植元 | 用途 |
|---|---|---|
| `tree-sitter-cdl` | `tecslib/core/bnf.y.rb` | `.cdl`／`.cde`本体の構文木 |
| `tree-sitter-tecs-cdecl` | `tecslib/core/C_parser.y.rb` | `import_C`が参照するCヘッダからの`typedef`／`struct`抽出（4.5） |

**バインディングは`web-tree-sitter`（WASM）を用いる。** ネイティブバインディング（`node-tree-sitter`）はNode.jsのネイティブアドオンを要求するため、ブラウザ単体構成（外部仕様2.2）では選択肢にならない。本書がブラウザ版を対象とする以上この選択に裁量はない——デスクトップ版では選択の余地が生じる（[[work/active/TECSCDE-DT-EL内部仕様/TECSCDE-DT-EL内部仕様|TECSCDE-DT-EL内部仕様]]2.2節）。

ファイル構成は次のとおり。**改訂前の`lexer.ts`・`parser.ts`は廃止する**——字句解析・構文解析の両方が文法側の責務になるためである。

| ファイル | 責務 |
|---|---|
| `cdl/grammar.ts` | WASM文法のロードと`Parser`インスタンスの保持（4.3の非同期初期化を担う唯一の場所） |
| `cdl/document-builder.ts` | **CSTを走査してモデル（C）を構築する**。改訂前のASTからの変換に相当し、走査対象がtree-sitterのCSTに変わる |
| `cdl/tool-info.ts` | `__tool_info__`のJSON部分のスキーマ検証（責務は改訂前と同一、入力がCSTノードになる） |
| `cdl/serializer.ts` | モデル＋保持したCST区間から`.cde`を生成（4.6） |
| `cdl/messages.ts` | 診断オブジェクトの生成（4.4） |
| `cdl/cdecl.ts` | `tree-sitter-tecs-cdecl`によるCヘッダの型抽出（4.5） |

2章2.3節が定めた「B内部の2責務分離」（CDL文法解析 ／ `__tool_info__`のスキーマ検証）は**変更しない**。むしろ分離の根拠は強まる——前者は文法パッケージの差し替えで変化し、後者はTECSCDE独自形式の版数で変化するため、変化する理由が改訂前よりさらに明確に異なる。

### 4.3 非同期初期化（新設）

**WASM文法のロードは非同期であり、これはモジュール境界を越える唯一の新しい制約である。** 改訂前の手書きパーサは同期的に`parse(text)`を呼べたが、`web-tree-sitter`は`Parser.init()`と文法バイナリのロードを待つ必要がある。

- モジュールBは`initCdlParser(): Promise<void>`を公開する。解決後は`parse(text)`を**同期関数のまま**保てる（文法のロードさえ済めば解析自体は同期）。この形にすることで、非同期性の影響をアプリ起動シーケンスの1点に閉じ込め、A・C・Hの契約を非同期化せずに済む。
- `app/main.ts`は、Aのファイル入力経路（`<input type=file>`・ドラッグ&ドロップ）を有効化する**前に**`initCdlParser()`の解決を待つ。待たずに有効化すると、起動直後にファイルをドロップした利用者に対してのみ失敗する再現困難な不具合になる。
- ロード失敗（WASMの取得失敗・インスタンス化失敗）は**起動時の致命的エラー**として扱う。CDLを解析できないアプリケーションは図を1つも開けないため、部分的に動作させる意味がない。9章の診断機構は解析結果を集約する層であり、解析系そのものの不在を表現できない点に注意する。

> [!success] 外部仕様への波及は不要と判断した（2026-09-13、実測で決着）
> この初期化待ちが「起動直後のごく短い時間は読み込み操作を受け付けない」という利用者から観測可能な挙動になるかを、[[TECSCDE-JS-TS実装]]の実機ブラウザで測定した。**WASMのロードはnavigation startから約120msで完了**（DOMContentLoadedが80ms、文法wasmの取得自体は4〜7ms）。利用者が起動直後にファイルをドロップしようとしても、その操作に到達する前に初期化が終わっている水準であり、**体感できる待ちにはならない**。したがって外部仕様3章（画面構成）に起動時状態の規定は置かない。

### 4.4 エラー回復と診断の対応付け

**構文エラーからの回復は文法側の機構に委ねる。** tree-sitterは解析失敗時に例外を投げず、`ERROR`／`MISSING`ノードを含む木を返す。外部仕様9.1.2が要求する「エラーがあってもインポート自体は中断せず、パースできた範囲は図に反映する」は、改訂前は手書きの回復処理として実装する必要があったが、改訂後は**文法側の既定の挙動をそのまま使うだけで満たせる**。

一方で、この置き換えは**メッセージ文言の欠落**を新たに生む。ここが改訂による唯一の後退であり、明示しておく。

- tree-sitterが提供するのは誤りの**位置と構造**（`ERROR`／`MISSING`ノードのバイト範囲・行・列、その親ノードの種別）だけで、**メッセージ文言を持たない**。
- 外部仕様9.1.2は「エラーコード・メッセージ文言はtecsgenのメッセージカタログを踏襲する」と規定しており、移植対象は構文定義のみでカタログは含まれない（同節に明記済み）。
- したがって`cdl/messages.ts`は、`ERROR`ノードの文脈（親ノードの種別・直前直後のトークン）からtecsgenのG-code相当（`G1015 Unexpected EOF`・`G1016 syntax error near '$1'`）へ**対応付ける責務を負う**。改訂前は自前のパーサが構文規則を知っていたため、どの規則の途中で失敗したかを直接メッセージにできた。改訂後はこの情報をCSTから復元する必要がある。
- 対応付けの網羅は目標にしない。**対応先が定まらない場合は`G1016`（`syntax error near '$1'`）へ倒し、`$1`にERROR区間の先頭トークンを入れる**。tecsgen自身も構文エラーの大半をこの1コードで報告しているため、この既定値は利用者から見て不自然にならない。

意味エラー（S-code相当）は改訂前と同様、モジュールB・Cが検出できる範囲——セル名重複・セルタイプ未解決・結合先不在——に限られる。採用する文法は意味解析を持たないため（外部仕様8.3.2）、この範囲は改訂によって広がりも狭まりもしない。

### 4.5 `import_C`のC型情報抽出（新設）

外部仕様8.1.2が「常に非対応」から限定対応へ改訂されたことに伴い、新たに必要となる責務。

- `cdl/cdecl.ts`が`tree-sitter-tecs-cdecl`を用いて、利用者が参照専用として読み込んだCヘッダから`typedef`／`struct`宣言を抽出する。Cプリプロセッサは起動しない（ブラウザから起動する経路が無い）。
- 抽出した型名はセルタイプ・シグニチャの解決に用いる。解決できなかった型は、モデルへ反映せず9.2.2の警告（「セルタイプが解決できない」）へ倒す。
- **この文法は汎用Cパーサではない。** 移植元`C_parser.y.rb`の字句解析器が`typedef`／`struct`以外をパーサへ渡さない実挙動をそのまま写したものであり、関数プロトタイプ・`extern`変数・`enum`／`union`単独宣言は解析対象外である。この非対称を実装側で「Cの解析ができる」と誤読しないこと。
- プリプロセッサ非実行に由来する差分（`#include`非展開・`#ifdef`非評価・`#define`未解決）は外部仕様8.1.2が制約として規定済みであり、本モジュールはそれを埋める試み（独自のプリプロセッサ実装等）を**しない**。

### 4.6 シリアライザ

`serializer.ts`は外部仕様5.1.1が確定した3ブロックの順序をそのまま踏襲する（改訂なし）。

```
① __tool_info__("tecsgen")   — toolInfoTecsgenをそのまま書き戻す（解釈しない）
② cell定義（editable === true のセルのみ、5.4.1踏襲）
③ __tool_info__("tecscde")   — 用紙・配置・結合経路。unknownFieldsを含めて書き戻す
```

改訂で強化されるのは**モデルに反映しない構文の書き戻し精度**である。4.1で保持したCST区間（composite・region・generate・`import`文等）は、テキストの再構成ではなく**元テキストの該当バイト範囲をそのまま複写する**。改訂前の「生テキストのまま保持する」という方針は同じだが、範囲の特定根拠が「解釈しないので触らない」という消極的なものから、構文木上の区間という積極的なものに変わる。

parse→serialize→parseの往復が意味的に一致することをfixtureテストで保証する方針（12章）は変更しない。**往復の検証基準は改訂前の「ASTの一致」から「モデルの一致＋未反映区間のバイト一致」に置き換える**——CSTは具象構文木であり空白・コメントの扱いがASTと異なるため、木そのものの一致を基準にすると意味のない差分を拾う。

### 4.7 既存実装との差分（移行メモ）

本章の改訂時点で、3つのリポジトリに手書きパーサの実装が存在していた。**うち1つ（JS-TS版）は同日中に移行済み、残る2つは未追随である。**

| リポジトリ | 該当ファイル | 状態 |
|---|---|---|
| [[TECSCDE-JS-TS実装]] | ~~`src/cdl/lexer.ts`・`parser.ts`~~ → `grammar.ts`・`cst.ts` | **移行済み（2026-09-13、コミット`353853a`）**。32テストpass、実機ブラウザ確認済み |
| [[TECSCDE-TS実装]] | `src/cdl/lexer.ts`・`parser.ts` | 同上（上記からの移植） |
| [[TECSCDE-DT-EL実装]] | `src/renderer/cdl/lexer.ts`・`parser.ts` | 同上。第11章の実装単位#1（round trip）として検証済み |

移行の影響範囲は**`lexer.ts`・`parser.ts`の2ファイルと`document-builder.ts`の入力側に限られる**という見込みは、JS-TS版の実移行で**概ね裏付けられた**（2026-09-13）——`document-builder.ts`の変更はimport先の差し替え1行、`serializer.ts`・`tool-info.ts`・`messages.ts`の契約は不変だった。ただし見込みに入っていなかった作業が2つ出た。

1. **fixtureとシリアライザ出力の書き換え。** 移行の完了条件を当初「移行前後で同じfixtureが通ること」としていたが、**旧fixtureがそもそも有効なCDLではなかった**ため文字通りには成立しなかった。テストのアサーションは維持しつつ、fixtureの内容を実際のCDLへ書き換える必要がある（下記）。
2. **非同期初期化のテスト環境対応。** ブラウザは`/wasm/...`のURLで解決できるが、テスト（Node）はファイル実体を注入する経路が要る。`initCdlParser()`に注入口を設け、vitestの`setupFiles`で一度だけ待つ構成にした。

> [!warning] 旧実装の出力は有効なCDLではなかった（2026-09-13、JS-TS版の移行で判明）
> 手書きパーサが受理していたのはCDLのサブセットではなく**別方言**だった——`entry_port`（実際は`entry`）、`attribute name;`（実際は`attr { int32_t name; };`）、`cell tFoo c1 { }`（実際は終端`;`が必要）、`import "x";`（実際は`import("x");`）。**保存した`.cde`はtecsgenに入力できず**、外部仕様2.2「tecsgenが受理するCDLを入出力対象とする」に違反していた。
>
> round-tripテストがこれを検出できなかったのは、パーサとシリアライザが同じ方言を共有していれば常に一致するためである（[[Patterns - 検証と調査#自前パーサと自前シリアライザのround-tripは、方言が外界の仕様から外れていても永久に緑になる（2026-09-13）|Patterns]]）。**移行時は往復の一致だけでなく、出力を文法に通して`ERROR`/`MISSING`がゼロであることを併せて検証すること**——残る2リポジトリの移行でも同じ確認を行う。
