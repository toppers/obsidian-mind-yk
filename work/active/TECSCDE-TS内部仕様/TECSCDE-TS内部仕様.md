# TECSCDE-TS 内部仕様（クラスベース）

> [!info] 文書状態
> **改訂（2026-09-13）**: [[TECSCDE外部仕様]]第8章（CDL連携）ほかの改訂——tree-sitter製CDLパーサの採用、`import_C`の限定対応、構文エラー検出の新設——に追随し、**第2章（モジュールB の代表クラス、2.4節「用いるCDL文法パッケージ」を新設）・第10章（ディレクトリ構成・Bのインタフェース・ランタイム依存と`.wasm`の扱い）・第11章（未決事項#3・#4、実装単位の検証基準）**を改訂した。本書は**`tools-ts/`版（TypeScriptで記述された`grammar.ts`）を文法の正典とする**——モデルからUIまでをTypeScriptの型で表現する本書の設計を、文法の記述にまで伸ばす判断である（2.4節）。両版の生成物が完全一致することは検証済みで、実行時の挙動に差は無い。あわせて、実装単位の完了条件を「往復の一致」だけでなく「出力を文法に通して`ERROR`/`MISSING`ゼロ」を含む形へ改めた（[[TECSCDE-JS-TS実装]]の移行で往復テストの構造的な盲点が判明したため）。
>
> **全11章執筆完了（2026-09-05）** — [[TECSCDE外部仕様]]（全11章、外部から見た挙動・画面・操作の一次情報源）を踏まえ、[[TECSCDE内部仕様]]（既存、`readonly`フィールドのみを持つplain interface + 独立した不変条件検証関数という設計）とは異なる、**クラスベース（OOP）のTypeScript内部仕様**として新規に起こした。モジュール分割・依存方向は外部仕様由来のため[[TECSCDE内部仕様]]第2章と同一——変わるのはC（モデル）以降の内部表現であり、特に不変条件の一部（呼び口=結合1本まで／受け口=複数可）を後付けの検証関数ではなく**クラス階層と型そのもの**で表現する点が本書の中心的な提案である。
>
> **章番号について**: [[TECSCDE内部仕様]]はモジュールB（CDLパーサ／シリアライザ）を独立した第4章として立てているが、本書ではその代表クラス（`CdlGrammar`・`CdlDocumentBuilder`・`CdlSerializer`等）を第2章2.2節の表に統合済みとし、独立した章を設けない（パース処理自体はクラス化してもロジックの実質的な差分が小さいため——2026-09-13に構文解析をtree-sitter文法へ委ねる改訂を行ったことで、この理由はさらに強まった。文法パッケージは言語非依存であり、クラスベースか関数ベースかで差が出ない）。そのため本書の第4章以降は[[TECSCDE内部仕様]]の第5章以降に1つ前倒しで対応する（本書第11章＝既存第12章、最終章）。
>
> **本書は設計提案であり、対応する実装はまだ存在しない**（現行の[[TECSCDE-JS-TS実装]]は関数ベースの[[TECSCDE内部仕様]]に沿ったもので、本書のクラス設計には未対応）。**本書自体の採否（現行実装を置き換えるか、部分採用に留めるか、参照のみに留めるか）も未決定**——詳細は第11章11.2節を参照(unverified／今後実装検証が必要)。
