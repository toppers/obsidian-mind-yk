## 1. 概要

### 1.1 目的

本書は、[[TECSCDE外部仕様]]（TECSCDE の外部から見た挙動・画面・操作を定める全11章、実装方式に依存しない）を実現するための内部設計のうち、**クラスベース（オブジェクト指向）の TypeScript 設計**を提案するものである。

TECSCDE の内部設計はすでに[[TECSCDE内部仕様]]が存在し、`readonly`フィールドのみを持つ plain interface としてモデルを表現し、不変条件はコンパイル時の型で表現しきれない分を`invariants.ts`の独立した検証関数群に委ねる設計を採っている。現行の実際の実装（[[TECSCDE-JS-TS実装]]）もこの設計に沿っており、`class`宣言はレンダリング層・アプリ層の一部（`SvgRenderer`・`GestureController`・`Store`など）に限られ、モデル層は関数とプレーンオブジェクトのみで構成されている。

本書はこれに対する**代替設計案**であり、モデル・コマンドを中心に、責務をクラスとして明示的にカプセル化する設計を提案する。外部仕様が定める挙動は変えない——変わるのはあくまで内部の型設計・責務分担の表現方法である。

### 1.2 既存内部仕様との違い（要点）

| 観点 | [[TECSCDE内部仕様]]（既存） | 本書（クラスベース） |
|---|---|---|
| モデルの型 | `readonly`フィールドを持つ plain interface（`Cell`・`TecscdeDocument`等） | クラス（`Cell`・`TecscdeDocument`等）。フィールドは引き続き`readonly`、更新は新インスタンスを返すメソッド経由 |
| 不変条件の強制 | 型で表現しきれない分は`invariants.ts`の独立関数が事後検証 | 一部の不変条件（例: 呼び口=結合1本まで）はクラス階層・型自体で表現し「そもそも不正な値を作れない」ことをコンパイル時に保証。残りは`static create()`ファクトリメソッド内で生成時に強制 |
| コマンド | `interface Command { apply, invert }` → 実装時にreplayベースの`History`へ簡素化（[[work/active/tecs/TECSCDE Undo-Redo設計決定|Decision Record]]） | `abstract class Command`。`invert()`は持たない——既存の決定（replayベース`History`）をそのまま踏襲し、ここを再検討の対象にはしない |
| モジュール分割・依存方向 | 9モジュール（A〜I）、外部仕様由来の境界 | **変更なし**。外部仕様が課す境界は実装方式に依存しないため、[[TECSCDE内部仕様]]第2章と同一の分割・依存方向を採用する |

本書が変えるのは「C（モデル）モジュール以降の内部表現」であり、モジュールの分割そのものや、5章で既に確定している Undo/Redo のアーキテクチャ判断（replayベース）を再度議論するものではない。

### 1.3 不変性（immutability）との関係

本ボールト（`CLAUDE.md`）のコーディング方針は「既存オブジェクトを変更せず、常に新しいオブジェクトを作る」ことを求めている。本書で言う「クラスベース」は、この方針からの逸脱ではない。クラスのフィールドは引き続きすべて`readonly`とし、状態を変更するメソッド（例: `Cell.moveTo(x, y)`）は`this`を書き換えず、新しいインスタンスを返す。クラスを導入する目的は可変状態の許容ではなく、

1. 生成時・更新時の不変条件チェックをコンストラクタ／ファクトリメソッドに閉じ込めてカプセル化すること
2. 型階層（例: `CPort`と`EPort`を`Port`の別サブクラスにする）によって、一部の不変条件をそもそも「間違った形のデータを作れない」という形で保証すること

の2点にある。
