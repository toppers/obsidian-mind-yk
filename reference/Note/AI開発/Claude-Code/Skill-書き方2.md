パスの一部が丸ごと省かれる（差し込み位置ごと消える）場合も、考え方は同じで「argsが空/未指定のときの分岐」をスキルの指示文の中に明示的に書きます。値を置き換えるだけでなく、パスの組み立て方自体を条件分岐させる形になります。

書き方の例

「起動パラメータの抽出」節:

| パラメータ | 例 | 説明 |
|-----------|-----|------|
| `top_dir` | `from_source` | 省略可。ドキュメントツリーのトップディレクトリ名 |

対象ディレクトリを決定する手順を明示的に分岐として書く:

### Step 0: 対象ディレクトリの決定

- `top_dir` が指定されている場合: `docs/<top_dir>/spec/external/` を対象ディレクトリとする
- `top_dir` が指定されていない場合: `docs/spec/external/` を対象ディレクトリとする
  （`<top_dir>/` の階層を挟まない）

以降の手順では「対象ディレクトリ」という言葉で参照するようにしておけば、Glob・Read等の実際のパス指定箇所をtop_dirの有無で書き分けずに済みます。

### Step 1: 全件読込

対象ディレクトリ（Step 0 参照）配下の `*.md` を Glob で列挙し、全件並列で読む。

ポイントは、docs/<top_dir>/spec/external/ のように中間ディレクトリを丸ごと省略するケースでは、単純な文字列置換のデフォルト値（例:「省略時はtop_dirを"foo"とする」）ではなく、パス構築自体を条件分岐にする必要があるという点です。
