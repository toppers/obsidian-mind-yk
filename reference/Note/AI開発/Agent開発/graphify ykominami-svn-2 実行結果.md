傾向として見えるもの:
- TECS系カーネル（asp/fmp/hrmp/hrp系）はいずれも lock_cpu() / unlock_cpu() / check_point() がGod Nodeで、排他制御まわりが中枢
- mruby系3リポジトリはいずれも mrb_get_args() が最多接続 — mrubyのC API呼び出し規約が支配的
- ev3rt+tecs/trunk は他より一桁大きく（16,764ノード）、mrb_state（mruby組み込み）が突出したハブ
- tecscde / tecsgen は Celltype/Cell/Join などTECS（コンポーネント記述系）特有の概念がGod Node

各リポジトリの graphify-out/GRAPH_REPORT.md に Surprising Connections・Suggested Questions・全コミュニティ一覧が入っています。graph.html をブラウザで開けば対話的に見られます（ev3rt+tecs/trunk と tecsgen/trunk は5000ノード超のためコミュニティ集約ビューです）。

なお、コミュニティ名（例: "Kernel - Time Event"）は、そのコミュニティに属するノードの source_file から自動的につけた見出しです（各コミュニティのファイル/ディレクトリ名ベース）。1,295〜692個ものコミュニティを個別に精読して命名するのは非現実的だったため、この機械的な方法にしています。手動での意味づけが必要な場合は、対象を絞って /graphify query で深掘りできます。

serenaとの比較で見たい観点（言語サーバ単位のシンボル数 vs graphifyのノード/エッジ/コミュニティ構造、特定リポジトリの深掘り等）があれば教えてください。
